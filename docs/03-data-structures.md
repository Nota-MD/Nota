## 1. 真相在哪

这两条是全仓最要紧的口径，写错任何一条都会得到"编辑器里看到的和存盘的不是一份东西"
这类最难查的 bug。`src/editor/create.ts` 的文件头与 `src/ui/EditorPane.tsx` 的去抖
那段都引用回本节。

### 1.1 前端是文本的唯一真相，后端是 300ms 去抖的镜像

```text
ProseMirror（WebView 里）＝ 真相
        │  改动后去抖 300ms
        ▼
Document::text（Rust 里）＝ 镜像，存盘写的是它
```

**为什么不像 Folio 那样把真相放后端**：Folio 的编辑区是一个 WebKit 视图 + C 宿主，
两边都要操作同一棵树，所以它挑宿主做真相、JS 只做渲染。Nota 反过来——撤销栈、
选区、IME 组合态**全在 ProseMirror 里**，把真相搬回 Rust 等于把这些状态复制一份
并保证同步，得不偿失。

**代价**：镜像可能短暂滞后（最多一个去抖周期）。**对策有两条**：

| # | 对策 | 落在哪 |
|---|---|---|
| ① | 前端改动后**去抖 300ms** 推一次，不是每击键一次 | `src/ui/EditorPane.tsx` 的 `SYNC_DEBOUNCE_MS` |
| ② | 任何"要读文档"的动作（存盘、插件读文档）**先强制同步一次** | `ui/useDocuments.ts` 的 `saveDoc()` 在 `api.doc.save` 之前调 `api.doc.sync`（**自动保存调的就是它**，所以两条路的字节一样） |

⚠️ **不要在前端直接改后端镜像之外的东西**：写文件、写设置都要走对应的命令，
否则镜像与实际落盘会分叉。

### 1.2 任何"后端改文本"的路径都必须发事件通知前端

编辑器不会自己知道后端把文本换了。所以**每一条后端改文本的路径，写完都要发
`nota:document-changed`**，前端收到才整篇替换编辑器内容。

⚠️ **反过来的一条不算**（2026-10-04，第 14 项）：插件的 `nota.document.insert_at_cursor(text)`
**不发这条事件**——它一个字节的镜像都没改，发的是另一条**编辑意图**
`nota:document-edit`（前端收到是落一笔真事务，不是整篇 `setMarkdown`）。
两条通道的分工见 `docs/05` §5.2b。**别把两条合并**：一条是"状态已经变了"、
一条是"请你替我改成这样"，后者的**落地权在编辑器**。

`nota:document-changed` 的实现路径是插件的 `nota.document.set_text` / `append_text`
（`src-tauri/src/lua/api/document.rs` 的 `emit_changed()`）：

```text
Lua 插件改文本
  → DocumentStore::sync()（改镜像、revision += 1、dirty = true）
  → 先 drop 掉 documents 锁
  → app.emit("nota:document-changed", { id, text, origin: "plugin" })
  → App.tsx 订阅处：origin === "plugin" 且 id === activeId 时才 setMarkdown(text)
  → ProseMirror replaceAll → 又一次 markdownUpdated → 去抖后再 sync 回后端
```

最后那一步**不会来回抖**：回推的是同一份文本，`DocumentStore::sync` 见内容没变
会直接返回旧 `revision`，不再发第二条事件（见 §4 的 `sync` 语义）。

⚠️ **事件里的 `id` 与当前活动文档不同时，前端直接丢弃**，不排队、不缓存（见 §11 第 2 条）。

⚠️ 前端**不去比 `revision`**，收到就覆盖。理由（代码注释原文的意思）：能走到这条
分支就说明改动不是本编辑器发起的，自己发起的那次不会绕一圈回来。

## 2. 锁序

`AppState` 是四个共享句柄，锁顺序**只能从左往右**：

```text
plugins  →  documents  →  settings
```

`workspace` 不在这个链条上（它单独一把，见 §3）。

### 2.1 为什么是这个顺序

不是随手排的，是照着**会交叉的调用**定的：

| 路径 | 持有什么 → 再取什么 | 今天真的会交叉吗 |
|---|---|---|
| `nota_plugin_call` | 持 `plugins` → 插件命令的 Lua 闭包里取 `documents`（`nota.document.*`）、可能取 `workspace` | ✅ **会**（这是唯一的真实交叉） |
| 窗口销毁时的 `unload_all()` | 持 `plugins` → 插件的 `on_unload` 可能取 `documents` / `workspace` | ✅ 会（同一个方向） |
| 存盘（`nota_doc_save`：持 `documents`）→ 读设置 | `documents` → `settings` | ❌ **今天没有**（`nota_doc_save` 全程只锁 `documents` 一把） |

也就是说：**反方向今天一次都没有**——没有任何路径先持 `documents` 再去锁 `plugins`。
这条不变量今天成立得很轻松，它真正的价值是**拦住将来的改动**：`state.rs` 里
"存盘流程要读设置"那句说的是这条规则**要保护的方向**，不是今天某一行的实际行为。

只要所有路径都朝同一个方向走就**不会成环**。反向取锁的后果是死锁，而且是最难查的
那种——**平时不触发，只在两个命令碰巧同时跑时才卡住**。

⚠️ **两条附带的约定**（逐命令的持有情况见 `docs/01` §共享状态与锁顺序）：

1. **插件命令执行期间 `plugins` 锁一直被持有**（`nota_plugin_call` 全程握着它）。
   所以插件命令路径里**不能**再触发一次需要 `plugins` 锁的动作——那是自锁。
   今天 Lua 侧拿不到 `invoke`，走不到这条；加新 Lua API 时要先确认这个前提仍然成立。
2. **不要跨 `.await` 持锁**（`AGENTS.md` 的硬规矩）。宿主今天所有命令都是同步
   `fn`（没有 `async fn`），所以这条暂时无从违反；它是给将来的异步命令留的。

### 2.2 为什么要 `Arc<Mutex<_>>`

`documents` / `settings` / `workspace` 是 `Arc<Mutex<_>>`，`plugins` 只是
`Mutex<_>`。差别在**生命周期**：

- 插件的 Lua 闭包要**长期持有**这几个句柄（比任何一次命令调用都长），所以得是 `Arc`；
- `AppState` 与 `HostContext` 拿的是**同一个 `Arc`**，不是两份拷贝——
  `lib.rs` 的 `setup()` 里先建 `Arc`，`HostContext` 克隆一份，再 `manage(AppState)`；
- `plugins` 在最外层，没有比它活得更久的人拿它，所以裸 `Mutex<_>` 就够。

⚠️ "不要跨 `.await` 持锁"（§2.1 第 2 条）的样板在 `lua/api/document.rs` 的写操作里：
**改完镜像先 `drop(store)`，再 `emit`**——`emit` 要序列化并投递给 WebView，
把它放在临界区里就是把锁的持有时间拉长到"另一个进程收不收得到"这件事上。

⚠️ 违反锁序不会被编译器或测试拦住，**只能靠人和这一节**。拿多把锁之前先想清楚
自己站在哪一层。

## 3. `AppState` 的四个句柄（＋两个只读字段）

定义在 `src-tauri/src/state.rs`：

| 字段 | 类型 | 管什么 |
|---|---|---|
| `documents` | `Arc<Mutex<DocumentStore>>` | 打开的全部文档与镜像文本 |
| `settings` | `Arc<Mutex<Settings>>` | 用户设置（内存里那一份） |
| `workspace` | `Arc<Mutex<Option<PathBuf>>>` | 当前工作区根目录。`None` = 没开文件夹（单文件模式） |
| `plugins` | `Mutex<PluginHost>` | 插件宿主。锁在最外层 |
| `settings_problem` | `Option<String>` | 开机读设置时出的问题，读成功是 `None`。**只写一次、此后只读，所以不是 `Mutex`** |
| `app_lang` | `String` | **宿主此刻在说哪种语言**（`lang::有效语言` 算出来的那个，2026-09-25 加）。⚠️ 与上一格同一条规矩：**启动时算一次、此后只读**。它和插件加载时拿到的是**同一个值**（`lib.rs` 里算完，给 `HostContext` 一份、给这里一份），所以前端问"现在是什么语言"，得到的答案与插件文案表的口径必然一致。⚠️ **别在命令里拿设置重算一遍**：用户改了设置但还没重启的那段时间，那样算出来的是"下次启动才会生效的语言"，而插件用的还是旧的那份——前端会照着新语言去给插件挑提示语，说的却是插件没在做的事。「重启后生效」这件事的落点就是这一格（理由见 §5.1b 与 `settings/general.rs`） |

⚠️ 第五个字段是 2026-09-25 加的，起因是"设置自己变回默认了"那类现象：解析
`settings.toml` 失败时宿主本来只往 stderr 写一行就退回默认值继续启动——双击
图标进来的人看不到控制台，看到的是"我的设置没了"。现在那句话经
`nota_settings_problem` 命令发给前端，启动时弹一条**不自动消失**的提示
（`ui/useToasts.ts` 里 `ttlMs === 0` 那条分支），并且原文件会先备份成
`.bak`（`settings/mod.rs` 的 `留一份备份`）。它**没有"清掉"的命令**：
描述的是开机那一刻的事实，改好文件重启一次就不出现了。

⚠️ **2026-09-25 起那行 stderr 归了调试闸门**（`src-tauri/src/log.rs`）：
**默认一行都不打**，要 `NOTA_DEBUG=1` 才有。所以提示条不只是"给 GUI 用户看得见"，
它现在是**这条故障唯一的出口**——"终端里没报错"不再等于"设置读成功了"。
（同一天同一批的 `docs/06` §3.1 与 `log.rs` 文件头写了闸门的口径。）

⚠️ **这个结构体没有构造函数**：`lib.rs` 在 `setup()` 里手写 `AppState { … }` 字面量
（2026-09-24 删掉了那个没人调用的 `AppState::new`——它当时是全仓唯一一处把开机时的
`strict_markdown` 传给文档仓的地方，而它没人调用 ⇒ 设置开机时到不了文档仓）。
`documents` 与 `workspace` 在那儿建成空的（`DocumentStore::new(settings.strict_markdown)` / `None`），
设置与插件宿主则必须先建好才能传进来（插件加载要用 `HostContext`）。
⚠️ 那个 `strict_markdown` 参数**不是可有可无**：标签页标题是文档仓自己算的，
漏了就是"设置里写着严格、名字按宽松算"——不报错，`docs/02` 的 `state.rs` 一节记了这件事。

⚠️ `workspace` **不只是 UI 状态**：它同时是 `nota.fs` 与 `nota.git` 的**围栏**——
插件能碰的文件范围、能跑 git 的目录都由它决定。所以设置工作区走的是**规范化后的
绝对路径**（`nota_workspace_open` 里 `canonicalize()`），不是用户点进来的那个串。

## 4. `DocId` / `Document` / `DocumentStore`

定义在 `src-tauri/src/document/mod.rs`。

### 4.1 `DocId`

```rust
pub struct DocId(pub u64);
```

进程内唯一、单调递增、**不重用**。序列化后就是一个 JSON 数字，前端类型是
`export type DocId = number;`（`src/bridge/ipc.ts`）。

### 4.2 `Document` 的字段与不变量

| 字段 | 类型 | 语义 |
|---|---|---|
| `id` | `DocId` | 见上 |
| `path` | `Option<PathBuf>` | 还没存过盘的新文档是 `None`（`is_untitled()` 的判据） |
| `title` | `String` | 派生而来，见 §4.4 |
| `text` | `String` | **镜像**（§1.1）。存盘写的就是它 |
| `dirty` | `bool` | **相对「上次认领的干净文本」**有无改动——**不是「发生过 sync」**。置 `true` 的只有 `sync`（内容真的变了时）；置 `false` 的是 `save` / `reload` / **`settle`**。不落盘、不持久化。⚠️ 判据是 `doc.text != doc.clean_text` 算出来的，不是打标记打出来的 |
| `clean_text` | `String` | **跟 `text` 比出 `dirty` 的那一份**"干净文本"。`open` / `reload` / `save` / `settle` 四处把它刷成当时的 `text`。⚠️ `#[serde(skip)]`：它是内存里的比对基准，不该出现在发给前端的 `Document` 快照里。加这个字段是为了 BUG-12——只靠 `dirty: bool` 一张标记，装载流程里编辑器那次"规范化"一执行，这个标记就无法复位 |
| `untitled_index` | `u64` | 这份未命名文档的**序号**，建的时候从 `untitled_count` 定死，之后一律用它。⚠️ `#[serde(skip)]`。加它是为了 BUG-9：原来四个调用点都传字面量 `0`，于是一叠未命名文档全叫「未命名 0」 |
| `revision` | `u64` | 版本号。**每次 `sync`（仅当内容真的变了）/ `save` / `reload` 递增**；新建与打开时是 `0` |
| `选区` | `Option<选区快照>` | 编辑器报上来的**选区**（第 14 项，2026-10-04）。⚠️ 它是**界面状态、不是文档内容**：**不碰 `revision` / `dirty`、不落盘**，且 `#[serde(skip)]`。⚠️ 里面存的是**选中的那段字**（`{ text, empty }`），**不是偏移量**——偏移量在块边界上不可换算（`docs/05` §5.2b 那张量测表）。⚠️ `None` ＝"编辑器还没报过"（我不知道），与"我知道、光标是个点"（`empty: true`）**不是同一件事** |

`revision` 的用途是给**插件与前端**判断"手里这份是不是旧的"——
`nota.document.get_revision()` 读的就是它。

⚠️ 两条容易记错的语义：

- **`sync` 传进来的文本与镜像相同时，`revision` 不动、`dirty` 也不动**，
  直接返回当前值。这是 §1.2 那条回推链不来回抖的原因。
- **`save` 无论内容是否变过都 `revision += 1`**（存盘本身就是一次新的落点），
  同时 `dirty = false`、`title` 重新派生（另存为会改文件名 → 标题可能跟着变）。
- **`reload` 也 `revision += 1`**，并清 `dirty`。
- **`settle(id, text)` 与 `sync` 的差别只有一条：它同时清 `dirty`。**
  ⚠️ 它是**唯一一个"不当作编辑"的写入口**，用途只有装载流程的最后一步
  （见 §1.2 与 `commands/document.rs`）。⚠️ 实现里**有一处 `if` 不能改成早退**：
  编辑器那次规范化很可能**已经先走 `sync` 把文本推上来了**，走到 `settle` 时
  `text == doc.text` 已经成立、脏标记却仍然为真——早退就等于这一步没有生效。
  这条有回归用例钉着（`装载时的规范化不算用户改动`，第一版就是被它逮住的）。

### 4.3 `DocumentStore`

| 字段 | 类型 | 说明 |
|---|---|---|
| `docs` | `Vec<Document>` | 打开的全部文档 |
| `active` | `Option<DocId>` | 活动文档 |
| `next_id` | `u64` | `alloc_id()` 用它自增发号 |
| `untitled_count` | `u64` | 只用来生成"未命名 N" |
| `strict_markdown` | `bool` | **严格模式的镜像**（默认 `false` = 宽松）。建仓时由 `new(strict_markdown)` 定下，之后只有 `nota_settings_set` 改它。⚠️ 它影响的是**标题怎么猜**（`derive_title`），所以两处都得跟：建仓参数 + 改设置时的重算 |

方法表：

| 方法 | 行为 |
|---|---|
| `new(strict_markdown)` | 建空仓，**建仓时就把标题口径定下来**。⚠️ 参数忘不掉（编译错），这正是它存在的理由——2026-09-24 之前那句 `set_strict_markdown` 挂在一个没人调用的构造函数上，于是开机时设置到不了文档仓 |
| `set_strict_markdown(strict)` | 跟上开关，**并立刻重算所有已打开文档的标题**（值没变则早退）。⚠️ 只有命令层调它 |
| `create_untitled()` | 建一份空文档，把当时的 `untitled_count` **抄进 `untitled_index`**，`untitled_count += 1`，**设为活动** |
| `open(path)` | 已在集合里则**复用那一份**（不重复开标签）并设为活动；否则读盘、派生标题 |
| `reload(id)` | 从磁盘重读，`dirty = false`，`revision += 1`。没有路径时报 `NoActiveDocument` |
| `sync(id, text)` | 内容没变 → 原样返回；变了 → 换文本、`dirty = true`、`revision += 1`、重派生标题 |
| `settle(id, text)` | **装载收尾**：换文本（变了才 `revision += 1`）、刷 `clean_text`、`dirty = false`。⚠️ **不早退**，理由见上面那一段 |
| `save(id, path_override)` | `path_override` 就是「另存为」。没有路径又没给 override → 报"这份文档还没有路径，请用「另存为」"。落盘后清 `dirty`、重派生标题、`revision += 1` |
| `移到(id, 目标)` | **挪磁盘上的文件**（`file_move::移动`），成功后只把 `path` / `title` / `revision` 换掉。⚠️ **不碰 `text` / `clean_text` / `dirty`**——挪的是文件不是内容，内存里那份未保存的改动照旧挂着、下一次存盘写到新路径上。⚠️ 没有路径时报"这份文档还没存过盘，先用「保存为」给它一个位置"（**不替用户存一份到他没选过的位置**）。⚠️ `revision += 1`：插件与前端靠它判断手里那份是不是旧的，而路径变了确实是它们该知道的一件事。**改名与移动都是它**——"重命名"只是在同一个目录里换个文件名（`commands/document.rs::nota_doc_rename`），两者共用一个后半段 |
| `close(id)` | 从 `docs` 里移掉；**若关的是活动文档，活动切到 `docs` 里的最后一份**（没有就 `None`） |
| `get` / `get_mut` / `active` / `active_id` / `list` | 读 |
| `set_active(id)` | 文档不存在时报错 |
| `has_unsaved()` | 任意一份 `dirty` 就为真（`nota_doc_has_unsaved` 用它） |

⚠️ `close` 只是把记录移掉，**不做未保存询问**——那是前端的事（它才知道用户点了什么）。
`ui/useDocuments.ts::closeDoc` 里用 `settings.confirm_unsaved` ＋ **自绘的三选框**（保存并关闭 / 丢弃并关闭 / 取消）兜这一层——⚠️ 早就不是 `window.confirm` 了，那个会阻塞 WebView 并打断输入法组合态。

### 4.4 `derive_title()` 的顺序

窗口标题的取值口径，**从上往下第一个命中的胜出**：

1. YAML front matter 里的 `title:`；
2. 第一个 ATX 标题（`# ` ~ `###### `）；
3. 文件名的 stem；
4. `"未命名 N"`。

两条细则（都有单元测试）：

- front matter 必须**在文件最开头**（`lines.next()` 是 `---`），到下一个 `---` 或 `...`
  结束（front matter 的通用界定）；里面没有 `title:` 就返回 `None`（**不**继续找）。
- 扫 ATX 标题时**跳过围栏代码块**（``` 或 ~~~）——那里的 `#` 多半是 shell 注释。
- `#标签` **不是**标题，`# 标签` 才是（`rest.starts_with(' ') || rest.is_empty()`）。

### 5.1b 界面语言：存的是**设定**，不是结果

`general.language`（`src-tauri/src/settings/general.rs`，2026-09-25 加）是全套多语言的
**唯一一个设置字段**——插件的文案表、前端的 `t()`、宿主那几张表都由它推出来：

| 事 | 事实 |
|---|---|
| 取值 | `"auto"`（默认，跟系统走）或一个 BCP-47 短横线写法（`zh-CN` / `en`）。⚠️ **空串按 `auto` 处理**（手写 `settings.toml` 的人可能清空它），判定只在 `lang::有效语言` 一处 |
| 存的是设定 | 存 `auto` 的机器换一个 `LANG` 就该跟着变，所以**不许在保存时把它翻译成具体语言**——那是一次性的、事后改不回来的猜测 |
| 生效时机 | ⚠️ **重启后生效**，界面上也是这么写的。理由不在前端：插件在**启动时**按这个语言加载自己的文案表，运行中换语言就得把所有插件重装一遍（跑 `on_unload` / `on_load`，里面有 `git`、有 HTTP），而"改个下拉就把用户的插件挨个重启一遍"不是个省事的取舍 |
| 谁是权威 | `src/lang.rs`（`支持的语言` / `语言名` / `插件兜底` / `应用兜底` / `自动` / `规范` / `匹配` / `读语言文件` / `有效语言`）。**宿主与插件的协商都问它**，`lua/api/i18n.rs` 不自己写一套 |
| ⚠️ 两个兜底：同值、不同概念 | 宿主那边是**两个**常量：`lang::插件兜底 = "en"`（**对插件作者的要求**，`plugin/manifest.rs` 拿它当"清单里有没有 `en`"的判据）与 `lang::应用兜底 = "en"`（**应用自己**的落点）。前端 `src/i18n/index.ts` 的 `兜底` 跟的是**后者**，**两边同值**。⚠️ 同值是**两个概念各自定的**，不是一个常量被两处引用：`应用兜底` 2026-09-26 一天里走过 `en` → `zh-CN` → `en` 一个来回（表只覆盖插件那一面时落到 `en` 会把界面切成两半；表铺齐之后按写下的条件翻回来）。⚠️ **2026-09-28 语言翻转之后那个条件不用再看了**——英语是**原文**，"英语界面完整"由构造保证。改任一处之前先读另一处 |

### 5.2 为什么是四条轴而不是一条

⚠️ **先把词定死，不然下面「第几条」会打架**（本节的编号**从 1 数到 4**，
而代码注释与 `AGENTS.md` 里说的「三条外观轴」指的是 **①②③**——那三条**不含文档主题**，
两套数法都对，只是范围不同）：

| 编号 | 轴 | 是不是「界面轴」 |
|---|---|---|
| ① | 界面风格 `ui_style` | ✅ |
| ② | 明暗 `ui_mode` | ✅ |
| ③ | 主题色 `appearance.accent` | ✅（2026-09-26 加，见 §5.2b） |
| ④ | 文档主题 `document_theme` | ❌ **不是**（见下） |

⚠️ 用户 2026-09-22 明确要求**不要合并成一条**；2026-09-26 加的 ③ 同样不许和 ①② 合并——
用户那天的话是「这个主题只包含一个 UI 的设计样式……而不包含主题颜色」：
**形状归风格、颜色归用户**。

⚠️ 用户 2026-09-23 又补了一条：「这是文档风格，不是界面风格，不应该影响到UI主题」。
所以 ④ 与 ①②③ **不是一类东西**——④ 的作用域在 `.editor-pane` 上，
**连 `data-*` 属性都没有**：

| 轴 | 设置字段 | DOM 属性 | 管什么 |
|---|---|---|---|
| 界面风格 | `ui_style` | `data-ui-style` | **一整套设计语言**（Adwaita / GitHub / macOS / Breeze / Windows 11 / Windows 10 / Yaru，**共 7 套**，各配明暗两格 = 14 种外观；⚠️ 2026-10-07 删掉了「Yaru 蓝」那一套）：换的不只是颜色，还包括控件形状、圆角、间距、动效、字体栈。⚠️ 它**不是**"主题"的同义词 |
| 明暗 | `ui_mode` | `data-ui-mode` | 亮/暗。`auto` 时跟随系统。**这条轴在任何风格下都成立** |
| **主题色** | `appearance.accent` | **内联 `--accent` / `--accent-fg` / `--switch-on`** | **2026-09-26 加的第四条**：强调色。**空串 = 跟随当前风格**（每档风格自带一个出厂色），填了就覆盖它。⚠️ **只覆盖这三个变量**（`--switch-on` 是 2026-09-30 加的，见 §5.2b），其余配色仍由「明暗」那条轴保证 |
| 文档主题 | `document_theme` | **（没有）** | **只管正文那一块**。纯 CSS，**只扫 Nota 自己的主题目录**，**不动应用外壳一分** |

⚠️⚠️ **④ 没有 DOM 属性，这一点是刻意的，不应加回去。** 它是一份注进 `<head>` 的
`<style id="nota-doc-theme">`，选择器被机械地收到 `.editor-pane` 之下
（见 `styles/doc-theme.ts`）。2026-09-23 之前它挂在 `<html data-doc-theme>` 上，
主题里的 `:root` 变量会被**提升到全局**、由 `theme.css` 末尾那排
`var(--nota-bridge-X, default)` 桥给外壳——**那正是"换个文档主题、整个应用跟着变色"的来源**，
用户的原话是「现在深色浅色都有，很混乱」。桥和提升都拆了。

⚠️ ①②③ 的落点都在 `<html>` 上（两条属性＋两个内联变量），④ 的作用域在
`.editor-pane` 上——**两棵不同的树**，一个变量都不共用。这条线有回归测试兜底
（`themes.rs::内置主题不碰界面变量`）。

### 5.2b 「主题色」为什么走**内联变量**而不是再加一个 `data-*` 属性

用户 2026-09-26 提「可不可以让用户自行选择主题色？」，随后补了设想：
「这个主题只包含一个 UI 的设计样式，比如说圆角的半径，而不包含主题颜色，
这样用户可以根据自己的喜好来定制。」

落到实现上就是**第 ③ 条轴**，但它和 ①② 三处不同，都是有意的：

| | ①②（风格 / 明暗） | ③ 主题色 |
|---|---|---|
| 落在哪 | `data-*` 属性（`<html>` 上） | **内联在 `<html>` 上的 `--accent` / `--accent-fg` / `--switch-on`** |
| 取值空间 | **离散**：CSS 里得预先写好每一格 | **连续**：1677 万种颜色，写不成选择器格 |
| 谁决定 | 我们（内置七档 + 用户导入的 `.css`） | **用户当场挑**（面板上一个原生取色器） |

⚠️ 内联自定义属性的优先级高于 `[data-ui-style][data-ui-mode]` 那 14 格选择器，
所以 `theme/color.css` **一行都不用改**——这也是"主题只管形状、颜色归用户"
这句话在代码里最省事的那种落法。

⚠️ **但"一行都不用改"只对"我们真的内联写了的那几个变量"成立**，2026-09-30 撞过一次：
`theme/base.css` 的 `:root` 里本来就有一句 `--switch-on: var(--accent)`（"开关跟强调色"
这个意图的原文），可它**优先级输给那 14 格**——各风格都把 `--switch-on` **各写了一个
字面值**（macOS 绿 `#34c759`、Yaru 橙 `#e95420`…），于是那句 `var(--accent)` 成了死代码。
用户设了主题色之后，色块变了、**右侧那些开关没变**，他报的就是这条（「还是橙色的」）。
处置：`accentVars` 把 `--switch-on` **也内联写一份**（内联优先于 14 格）；用户没设主题色时
**一个字都不写**，各风格的出厂长相（包括 macOS 那个绿）照旧。

⚠️ **前景色（强调色上面那行字）不存进设置**，由 `styles/accent.ts::accentFg` 按
对比度当场算。存下来的话，改一次主题色就可能留下一对"白字排在浅黄上"的组合，
而那种组合在设置界面里怎么看都看不出来（它只在真正用上的那一处露出来）。
判定那条线的来历（**是一个亮度阈值 0.25，不是"挑对比度高的那个"**）写在
`styles/accent.ts` 与 `tests/accent.test.ts` 的文件头。

⚠️ **认不出的值不报错、不清洗**，一律按"跟随风格"处理（同 `ui_style` 拼错那条口径）：
这一格是用户手改 `settings.toml` 会敲错的地方，让一个拼错的颜色**把整份设置
读不回来**比让它安静失效坏得多。「外观」页有一句红字把这件事当场说出来
（`stg-warn`），`settings/appearance.rs` 有一条测试盯着"写着一个认不出来的值
也不许把设置读死"。

把"形状"和"颜色"合成一条的后果很具体：想做"macOS 风格 + 暗色"时发现颜色写死在
风格里了，于是只能再加一套 `macos-dark`——轴数就从 3 变成了排列组合。所以 CSS 的
组织方式是**二维相乘**（见 `docs/04-ui-map.md` §3）。

⚠️ **`view_mode` 不是第四条轴**（2026-09-23 加的）。它管的是"**怎么编辑**"
（编辑区摆一个窗格还是两个、哪一侧可写），而那三条管的是"**长什么样**"。
两者之间没有任何耦合：任何模式 × 任何外观都成立。⚠️ 它不该写进 `theme.css`
那种地方，也不算进下面这张"轴"表。

⚠️⚠️ **2026-10-07 起它连"设置里的字段"都不是了**：`settings.view_mode` 已退休
（用户原话「请设置默认启动为 WYSIWYG」），模式改成**会话内状态、不落盘**——
每次启动一律 `wysiwyg`，Rust 侧**没有这个枚举了**，`src/bridge/types.ts` 那份
`ViewMode` 是唯一一份。默认值只有一处：`ui/useFileKindMode.ts` 里那条
`useState("wysiwyg")` 的初值（那条 hook 兼任"用户选的那一档"的家，见 `docs/02`）。

| 取值 | 编辑区 | 谁的话算数 |

| `Source` | Markdown 原文（CodeMirror） | CodeMirror |

（三条口径与"为什么分屏只朝一个方向"见 `docs/05` §3.1。）

`Windows10`（Windows 10 原生，**只能手选**——Win10 与 Win11 的 UA 是同一串

### 5.3 "存法即接口"：kebab-case 落盘

设置文件里带 `#[serde(rename_all = "kebab-case")]` 的枚举现在**只剩一个**
（`UiMode`），所以文件里写的是：

```toml
ui_style = "macos"
ui_mode = "dark"
```

而**不是** `"Macos"` / `"Dark"`。这条不是审美问题：

- 这串字符串**就是接口**——用户手改 `settings.toml` 时要能猜到怎么写；
- 前端的类型也是同一批串：
  `export type UiStyle = "auto" | "adwaita" | "ghub" | "macos" | "plasma" | "windows" | "windows10" | "yaru";`
  `export type UiMode = "auto" | "light" | "dark";`
  `export type ViewMode = "wysiwyg" | "source" | "split";`
  （`src/bridge/types.ts`），改一处就要改另一处。⚠️ `ViewMode` 那一条 2026-10-07
  **只剩前端这一处**了（Rust 侧那份已删），但写法照旧——它落的是快捷键表、
  菜单 id 那些**别的**字符串接口，不是设置文件。

⚠️⚠️ **这节的 `kebab-case` 不是全仓通例**（2026-09-27 补）：`settings/appearance.rs`
里那**两个**枚举走的是 **`snake_case`（下划线）**——`ToolbarMode`（`always` / `hover` /
`never`）与 `CtrlWheelTarget`（`font_size` / `zoom`）。它们不是"外观轴上的取值"，
当初就没跟这条口径走。⚠️ **所以加新枚举之前先看 `.rs` 里那行 `rename_all`，
别照这节猜**——猜错的写法是**认不出的变体**，而 `load_from` 解析不了时**报错**，
也就是**整份 `settings.toml` 读不进来**（不是那一格静默回默认）。`[appearance]` 那两格
逐项见 §5.6b。

加一条新轴上的新值时，**三处缺一不可**：`settings/mod.rs` 的枚举、`src/styles/theme.css`
（以及 `applyTheme.ts` 需要的解析分支）、`docs/04-ui-map.md` 的外观一节。
⚠️ `view_mode` 加值时是**另一组、而且 2026-10-07 起全在前端**：`src/bridge/types.ts`
的类型、`ui/view-modes.ts` 的表（`Record` 会当场报错，它是这条规矩剩下的唯一一处
编译期保险）、`ui/commands.ts` 的「视图」栏三条（id / label / 快捷键）、
`ui/useMenus.ts` 的 `menuChecks` 三条（外加 `docs/04`）。

⚠️ **默认值现在只有一处**（2026-10-07 改）：`ui/useFileKindMode.ts` 里那条
`useState("wysiwyg")` 的初值——Rust 的 `impl Default` 与前端的兜底读写随
`view_mode` 一起退休了。⚠️ 老设置文件里残留的 `view_mode = "…"` **必须继续
被忽略**（那是"用户升上来发现进了别的模式"的另一条路），`settings/mod.rs` 那条
`老设置文件里没有那七张表时全是默认值` 的用例故意在样例里留了这一行钉着它。

### 5.4 读写口径

- `nota_settings_get` 直接克隆内存里那一份。
- `nota_settings_set` 是**整份替换**并落盘：先改内存 → 落盘失败则**把内存改回去**
  再返回错误。否则会出现"界面上是新的、重开又变回去"这种最难解释的状态。
- 为什么是整份替换而不是逐项 patch：设置项还少，patch 语义（"没给的字段不动"还是
  "没给的字段恢复默认"）会变成一个新的、没人想要的理解负担。
- 启动时读失败**不回滚启动**：一份坏掉的 `settings.toml` 不该让人连界面都进不去，
  退回默认值 + 在控制台说明（`lib.rs::run`）。

⚠️ `nota_settings_set` **改了 `strict_markdown` 之后要连带做两件事**（`commands/settings.rs`）：
调 `set_strict_markdown()` 把文档表里所有文档的**推导标题重算一遍**（标签页标题是后端
按当前口径从正文算的），并把 `settings` 锁**先放下**再动 `documents`——锁序是
`plugins → documents → settings`，反着拿会死锁。

### 5.5 ⚠️ 严格模式：关着的时候**一个字节都不改**

用户 2026-09-24 定的死规矩，原话「**注意应用中不应出现"同外部编辑器"这种。如果关闭，
存盘不要自动修复。**」两条都要读：

1. 应用里（用户看得见的字符串）**不许拿别的编辑器当参照**——那是给开发看的
   口径，写在 `docs/10` 里；
2. **宽松模式（默认）存盘不许改用户的字**。`#你好` 存下去还是 `#你好`：不许补成
   `# 你好`，也不许加上 `\#` 转义。

第 2 条的落地方式见 `docs/02` 的 `lax-heading.ts` 那一节：**文档树里它就是个段落**
（所以序列化必然原样吐回来）。⚠️ 显示那半边**改过三次口径**，三次都是用户拍的板：
**2026-09-26** 用户说「应该作为标识符的 `#` 不要变换位置和大小」，于是"把 `#你好` 画成
标题"的显示层装饰**整个删掉**，那天起 `#你好` 就是普通段落的样子（⚠️ 删之前它一度
"跳过光标所在的那一段"，那只是绕过——光标一走开照旧跳成 h1 字号，用户 09-26 报的正是这个）；
**2026-09-29** 用户又要求宽松那条**按标题排**，只是「**输入时先不放大，等用户回车后再放大**」
——装饰因此回来了，但**搬进了 `heading-on-enter.ts`**；
**2026-09-30** 那份长相又被推翻一次，**这次是定稿**：用户要的是「**类似 `# 你好`。就是不回车
只是显示加粗，回车变成标题。**」——于是 `#你好` 和 `# 你好` 走**完全同一条路**，输入期
一律**只加粗**（`.nota-heading-pending`），**按下回车才成块放大**。09-29 那套"按该级字号排
＋ 正在写的不放大"（判据是"最近一次改动文档的那笔事务落在哪一段、光标还在不在那里"）
**整个删掉**。

⚠️ **现在判"写完了没有"只剩一条判据：它还是不是段落**——是段落就只加粗，按了回车就成了
标题块、由 `h1`~`h6` 自己排。**光标在哪儿完全不参与**（点走／切窗口／敲方向键什么都不发生）。
装饰一直是 `Decoration.inline`（只作用在**正文那段文字**上，井号本身一个像素都不动），
不是当年那个整段包 `<h1>` 的 `Decoration.node`。判据与代价详见 `docs/05` §4.9c。
⚠️ `lax-heading.ts` 因此**只剩 `不转义行首井号` 一个导出**（`create.ts` 引它进序列化扩展），
文件不能删——删了 `#你好` 存盘会被加上反斜杠，下面那条不变量当场就破。⚠️ 这是一条
**结构性**的保证，不是靠每一步小心——从这里到文件那条路上没有一步会改字（显示怎么变都
不碰这一条：装饰是 `Decoration`，一个字节都不写回）。**唯一的例外是用户按下的回车**，
见下面第二处。

**存盘字节是唯一判据**：改完要拿一份 `#标签` 的文件开窗，Ctrl+S，比对 md5
（两种模式都要比，见 `docs/06` §5）。⚠️ 只看"屏幕上显示对不对"证明不了这条——
第一版就是因为只看了显示，存盘时被序列化器加了个反斜杠，用户看到的是"我写的字被改了"。

**已知的两处改字**（都登记在案）：

1. 用户**手打**的 `\#标签`，存盘会变成 `#标签`——反斜杠没了。原因是转义井号和裸井号在
   文档树里**是同一个东西**（都是文本 `#标签`），要区分就只能保留源码（那要改 schema，
   是另一个量级的工程）。⚠️ **差别只在字节上**：两者的解析结果、以及 Nota 里的显示
   **完全一样**。它属于 `docs/05` §3.1「往返会改字」那一族，不是新的破口。这条**不打算修**。
2. 📌 **2026-09-30 新增**：宽松档下用户**按回车**把 `#你好` 变成标题块时，序列化出去是
   `# 你好`——**多一颗空格**（标题节点固定是"井号 ＋ 空格 ＋ 正文"）。⚠️ 这**不算违反**
   上面那条不变量：规矩管的是**存盘时不许自动修复**，而这里改字的是**用户自己按下的
   回车**，他明确要的就是"变成标题"。**不按回车，一个字节都不动**——这一半仍然成立。

### 5.6 `[focus]`：强制专注的四个旋钮、三个不变量

**2026-09-26 加**（`src-tauri/src/settings/focus.rs`，`Settings::focus`）。⚠️⚠️ **它是核心功能的设置，不是插件的**——
用户原话是「注意啊，这不是插件。这是核心功能」：它要窗口焦点、要开一个置顶窗、要出声，
三样都在插件沙箱之外（`docs/12` §4.7a）。

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `total_minutes` | `u32` | `25` | **账户余额的上限**（分钟）。⚠️ 不是"这一轮打算坐多久"——写满它就**封顶**，不能先攒两小时额度再摸两小时鱼（`写满就封顶` 那条用例钉着这个语义） |
| `alarm_minutes` | `u32` | `20` | **开局余额**（分钟）。⚠️ 它才是"一直不写，多久会响"的那个数，**不是** `total_minutes`。用户说的「大概 20 分钟左右…启动报警」指的就是它 |
| `gain_per_minute` | `f64` | `1.0` | 专注 1 分钟**加**多少余额（分钟）。所以单位是**分钟**——四个旋钮各自的话才都说得通："写 1 分钟赚 1 分钟" |
| `drain_per_minute` | `f64` | `1.0` | 离开 1 分钟**扣**多少余额（分钟）。⚠️ 要"更狠的模式"该拧这一条（调成 2 = 写两分钟才够摸一分钟），**不是**把 `alarm_minutes` 调小——那只让一上来就快响，写起来之后该磨还是磨 |
| `grace_seconds` | `u32` | `10` | 失焦后的**免罚宽限**（秒）。用户原话：「如果用户在这段时间内系统窗口焦点离开这个编辑器超过 10 秒」。⚠️ 设 0 = 一失焦就扣 |
| `sound` | `bool` | `true` | 警报响不响。默认**响**（用户要的就是「发出尖锐的警报声」）；给这一格是留一条"我在图书馆"的出路 |
| `introduced` | `bool` | `false` | **首次说明**弹窗看过了没有。⚠️ **它必须落盘**：只在内存里的话，每次重启都会再被拦一次，用户很快就学会闭眼点掉，而那正好把这次说明的意义抵消掉 |

⚠️ **余额的单位是「分钟」，但账本内部存毫秒（整数）**。浮点费率可以（用户可能想要 0.5），
**乘完立刻取整成毫秒**，账本本身是整数——余额要被一秒一拍地加减，浮点累加会攒出可见漂移，
而"为什么显示还剩 0.0000001 分钟但就是不响"是没人能排查的那类故障。

⚠️ **三个不变量**（各有一条用例钉着，`focus/mod.rs` 的测试表见 `docs/02`）：

| 不变量 | 一句话 | 少了它会怎样 |
|---|---|---|
| **宽限期内不欠账** | 扣费从第 `grace_seconds + 1` 秒起算，不是"先记上回头一起扣" | 用户切出去查个词、复制一行引用就挨一刀，而那种扣费跟"摸鱼"没关系——**罚得太密就等于没罚**，用户会干脆关掉这个功能 |
| **警报中账本冻结** | 警报那一拍不赚也不赔 | 警报窗**自己会抢焦点**，不冻的话它会把自己判成"用户回来了"或"用户跑了"，一秒钟自我扣费成连环响 |
| **冷却要攒到复活线** | 响过一次之后必须先**把余额重新攒过复活线**才允许再响。复活线取 `上限 / 4` 并夹在 **10 秒 ~ 1 分钟**之间（默认配置下 = 1 分钟） | 用户点掉警报就白拿一次复活（"摸到响、点一下、继续摸"）。⚠️ 冷却**故意不做成设置项**：它是防炸的保护、不是偏好，暴露出去只会多一个"把它调小"的坑 |

⚠️ **为什么是账户模型而不是"每 20 分钟无论如何响一次"**：用户先说过后者，
**紧接着自己推翻**了并点出了漏洞——「应该考虑到他是不是单纯切换回来就为了避免警报」。
计时器模型下那个漏洞**无解**（切回来 3 秒也算"回来了"，计时器一重置，
"每 19 分钟切过去 3 秒"就能一直不响）；账户模型下它自己就没了：切回来 3 秒只赚回 3 秒的额度。
**只有真的在写，额度才会涨。** ⚠️ 这一段是这一页存在的全部理由，改模型时先回来看它。

⚠️⚠️ **这里没有、也不该有"哪个应用算摸鱼"的字段。** 用户 2026-09-26 把宽限名单整个砍了
（「宽限名单不用开了。把这个功能删掉吧，干脆」），字段与用例一并删干净。
`focus.rs` 里那条用例 `设置里没有任何看别的应用的东西` 是**承重**的：它拿默认值序列化一遍，
断言文本里不出现 `app` / `window` / `foreground` / `xprop` / `process` / `title` 六个词——
**守的是"强制专注只看本应用自己的窗口有没有焦点，不越过应用的边界"这条决定**。
要加回"读活动窗口"这类能力，得先改 `focus` 模块头那段说明，然后这条测试会红，
然后改它的人必须解释为什么。⚠️ 设置页那格留着**灰着的**，它的 `title` 说的是「决定不做」，
**故意不跟**别处那几格的「尚未实现」——那三格是会做的，这一格是不做的。

⚠️ **会话状态不在这里，也不该在这里**：此刻余额还剩多少、处于哪个阶段（`专注` / `走神` / `警报`）、
这一轮坐了多久，全都只在内存里（`FocusState`，每秒都在变），出口是状态栏那一格
（`ui/FocusMeter.tsx`）。设置页显示一个每秒跳动的数会让整页都在重画，
而用户来那一页是为了**改参数**，不是为了看表。

### 5.6c `[editor]` 里的「段首缩进」：**看着**缩进，不是把空格写进文件

**2026-09-27 加**（`src-tauri/src/settings/editor.rs`，字段 `paragraph_indent` ＋
`paragraph_indent_chars`，默认 **关** / **2**）。用户原话：「标题下方第一行默认没有缩进。
在设置中加入：缩进是否开启&以几个字符的宽度缩进」，紧接着又补了一句「第一段没有那个
是现状。**要求改**」——所以标题下面那一段**照样缩**，没有"标题后第一段不缩"这条例外
（那是英文排版的规矩，中文排版不给它开例外）。

⚠️⚠️ **它一个空格都不往文件里写**，这是这个字段全部设计的起点。真按"段首打两个全角
空格"来实现的话：

| 会出的事 | 为什么 |
|---|---|
| 源码模式与别的编辑器里**看得见脏字符** | 那两个空格是文件内容的一部分，不是排版 |
| `  - 列表项` 这种行**含义会变** | 行首空格在 Markdown 里是语义（缩进 ≤3 个还当列表，≥4 个变代码块） |
| 用户关掉开关之后**删不掉** | 得逐段退格，或者写一个"扫全篇删行首空格"的工具——那个工具还会误伤代码块 |
| 导出/存档**被污染** | 别人 clone 下来的文档里就有两个空格，而他并不知道为什么 |

所以它落在 **CSS** 上（`text-indent`）：`styles/applyTheme.ts` 把 `--para-indent: 2em`
写在 `<html>` 上（**关着时把这个变量摘掉**，让 `editor.css` 里那条 `var(--para-indent, 0)`
兜底——同上面「界面字号」「主题色」两段的写/摘口径），消费者只有
`styles/editor.css` 里的一条 `.editor-mount .ProseMirror > p`。

⚠️ **单位是 `em` 不是 `px`**：用户填的是"几个字符宽"，1em = 一个汉字宽；正文换字号、
换文档主题，缩进跟着变——这正是这一项该有的行为（px 会让缩进在放大字号时变窄）。

⚠️ **只认顶层段落**（选择器那个 `>`）：引用、列表项、表格格子、代码块里的段落一律不缩。
中文排版说的"段首空两格"针对**正文段落**；引用与列表项自己已经有左边距，再缩一层就是
两层缩进，表格格子还会被撑歪。⚠️ 去掉 `>` 在开窗目检时**看着也对**（最常见的文档就是
一堆顶层段落），改之前先想这条。

⚠️ **它与同页那条「默认缩进」（`default_indent`）是两个东西，而且默认值都是 2**——这个巧合
值得单独说一句：两者被写串、或者被并成一个字段，**光看默认值看不出来**，所以
`editor.rs` 里那条用例把两个数设成 3 与 6 再落盘、断言两行都在。

⚠️ **区间 1~8**，两处各夹一道：设置页那格写着 `min=1 max=8`（越界进不来），
`applyTheme.ts` 那一处再夹一次（手改 `settings.toml` 写成 `999` 的人不该把一行推到屏幕外）。

⚠️ **导出 / 打印 / 分屏预览里没有它**，这是有意的，不是没接完：那三处拿的是**文件本身**
（导出生成 HTML、打印走同一份 HTML、分屏预览走只读实例），而缩进是"看着"的属性、
没写进文件。与同页的「正文宽度」是同一条边界——它也只管编辑区
（⚠️ 正文宽度那一格 2026-10-09 起默认**关**，见 §5.1 那张表）。
**要不要让导出的 HTML/PDF 也带上段首缩进**是**用户还没拍板**的一件事
（记在 `docs/07`），别默默接上去：那会让"我存下来的文件和我在屏幕上看到的不一样"
从一个 bug 变成一条规矩。

### 5.6d `[editor]` 里的「智能符号补全」：**一个开关管整条插件**

**2026-09-28 加**（`src-tauri/src/settings/editor.rs`，字段 `smart_symbols`，**默认开**）。
用户原话：「自动补全 `*`、`[` 这种在设置中搞一个选项，**智能符号补全**。**默认为开**。」

⚠️⚠️ **它取代了 `match_brackets` / `match_markdown` 那两条死开关**（同批删掉）。那两条
**存了值、从来没有任何代码读过**——界面上摆着两颗能拨的开关、拨了什么都不发生，
**比没有那两颗更坏**：用户会以为自己关掉了一件事，然后去找"为什么没用"。它们本来就是
一件事的两半（用户原话里 `*` 与 `[` 是并列举的两个例子），所以按用户要的"**一个**选项"
合成一格。

⚠️ **它是整条插件的开关，不是"补得少一点"**：关掉时 `src/editor/auto-pair.ts` 的
`配对处理()` 返回 `[]`，也就是**这条插件不装**（Milkdown 的 `.use([])` 是合法的，
`smart-punctuation.ts` 的 `标点输入` 是同一个做法）。四件事——补一对 / 跳过右半边 /
空对退格 / `Tab` 跳出右半边——**只能一起关**，因为 `Tab` 跳的正是我们补出来的那颗闭括号。

⚠️ **改它要重建编辑器**：与编辑器那一页其余选项同一个口径（建实例时取一次，
`editor/create.ts` 里 `options.智能符号 ?? true`）——设置页改完，已开着的文档要重开才生效。

⚠️ **老设置文件里那两行留着不报错**（`#[serde(default)]` 只认自己认识的键，多余的忽略），
下次保存时自然消失。`editor.rs` 里有一条用例专门钉住这件事（`老的两条配对开关留在
文件里也不报错`）：它防的是**后来有人加上 `deny_unknown_fields`**——那会让升级后的
第一次启动直接掉进"设置读不出来"的兜底里。**不为老配置写迁移代码**是这个项目的既定口径。

⚠️ 字段本身的语义（打哪颗补哪颗、`[` 与 `*` 各走哪条路）记在 `docs/05` §4.20–4.20c；
界面上那一格在 `docs/04` §3.5（编辑器那一节·「智能符号补全」）。

### 5.6e `[editor]` 里的「拼写检查语言」：**空串是一个有含义的档**

**2026-10-10 加**（`src-tauri/src/settings/editor.rs`，字段 `spellcheck_lang`，**默认空串**）。
用户原话只有一句：「**拼写检查允许设置不同语言**」。它和上一页那个开关是**一对**
（`spellcheck` 管开不开、这一格管用哪本词典）。

⚠️⚠️ **值的写法是 enchant/hunspell 那套 `语言_地区`（`zh_CN`，下划线）**，不是 BCP-47 的
`zh-CN`。这条不是风格问题：那一串字符串会被送进
`WebKitWebContext::spell-checking-languages`，由 WebKit 拿去做
`enchant_broker_dict_exists()` 查词典——写成连字符时**查不到**，而症状是**一个字都不检查**。

⚠️ **空串 ＝ 跟随系统**，而且这是 WebKit 自己的语义（不是"我们不去设"）：
`TextCheckerEnchant::updateSpellCheckingLanguages` 里，列表为空那一支会去取系统默认语言，
连它都没有词典才退到"装着的第一个词典"。所以"跟随系统"这一档落的是**一个空列表**，
不是"跳过不调用"——跳过的话上一个语言会一直留着。

⚠️ **这一格不保证画得出红线**：真词典得机器上装过（Nota 一个字节都不带，`THIRD-PARTY.md` §7）。
点名了一个没装词典的语言时，WebKit 会**一本词典都不加载**，于是**那个语言下不检查**。
前端拿"设完之后读回来的词典列表是不是空的"把这件事说出来（`ui/useSpellcheck.ts`）——
2026-10-10 在无头窗里点过两档：选 `zh_CN`（容器里没这本词典）**弹了那句提示**，
选 `en_US` **没有弹**。

⚠️ **界面上是两行**：一行下拉（跟随系统 ＋ 十六个常见语言 ＋ 自定义），选了「自定义」
才出现第二行的文本框（自己敲 `ca_ES` 这种）。⚠️ 开关关着时**两行都不画**——同「正文宽度」
那条滑杆的口径（画出来就得解释"为什么选了没反应"）。

⚠️ **`lang` 属性是顺手补的语义，不是它挑词典**：正文那一层拿到了一个连字符形式的
`lang`（`zh-CN`，断词/朗读/别的内核用得上），而这一版 Linux 上真正决定用哪本词典的是
上面那个语言列表——2026-10-10 读了 WebKit 源码确认（`checkSpellingOfString` 从头到尾
没有语言参数，拿的是全局那几本词典）。

但**改名会让用户存下来的那格开关被静默清掉**（`#[serde(default)]` 遇到认不出的键就是回默认值）。
代价是名字与语义对不上，所以那张表就写在这个字段的文档注释里。

根本没有 `ctrl_wheel_target` 这一格，它取默认值 `FontSize`，而 `ctrl_wheel_zoom` 照旧认
（`appearance.rs` 里那条用例拿 `ctrl_wheel_zoom = true\nzoom = 150\n` 钉着这半边）。
这么选的理由是**改字号比改缩放更常见、出问题也更小**——滚轮把整个界面放大到 300% 的观感
比字号从 15 变到 18 吓人得多。而且这一项在设置里一眼能看见、改回去一步
（「滚轮改什么」那个 `Select`，就在「按住 Ctrl 时用滚轮」开关的下面）。

⚠️ **改字号那条路必须顺手打开顶层 `custom_font_size`**：那一格是"这个数算不算数"的开关
（`applyTheme.ts` 里那一支写着）。不打开的话滚轮**看起来一点用都没有**——`ui_font_size`
从 15 滚到 18，界面一个像素不动，而设置里那个数确实变了。这不是"替用户多做一步"，
这就是"滚轮改字号"这件事本身的意思。⚠️ 落盘写的是**顶层** `ui_font_size`
（＋`custom_font_size`），`zoom` 才落在 `[appearance]` 里——三格分居两处，改的时候别只改一边。

⚠️ **上下界与步长在前后端各写了一份，必须一致**：`ui/useZoom.ts` 里是
`缩放 50~300%／一格 10%`、`字号 12~20px／一格 1px`（＋兜底字号 15，与 `Settings::default()`
的 `ui_font_size` 对齐），设置页 `AppearancePane.tsx` 那两颗控件写着同样的数
（字号那颗是 `Range` `min=12 max=20`，缩放那颗是 `NumberInput` `min=50 max=300 step=10`）。
不一致的症状是"滚轮能滚到设置里填不出来的值"。⚠️ **滚轮是热路径**，所以
`useZoom.ts` 的做法是**立刻改、攒 400ms 再落盘**（每一格都 `updateSettings` 会把设置文件写穿）。

### 5.6e `[files]` 的「启动时」：一个三值枚举，落盘是 kebab-case

| `"last-file"` | 打开后自动打开上次的文件 | 标签顺序、前台是哪一份都照旧，**但没有那个文件夹** |
| `"last-session"` | 打开后自动打开上次的文件和文件夹 | 上面那些 **＋** 侧车里的 `workspace` |

⚠️ **第三档落到 `"last-session"`、不是 `"folder"`**（2026-09-27 改的名）：老名字说的只是
"打开文件夹"，而它真正干的是"连文件带文件夹一起接上"——**按老名字实现的话，第三档会比
第二档少恢复标签**。⚠️ 那个 `#[serde(alias = "folder")]` **不能删**：老设置文件里可能
已经存着 `startup = "folder"`（那一档在界面上一向可点，只是从前没人读它），删掉别名
会让**整份 `settings.toml` 解析失败**——而 `load_from` 在解析不了时是**报错**（不是静默
回默认），用户看到的是"我的偏好全没了"。留着它，老值读进来就是第三档。

⚠️ **这个字段 2026-09-27 之前是摆设**：全仓没有一处读 `files.startup`，而前端的
`接上会话` **无条件恢复一切**＝永远按第三档办。所以这一批**改了默认行为**：没动过这一项
的人，启动从"什么都有"变成"一张白纸"——那正是第一档的词义、也是 `default()` 一直以来的值。
⚠️ **第一档不是"什么都不干"**：`最近打开` 那份记录照记（那是另一个设置项的功能，
不该被启动档连坐）。

### 5.6f `[keys.overrides]`：只存**差量**的一张表

**2026-09-27 晚加**（`src-tauri/src/settings/keys.rs::Keys`，`Settings::keys.overrides`）。
形状是 `BTreeMap<String, String>`：**命令 id → 键位串**（`"file.saveAs" = "Ctrl+Shift+S"`）。

| 表里 | 含义 |
|---|---|
| **没有这个 id** | 用 `src/ui/commands.ts` 里 `MENUS` 的默认键位（可能本来就没有） |
| 有，值非空 | 就用它 |
| 有，值是**空串** | **这条命令不要快捷键** |

⚠️ **只存差量、不存整张快照**，两个理由写在 `keys.rs` 文件头：① 存快照的话，
**新加的命令在老用户的设置里没有**，于是"表里有几条"和"实际有几条命令"出现两个数，
缺的那条会静默地没有快捷键；② 改一个默认键位（哪怕只是修一次撞车），**所有用户都被
钉在旧值上**——他们那份完整快照里存着旧值。只存差量，没动过的命令永远跟着 `commands.ts` 走。

⚠️ **空串那一档是必需的，不是"顺带支持"**：用户想把某条的键位腾出来给别条用，就得能
把它清掉；而"从表里删掉这一项"表达的是"回到默认"，正好相反。**两者必须能分开**，
否则用户改不回默认。⚠️ **这里不做清洗、不做校验**（认不出的 id、写错的键位串原样存原样
取）：判据（认不认得那个键位）在前端，在这儿重写一遍迟早两边不一致；手写 `settings.toml`
写错一个键位串，前端当"没有快捷键"处理，不炸——与别的设置项待遇一致。
⚠️ 用 `BTreeMap` 不用 `HashMap`：它要写进 TOML，**按键名排序**之后每次存盘的字节一样，
用户拿它去 diff 不会满屏乱跳。

### 5.6g `[files]` 的「文件树」三格：一个排序枚举 ＋ 两个**摆了四天**的开关

**2026-09-28 加**（`src-tauri/src/settings/files.rs::TreeSort`、`FileFilter`、
`Settings::files.{tree_sort, tree_filter, show_hidden}`）。

| 字段 | 取值 | 界面上的字 | 默认 |
|---|---|---|---|
| `tree_sort` | `"name"` / `"modified"` / `"created"` | 按名字（A→Z）／最近修改的在前／最近创建的在前 | `"name"` |
| `tree_filter` | `"supported"` / `"all"` | 只看支持的文件／显示全部文件 | `"supported"` |
| `show_hidden` | `true` / `false` | 显示隐藏文件 | `false` |

⚠️ **只有「按名字」是升序**，两个时间档都是**新的在最上面**：用户想看的是"我刚改过的那几份"，
按时间升序要点到列表另一头去。这条取舍写在枚举三档的文档注释上，改之前先想清楚它是不是
两档各说各话。

⚠️ **目录永远排在文件前面**，三档都一样：树是靠缩进与层级读的，把目录混进文件里按时间排，
读起来是一堆不知道该不该展开的行。

⚠️ **`"created"` 拿不到创建时间时退回修改时间**（`meta.created()` 在有些文件系统上直接报错，
ext4 要有 statx 才有 btime），**不是"排到最后"**：排到最后的表现是"这一批文件不参与排序"，
看起来像排序坏了。目录排的是它**自己**的修改时间（在里面加/删文件会更新它），不是"里面最新的
那一份"——后者要递归下去，展开一层就等于把整棵子树读一遍。

⚠️ **`tree_filter` 与 `show_hidden` 是各自独立的两格**：默认档 `"supported"` 会把 `.env`
这类非 Markdown 文件挡在外面，所以"只拨开隐藏文件"看到的是 `.github` 而没有 `.env`——
这不是 bug，是两格各管各的（`commands/workspace.rs` 的测试里有一条把这件事钉住）。

⚠️ **`.git` 与 `node_modules` 永远跳过，与 `show_hidden` 无关**。这一条与上面那两格**必须
分开写**（两个判断原本挨在一起）：合在一起的话，拨开隐藏文件会连 `node_modules` 一起冒出来。

⚠️ **`tree_filter` 与 `show_hidden` 从 2026-09-24 起就摆在设置界面上，而 2026-09-28 之前
一个消费者都没有**——`commands/workspace.rs::read_dir_sorted` 里那两个判断是**写死**的
（点开头的一律跳过、只列 markdown），拨了等于没拨、一个字都不报。这一批是**给旧字段补上
消费者**，与 §5.6d 的智能标点同一类账。

⚠️ **口径不落在这两格上读**：`nota_workspace_tree` 收一个 `TreeOptions`（三格可选，逐格回落
到 `[files]`），也就是**口径随请求走**。理由与"先改内存再写盘"那条有关：用户在下拉里换成
"按修改时间"之后紧接着发出的那一次取树请求，完全可能赶在设置到达宿主**之前**，症状是
"拨了没反应、过一会儿自己好了"。完整的取舍写在 `src/ui/tree-options.ts` 的文件头与 `docs/07` 第 85 项。

## 6. `Capability`：插件能申请什么

定义在 `src-tauri/src/plugin/manifest.rs`。清单里写的是**字符串**，解析成枚举；
**未知能力报错而不是忽略**——悄悄忽略会变成"插件作者以为申请到了、实际没有"的静默降级。

| 清单里写的串 | 枚举变体 | 意味着什么 |
|---|---|---|
| `document.read` | `DocumentRead` | 读当前文档：`nota.document.get_text / get_path / get_title / get_revision / is_dirty` |
| `document.write` | `DocumentWrite` | 改当前文档：`set_text` / `append_text`（**整篇替换语义**，写完发 `nota:document-changed`）／ **`insert_at_cursor`**（⚠️ **不改镜像**——发编辑意图 `nota:document-edit`，由编辑器落一笔真事务；第 14 项，2026-10-04） |
| `fs.read` | `FsRead` | 读**工作区内**的文件（界外一律拒） |
| `fs.write` | `FsWrite` | 写**工作区内**的文件 |
| `process.git` | `ProcessGit` | 起子进程跑 `git`。⚠️ **只放行 git 这一个命令**，不是通用 subprocess |
| `network.http` | `NetworkHttp` | 发 HTTP 请求。⚠️ **宿主侧尚未实现**：装的是"尚未实现"表，调用返回"网络请求尚未实现（见 docs/07 第 12 项）" |
| `ui.notify` | `UiNotify` | `nota.ui.notify` → 发 `nota:notify` 事件（⚠️ `nota.ui` 三条里**唯一推事件**的） |
| `ui.panel` | `UiPanel` | `nota.ui.register_panel` → **写 registry，不推事件**（BUG-13）。前端调 `nota_plugin_panels` 拉 |
| `ui.menu` | `UiMenu` | `nota.ui.register_menu` → 同上，落在 `nota_menus`，由 `nota_plugin_menus` 拉 |
| `settings.own` | `SettingsOwn` | 读写插件自己的设置段。⚠️ **宿主侧尚未实现**：同样是一张"尚未实现"表（docs/07 第 13 项） |

放行的形状是**"按能力装表，不装空壳"**（`lua/api/mod.rs` 的铁规矩）：

- 没申请 `document.read`/`document.write` → `nota.document` 整个是 `nil`；
- 只申请了读 → `nota.document` 上**没有** `set_text` 这一格，写不出来也绕不过去；
- ⚠️ `insert_at_cursor` 在**写**那一侧，所以只申请 `document.read` 的插件**发不出编辑意图**；`get_selection` 在**读**那一侧，只申请 `document.write` 的插件**看不见选区**（`docs/13` §15 那张速查表是同一口径）；
- 没申请 `process.git` → `nota.git` 是 `nil`。

**为什么不装"调用时才报没权限"的表**：那既让插件作者在开发期发现不了问题（写到调用时才失败），
也让"权限"退化成一句运行时的声明，而不是一道结构上的约束。

永远可用、不需要任何能力的只有这几项（它们不碰文档也不碰磁盘，是插件跟自己、
跟宿主说话用的）：身份三项 `version` / `api_version` / `plugin_id`，以及四张表
`log` / `command` / `event` / `diff`（最后那张 2026-09-24 加的，是**纯函数**：
一段文本进、一段文本出，见 `docs/13` §11）。

⚠️ **能力申请只写真的用到的**。申请了不用的能力是在扩大攻击面而不换任何功能——
`plugins/git/plugin.toml` 连 `fs.write` 都没申请（它让 git 自己去改工作区），
`plugins/ai/plugin.toml` 的 `network.http` / `settings.own` 两条 2026-09-24 起都**已经实现**了，
申请它们是有用的（这条早先的记录说的"申请了但宿主还没实现"已经不成立）。

## 7. `PluginMeta` / `Manifest` 与校验规则

### 7.1 `PluginMeta`（清单的 `[plugin]` 段）

| 字段 | 类型 | 必填 | 默认 | 校验 |
|---|---|---|---|---|
| `id` | `String` | ✅ | — | 非空；**只能用小写字母、数字、`.`、`-`、`_`** |
| `name` | `String` | ✅ | — | 给人看的名字，不校验 |
| `version` | `String` | | `"0.0.0"` | 插件自己的版本，**不代表 ABI** |
| `api` | `u32` | ✅ | — | **精确匹配** `NOTA_PLUGIN_API_VERSION` |
| `entry` | `String` | | `"main.lua"` | 不许含 `..`，不许是绝对路径 |
| `description` | `String` | | `""` | |
| `authors` | `Vec<String>` | | `[]` | |
| `license` | `String` | | `""` | |
| `capabilities` | `Vec<String>` | | `[]` | 逐个过 `Capability::parse`；**空 = 纯声明式插件**（只贡献菜单/面板，不碰文档与磁盘） |

必填项缺失 = TOML 解析失败 → `NotaError::Manifest`。
⚠️ **`name` / `description` 这两栏可以被插件的语言表改写**（**保留键**，2026-09-27 起是两个）：`lang/<tag>.toml` 里同名的两条分别盖掉清单里的值（`lua/api/i18n.rs` 的 `语言包::名字` / `语言包::描述`，落点是 `plugin/mod.rs` 拼 `PluginInfo` 那两处）。⚠️ **主语言是英语**（用户 2026-09-27 定：「英文才是主语言，中文才是翻译包」）——所以清单里这两行写英语、中文挪进 `lang/zh-CN.toml`。⚠️ **`id` 不在可改写之列**：它是身份，签名、信任表、设置段全按它索引（§7.3 第一条）。口径在 `docs/11` §2.4 ②。

### 7.2 `Manifest`：解析好、校验过的清单

| 字段 | 类型 | 说明 |
|---|---|---|
| `meta` | `PluginMeta` | 原样保留（前端 `PluginInfo.capabilities` 用的就是 `meta.capabilities` 这批**原始字符串**） |
| `dir` | `PathBuf` | 插件根目录（`plugin.toml` 所在处） |
| `capabilities` | `Vec<Capability>` | 解析并**去重**后的能力表 |

`entry_path()` = `dir.join(meta.entry)`；`has(cap)` 是唯一的查询口。

### 7.3 三条校验规则与它们挡的东西

| 规则 | 挡住的攻击/事故 |
|---|---|
| **id 字符集**：`[a-z0-9.\-_]`，非空 | 通道名与依赖引用要能拼得出来；大写/空格/中文在事件名里非法（见 §7.5） |
| **`api` 精确匹配** | 老插件在新宿主上静默拿到别的东西。见 §8 |
| **`entry` 不许逃出插件目录**：含 `..` 或绝对路径即拒 | 清单是**插件自带**的，`entry = "../../../etc/passwd"` 必须在门口挡住 |

⚠️ 这三条都在 `Manifest::from_meta()` 里、**加载期**执行；插件跑起来之后不再复核。

### 7.4 `find_manifests()`：认两种形状

- `<dir>/plugin.toml` —— 找到就**只认它**，不再往下扫；
- 否则扫 `<dir>/*/plugin.toml`（每个子目录一层），结果排序。

第二种是为了开发时少写一层目录。

### 7.5 `channel_id()`：id → 事件通道名

```rust
pub fn channel_id(id: &str) -> String
```

口径：**不在 `[A-Za-z0-9_-]` 里的字符一律换成 `-`**。

**为什么需要它**：Tauri 的**事件名只允许字母数字与 `-` `/` `:` `_`**，而清单里的 id
允许点（`nota.git` 这种反域名风格是主流写法）。漏了这一步的表现是：插件加载"成功"，
但**第一次 `emit` 才抛** `only alphanumeric, '-', '/', ':', '_' permitted for event
names`——静态看代码完全看不出来（`docs/07` BUG-3）。

事件的完整形状是 `plugin:<channel_id>:<名字>`：`plugins/git/main.lua` 里的
`nota.event.emit("git:status", …)` 从 `nota.git` 发出去，实际通道是
`plugin:nota-git:git:status`（名字里自带冒号是合法的——Tauri 允许 `:`）。

⚠️ **归一化有代价**：`.` 与 `-` 在通道名里是同一个字符，所以 `nota.git` 与 `nota-git`
这两个**都合法**的 id 会占同一个通道。撞了事件就分不清是谁发的，所以
`PluginHost::discover()` 直接**把后到的那个判为加载失败**（`LuaPlugin::rejected`），
让失败显式暴露，而不是让它们悄悄混在一起。

⚠️ **`_` 不在被替换的字符里**（`channel_id("a_b-c") == "a_b-c"`，`manifest.rs` 有用例钉着）。
✅ 2026-09-25 更正：`plugin/mod.rs` 的撞名注释**已经不写错了**——它现在明写
「只有 `.` 这一类不合法字符会被换掉，`-` 与 `_` 原样保留」，并留了一句「早期的错误信息写成『`.` 与 `_` 都写作 `-`』，那是错的，2026-09-22 核对用例后改掉」。
`docs/07` BUG-3 那一格是否还留着旧写法，以那一格自己的现状为准。

### 7.6 安装账本与信任表（两个 `.toml`，都在 `config` 下）

插件那一摊有**两个**记账文件，形状不同、回答的问题也不同，别混：

| 文件 | 回答的问题 | 代码 |
|---|---|---|
| `plugins.toml` | **这台机器上**：哪些插件开着、当初装进来时验签验出了什么 | `plugin/installed.rs::Installed` |
| `trusted-keys.toml` | **谁签的算数**：我信任哪几把签名公钥（TOFU） | `plugin/trust.rs::信任库`（2026-09-29 从 `plugin/package.rs` 拆出） |

#### ① `plugins.toml`

```toml
[plugins."nota.git"]
enabled = true
signature = "verified"          # verified / unknown / unsigned
key_id = "a1b2c3d4e5f60718"
public_key = "…base64…"         # 签名者的公钥，给「信任」按钮用
```

⚠️ **只记"用户做过决定"的那些。** 没出现在文件里的插件走
`Installed::没记过时开不开()` 那条默认值——所以这个文件小、可读，而且
**删掉它就等于恢复出厂**（这一点是刻意的，写在 `docs/11` §1.6）。

⚠️ **默认值分两种构建，这是刻意的**：

- **调试构建**：没记过 = **开着**。开发时改完 Lua 存盘就该看到效果，不该还要先去
  面板里打开一次；仓库里新加一个插件也该直接出现在界面上。
- **发布构建**：没记过 = **关着**。用户装应用时不该凭空多出一堆他没要过的东西
  ⇒ 一条干净的发布版装完之后，那四个内置插件**在「拓展」页里列着、但都是关的**，
  用户按需打开（也可以从文件装自己的）。
  ⚠️ **这里 2026-10-09 改过一次**：原文写的是「发布版**连内置插件都不打包**
  （`bundle.resources`），所以装完「插件」页是空的」——**那是句错的**。
  真相是：2026-09-23 修 BUG-11 时给 `tauri.conf.json` 补上了 `bundle.resources`，
  内置插件**照样打进包**（在那之前才是"一个都没有"）；而"没记过 = 关着"管的是
  **启用状态**，两件事被那句话搅在一起了。⚠️ 同一天插件源码搬去了独立仓库
  （`Nota-plugins`），那条 `bundle.resources` 的键跟着改成 `"../../Nota-plugins/plugins"`（键相对 `src-tauri/`）
  ——**要"真的一个都不打包"，删掉那条键**，见 `docs/11` §1.5。

⚠️ `signature` 是 `Option<Signature>`：**老记录里没有这一栏 = `None`**，
**不是 `Unsigned`**——后者会谎称"当初验过，是没签名的"。这一栏
`skip_serializing_if` 掉，所以文件里不出现就是没记过。

⚠️ **`public_key` 也存了一份**，虽然指纹就在旁边那一栏。指纹是
`sha256(公钥)` 的前 8 字节，**反推不回去**，而留公钥是为了「信任」那颗按钮能**事后**点——
装完之后原包文件不在手里了（签名块也不落进安装目录，`包::从文件们` 会摘掉它），
而信任一把钥匙要的是**公钥本身**。

⚠️ 三个字段**一起写**（`来路` 那个结构），不分成三次落盘：它们是"同一件事的
三个侧面"，分三次就会出现"结论记上了、指纹还没记"这种中间态。

#### ② `trusted-keys.toml`

```toml
[keys.a1b2c3d4e5f60718]
name = "某某"
public_key = "…base64…"
added_at = "2026-09-25"
```

形状是 `[keys.<指纹>]`：**指纹是键**，所以"信不信这把"是一次哈希查表。
`name` 只是**给人看的**（记下当时那个插件的名字），信任**按指纹判**。

⚠️ `added_at` **是 UTC 的今天，不是本机的今天**（`package.rs::今天`）。
取 UTC 是为了**不引 `chrono`、也不碰 `unsafe`**（读本机时区要 `localtime_r`）：
一个"给人看的"栏不值得这两样。代价是 UTC+8 的用户在本地凌晨 0 点到 8 点之间
信任一把钥匙，这里会记成前一天——界面不显示它，验签也不读它。
📌 这个栏**2026-09-25 之前一直是空串**（`String::new()`），因为宿主当时没有任何
时间来源；现在填上了，见 `docs/07` 那一轮的记录。

⚠️ **没有"信任任何签名"这一档，而且不得加。** 三种结论里只有
「有签名但验不过」是硬拒（`Err`，见 §7.6① 之上那段），另外两种照装、
只是如实标出来。信任库的作用是让「已验证」这个标签有意义，
不是一道"不给装"的门。

⚠️ **指纹是算出来的**（`公钥指纹(public_key)`），包里那份 `key_id` 只是
"方便人看"——验签时会拿公钥**重算一遍再对比**，对不上就拒。否则改一个
`key_id` 就能冒充别人已经信任的那把钥匙。

⚠️ **坏掉的信任库当空表**（`从文本` 里 `unwrap_or_default`）：它不该让应用打不开。
同理 `plugins.toml` 读不了就当没记过——这条降级是安全的（回到按构建档的默认值）。

### 什么时候该动号

| 改动 | 动不动号 | 为什么 |
|---|---|---|
| 给 `nota.*` 表**增加**成员 | **不动** | 老插件照样跑（它不会去调没见过的东西） |
| **改名**某个 `nota.*` 成员，或**改变它的语义** | **动** | 老插件会静默拿到别的东西 |

`api` 之所以是精确匹配而不是 `>=`，是因为宿主与内置插件**永远同批构建**，
`>=` 只会让"插件作者以为存在一个他没见过的新版本"这种事发生。号一变，
内置插件同批改号，**没有迁移动作**。

## 10. 跨语言形状对应（改一边必须改另一边）

`src/bridge/types.ts`（2026-09-26 之前这些类型在 `ipc.ts` 顶部，那天 `ipc.ts`
涨到 1035 行、顶破硬线，类型整块搬了出去；`ipc.ts` 里一行 `export * from "./types"`
让引用点一处都没改）与 Rust 侧结构体是**手抄的对应关系**，
