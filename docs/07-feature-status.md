## 2. 缺陷清单

编号是**永久的**：修好之后把状态改成 `✅ 已修（日期）`，**不要删行、不要把号让给新条目**
——别处的注释与提交信息会引用这些号。

| 编号 | 状态 | 症状 | 根因与修法 |
|---|---|---|---|
| **BUG-1** | ✅ 已修（2026-09-22） | 插件的 `on_unload()` **从来没有被调用过** | `LuaPlugin::unload()` 从 `globals()` 里读 `__nota_module`，而 `run_entry()` 从来没往那儿写过东西。改成两头都用**命名注册表值** `nota_module`（用注册表而不是全局，是因为插件可以合法地把全局 `nota` 覆盖掉） |
| **BUG-2** | ✅ 已修（2026-09-22） | **没打开文件夹时，Git 插件显示「失败」**，而插件本身一个字都没写错 | `nota.git` 的 `working_dir()` 对"没有工作区也没有活动文档"直接抛 Lua 错误，而 Git 插件的 `on_load()` 结尾要刷一次状态——于是**环境问题被当成了插件故障**。改成：**调用错误**（传 `-C` 之类）抛错，**环境不具备**折成一张 `code != 0` 的结果表（`stderr` 里写原因）。插件侧那一次刷新再包一层 `pcall` |
| **BUG-3** | ✅ 已修（2026-09-22） | 插件**加载"成功"但一发事件就抛错**：`only alphanumeric, '-', '/', ':', '_' permitted for event names` | 清单里的插件 id 允许点（`nota.git`），而 **Tauri 的事件名不认点**。通道名是 `plugin:<id>:<名字>`，于是每一次 `emit` 都失败。加了 `manifest::channel_id()` 做归一化（**`.` 及其它不合法字符 → `-`；`-` 与 `_` 本来就在 Tauri 的允许集合里，原样保留**——⚠️ 本格的早期版本写成"`.`/`_`/其它 → `-`"，那是错的，`channel_id("a_b-c") == "a_b-c"` 有用例钉着），并在 `discover()` 里**检测归一后的撞名**（`nota.git` 与 `nota-git` 会撞，`nota_git` 与 `nota-git` 不会）：撞了就把后到的那个直接判失败，把话说在当面 |
| **BUG-4** | ✅ 已修（2026-09-22） | `Ctrl+W` 关文档时用的是**陈旧的闭包** | `App.tsx` 里 `closeDoc` 定义在快捷键 `useEffect` **之后**，且没进依赖数组，于是快捷键一直抓着首次渲染那一版。把 `closeDoc` 的 `useCallback` 提到 effect 之前并加进依赖 |
| **BUG-5** | ❓ 待查 | **中文输入法（IME）组合态**未实测 | ProseMirror 的 IME 处理是成熟的，但中文输入是 Nota 的主力场景，**这条要专门验一遍**。见 backlog 第 24 项 |
| **BUG-6** | ✅ 已修（2026-09-22） | **切标签时后端的「活动文档」不跟着变**：`TabBar.onSelect` 只 `setActiveId(id)`，**从不调 `api.doc.setActive`**。于是后端的活动文档只被 `new`/`open`/`close` 改过。⚠️ **后果对插件是实的**：用户点了标签 A 在看 A，`nota.document.get_text()` 却返回**最后一次新建/打开的那份**——AI 助手插件按这个路径写回，就会**改错文档** | 前端单方面漏了一枪。后端命令 `nota_doc_set_active` 早就有了，`ipc.ts` 里也声明了 `api.doc.setActive`——只是**没有任何调用者**。**修法（已落地）**：`App.tsx` 里加一个只依赖 `activeId` 的 effect 统一同步，**不补在 `onSelect` 上**——补在那儿只堵住"点标签"一条路，`open` / `new` / `close` 三条路径照样漏。多喊一次无害，后端是幂等的 |
| **BUG-7** | ✅ 已修（2026-09-22） | **`applyTheme` 的退订函数被丢掉**：`App.tsx` 里写的是 `if (settings) applyTheme(settings);`，**没有接返回值**。`ui_mode = "auto"` 时每次 `settings` 变化都会再挂一个 `matchMedia` 监听，旧的**从不移除** | effect 漏了 `return` 清理函数。功能上不致命（`paint()` 幂等），但监听器累积。**修法（已落地）**：`if (settings) return applyTheme(settings);`。⚠️ 顺带一条：`settings` 为 `null`（还没拉到）时**不能**把主题刷成默认值——那会让首屏闪一下再跳回来 |
| **BUG-8** | ✅ 已修（2026-09-22） | **只申请 `ui.menu` 的插件拿不到 `nota.ui`**，调 `register_menu` 直接 `attempt to index a nil value`。`ui.menu` 这条能力**形同虚设** | `lua/api/mod.rs` 的判据写的是 `ui.notify \|\| ui.panel`，**漏了 `ui.menu`**；而 `ui.rs` 表内三个方法又各自判一次。两层判据**相乘** → 只申请 `ui.menu` 的插件连表都拿不到。两个内置插件都申请了 `ui.panel`，所以一直没暴露。**修法（已落地）**：把判据剥成纯函数 `装_ui吗()`，由 `const UI能力: [Capability; 3]` 驱动——**外层判据和 `ui.rs` 里那三处由同一个数组产生，漏一项就不可能悄悄溜过去**。加了 4 条回归用例：每条 `ui.*` 能力单独装表、没申请不装表、**`UI能力` 与 `ui.rs` 里的判据个数对得上**（用 `include_str!` 数 `manifest.has(Capability::Ui` 的出现次数）、以及能力的 serde 名与 `parse()` 同口径。用例数 32 → **36** |
| **BUG-9** | ✅ 已修（2026-09-22） | **每个未命名文档的标题都是「未命名 0」**：新建两份未存盘、且正文还没有标题的文档，标签页上两份**同名** | `derive_title(text, path, untitled_index)` 本身收序号，但**四个生产调用点全部传字面量 `0`**（`document/mod.rs` 第 192/212/228/254 行）；只有用例传了 1/7/3。序号从来没有真的递增过。**修法（已落地）**：序号**在建文档那一刻钉死在 `Document::untitled_index` 上**，之后 `sync`/`settle`/`save`/`reload` 一律读这个字段。⚠️ 不能改成"每次重算标题时问一下计数器"：那样第一份未命名文档在用户打出第一个字之后就会**改名**（`untitled_count` 那时可能已经涨到 3），而用户会看到标签页上的名字自己变了。加 3 条用例：序号不被打字抹掉、装载时的规范化不算改动、空文档不脏 |
