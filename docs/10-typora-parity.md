# 10 · 对标 Typora 的逐项对照矩阵

> 最后同步：2026-09-24
>
> 用户对 Nota 的要求是「**功能 100% 对标 Typora**」。这份文档就是那件事的**唯一权威**：
> 到底对标了哪些、每个处在什么状态、`⬜` 的那些排在哪儿。
>
> ⚠️ **状态列只写实测过的结论**。写「✅」意味着有人真的在界面上点过它、
> 并且它做了该做的事；「🟡」意味着代码在、但要么入口没有、要么只做了一半。
> 拿不准的时候写「❓」并去开窗看一眼，**不要**照着"我们写了这块代码"就填 ✅。

图例：

| 记号 | 意思 |
|---|---|
| ✅ | 实测可用 |
| 🟡 | 部分实现 / 代码在但没有入口 |
| ⬜ | 未开始 |
| ➖ | 刻意不做（附理由） |

> ① 依赖一个用户可能没装的外部程序，会把"导出"变成一件"看环境脸色"的事；
> ② 那等于承认"HTML 由别人生成"，而 HTML 我们**已经有一条和屏幕同源的渲染路径**
> （`editor/export.ts`），再拉一个 Pandoc 进来就是两套渲染实现。
> **所以 PDF / Word / RTF / ePub / LaTeX / ODF / OPML 七项一律 ⬜，这不是"忘了做"**——
> 真要做得先做技术选型（内嵌二进制？要求用户自装？还是走浏览器的"打印成 PDF"？）。
> ⚠️ **PDF 有一条近路**：打印那条链交给系统默认程序之后，用户在那边
> 「打印 → 另存为 PDF」就能拿到 PDF——**但那是系统对话框给的**，不是我们导出的，
> 所以这一格仍然是 ⬜，别拿它当"PDF 已实现"。
> 真要动这一块，先决定：**自带 Pandoc**（重、但保真）还是**自己写导出器**
> （轻、但每种格式都是独立工作量）。这个决定会影响打包体积，**得先拍板**。

## 10. 这份矩阵怎么维护

1. **改了状态就在同一批改这里**（`docs/09` 的映射表把它绑在 `docs/07` 上）。
2. ⚠️ **不要手改 §1 的数字，重跑一遍数出来。** 下面是 §1 那几张计数的生成办法——
   改动 §2–§9 之后跑它，把输出抄进 §1。
   **为什么强调这个**：本表 §1 的第一版是**我估的**，估出 97；实际扫出来是 103，
   而且逐节都对不上（"编辑与格式化"实为 30 行，估成 27）。**估数字就是编数字。**

   ```sh
   python3 - <<'PY'
   import re
   lines=open('docs/10-typora-parity.md').read().split('\n')
   sec=None; counts={}
   for ln in lines:
       m=re.match(r'^## (\d+)\. (.+)$', ln)
       if m: sec=(int(m.group(1)), m.group(2)); counts[sec]={k:0 for k in '✅🟡⬜➖❓'}; continue
       if sec and ln.startswith('|'):
           c=[x.strip() for x in ln.strip('|').split('|')]
           if len(c)>=2 and c[1] in counts[sec]: counts[sec][c[1]]+=1
   tot={k:0 for k in '✅🟡⬜➖❓'}
   for (n,t),c in counts.items():
       if not 2<=n<=9: continue
       for k in tot: tot[k]+=c[k]
       print(f"{t:<22}"+"".join(f"{c[k]:>5}" for k in '✅🟡⬜➖❓')+f"{sum(c.values()):>7}")
   print(f"{'合计':<22}"+"".join(f"{tot[k]:>5}" for k in '✅🟡⬜➖❓')+f"{sum(tot.values()):>7}")
   PY
   ```
3. ⚠️ **不要把"我们写了这块代码"当成 ✅**。判定标准是**有人在界面上点过**。
   填 ❓ 比填错的 ✅ 有用得多。
4. ⚠️ **反方向同样成立：也不要把"没做过"直接填 ⬜，先 `grep` 一下。**
   本表有三格栽在这上面（文件树点击、字数项数、文档主题 CSS）——
   全是按先入判断填的，一查发现代码早就在那儿了。见 `docs/07` §4。

### 12.1 physics 宏包：支持的，和我们做不到的

口径先说三条（完整理由在 `src/editor/math-macros.ts` 的文件头）：

1. 数学渲染走 **KaTeX，而它官方没有 physics**。
2. npm 上那个 `katex-physics`（2019 年）**刻意没引**：npm 元数据与 GitHub 仓库对不上、
   仓库里**没有 LICENSE 文件**。所以这张表是**我们照着 physics 的语义自己写的**
   （`math-macros.ts`，**108 条**，每条配一个可渲染样例）。
3. 开关**默认关**，因为它会**重定义 `\div`、`\Re`、`\Im`**——那是 physics 原版的行为，
   不是我们的 bug。重定义会让"同一个公式在开关两边长得不一样"，
   所以开着才需要用户主动选。

**支持的**（按族列，完整清单**以代码里那张表为准**——它的键就是唯一权威）：

| 族 | 命令 |
|---|---|
| 括号与定界 | `\qty` `\pqty` `\bqty` `\vqty` `\Bqty` `\abs` `\norm` `\eval` `\order` `\comm` `\acomm` `\pb` |
| 导数 | `\dd` `\dv` `\pdv` `\fdv` `\var` `\flatfrac`（⚠️ **2026-09-24 修过一轮，见下**；不带可选阶数） |
| 向量与微积分算子 | `\vb` `\va` `\vu` `\vdot` `\cross` `\grad` `\div` `\curl` `\laplacian` |
| 算子名 | `\tr` `\Tr` `\rank` `\erf` `\pv` `\PV` `\Re` `\Im` |
| Dirac 记号 | `\ket` `\bra` `\braket` `\ip` `\dyad` `\ketbra` `\op` `\expval`（**只一参**） `\mel` |
| 矩阵定界 | `\mqty` `\pmqty` `\bmqty` `\vmqty` `\mdet` `\smqty` 等 |
| 条件文本 | `\qq` `\qc` `\qif` `\qthen` 等 |

⚠️⚠️ **2026-09-24 的更正**：这张表上一版把导数那一族列成绿灯，**那是错的**。
实测 `\dv{f}{x}` 画出来是 `]dxfdfx` 这种垃圾、`\dd` 单独用直接报错、
`a\dd+b` 把加号当参数吃掉——**而且全都不报错、不红字**，所以
"能不能渲染"这个判据永远抓不到。根因是那五条用了 KaTeX **根本不支持**的可选参写法
（详见下面那张表）。**已经改掉**：`\dv{f}{x}` → `df/dx`，`\dd` / `\var` 改回
physics 那样的**零参**。⚠️ 代价是 `\dv[2]{f}{x}`（二阶导）现在**做不到**了。

⚠️ **三条根因（这一版改过一条）**：**参数必须带花括号**、**KaTeX 的宏完全不支持可选参**
（`\renewcommand{\x}[2][]{}` 与 `\def` 风格**都不行**，实测都是红字；上一版写的
"可选参只能用 `\renewcommand` 声明"**是错的，已删**）、**星号不被吃掉**。

**做不到的**（用户会踩，所以先说清）：

| 写法 | 为什么不行 | 改用 |
|---|---|---|
| `\dv[n]{f}{x}` / `\dd[2]{x}` ——**可选阶数** | KaTeX 的宏**不支持可选参**（上面那条根因） | ⚠️ 手写 `\frac{d^{2}f}{dx^{2}}`；`\dd` 就直接写 `\mathrm{d}` 那两个字 |
| `\dd` 后面不写花括号以外的东西（`a\dd b` 这种"喂一个 token"的写法） | 我们这一版把 `\dd` 做成**零参**（和 physics 一致） | 变量写进花括号：`\dd{x}`、`a+\dd{x}` |
| `\expval{A}{\Psi}` / `\ev{A}{\Psi}` / `\mel{n}{A}{m}{\Psi}` 这类**多给一参** | 多出来的那一参会被**静默排到后面**（`⟨A⟩Ψ`）——不报错 | 期望值只支持一参；显式写态用 `\mel{n}{A}{m}` |
| `\dv*{f}{x}` 这类**星号变体** | KaTeX 的字符串宏**不吃星号**：`*` 会留在输出里当正文字符（实测 `\abs*{x}` → `\|*\|x`） | 去掉星号；要"不画 d"的手感用 `\flatfrac`，或直接手写 |
| `\qty(\frac{a}{b})` / `\abs(\frac{a}{b})` / `\comm(A)(B)` / `\mqty(a&b\\c&d)` 这种**拿括号当定界符的写法** | 宏只能按 `{…}` 取参数，**吃不了"配对括号"这一层语法**（前三个会**静默画错**、`\mqty(...)` 才报红） | 统一写 `\qty{…}`（physics 文档里这也是合法写法） |
| `\qty\big{x}` / `\qty\Big` 等**手写尺寸前缀**；以及 `\qty\frac{a}{b}` 这种**参数不写花括号** | 那个 `\big` / `\frac` 会被当成第一个参数（后者直接报红） | `\qty` 自带 `\left…\right`，尺寸是自动的；参数一律带 `{}` |
| `\braket{a\|b}`（**一参**，KaTeX 内建） | 我们的 `\braket` 是**两参**（physics 语义），同名不同元 ⇒ 开着 physics 时一参写法会失败 | 一参那种写 `\Braket{a\|b}`（这个名字我们**没覆盖**，两个方向都实测过） |
| 矩阵生成族 `\dmat` `\admat` `\imat` `\xmat` `\zmat` `\pmat` | 它们要**按参数个数生成一整行**，字符串宏给不了（返回字符串的宏**不会二次展开**） | 老实写 `\mqty{a & b \\ c & d}` |
| `\real` / `\imaginary`、`\grad{}` 那种长写法 | 语义重复（`\Re`/`\Im`、`\grad` 已经覆盖） | 用短名 |
| 三角函数族被 physics 重定义的那些 | ⚠️ **我们没跟**：physics 会把 `\sin` 等换成"自动补括号"的版本，那会让**没开 physics 时写的公式换个开关就变形** | 想加括号自己写 `\sin(x)` |
| `\bra` / `\ket` 的"收缩"行为（某些参数下退化成单竖线） | ⚠️ 未实现；我们的版本用**自动定尺寸**的定界符 | 需要那种效果就手写 |
| 拼错的命令名（`\qtyy{x}`） | 会画成红字，但**没有悬停提示**（只有语法错才有 `title`），参数被吞进同一块红 | 核对命令名；⚠️ 这是**显示上的限制**，要跟用户说清 |

⚠️ **验法（别靠眼看）**：`tools/menu-harness` 的 `#math` 场景把**每一条宏真渲染一遍**——
报的是：宏表条目数、样例表的键是不是同一批、**缺样例的宏**、开着 physics 有没有渲染失败的、
**对照渲染不一致的**（宏写法 vs 手写等价 TeX，比**可见文本**）、关着时哪些命令还能渲染
（说明它不靠这套宏）、`\braket` 两个方向的元数变化、`\Braket{a|b}` 开着也还能用、
`\div`/`\Re`/`\Im` 确实被重定义、`\ce`/`\pu`（mhchem）能用、
坏公式 `x^{` 渲染成错误提示而**不抛**。**加一条宏必须同时加一条样例**，否则那个场景会报缺样例。

⚠️⚠️ **别只加样例**：`PHYSICS_SAMPLES` 只证明"这条宏**不炸**"，证明不了"它**画得对**"——
上面导数那一族就是在这个判据下混过整整一轮的。所以还有个
`PHYSICS_EQUIVALENTS`（对照表，共 15 条）：**宏写法的可见文本必须等于手写等价 TeX 的**。
加新宏时顺手加一条对照，尤其是"展开成好几个 token"的那类。

⚠️ **`\ce` / `\pu` 与 physics 无关**：它们来自 KaTeX 自带的 `contrib/mhchem`，
`math-macros.ts` 里那句 side-effect import 就是干这个的（**别删**）。实测它也不碰 `\div`。

### 12.2 偏好设置的逐页缺口（§11.3 那六格「逐项未抄」的账）

⚠️ **出处与成色**：下面每一行"Typora 有什么"按 Typora 官方 i18n 仓库的
`Base.lproj/Panel.strings`（中文那份在 `zh-Hans.lproj/Panel.strings`）核过一遍；
**官方没有一份"偏好设置全量清单"页**（见 §11.3 末尾那段），所以"某一项归哪一页"
里有一部分是**归纳**，不是逐字有路径佐证——凡官方文档明确写过路径的项单独标了。
**我们这一侧**每一格都有 `文件:行` 证据。

**总览**：Typora 11 页，我们**5 节**（外观 / 文档主题 / 编辑器 / Markdown / 快捷键）。
⚠️ 也就是说 **"页面结构本身"就差 6 节**——而按 `docs/07` 第 45 项那条口径，
**11 节不是照抄 11 个空壳**：每一节得真有东西才开，"点进去是个空页面"比没有这一节更糟。

| # | Typora 的页 | 我们 | 一句话 | 档 |
|---|---|---|---|---|
| 1 | 通用 General | 🟡 部分 | 外观那两条我们**超出**它；但**自动保存是"记着不生效"**（§2.1 第一行） | **P0** |
| 2 | 外观 Appearance | ✅ 超出 | 7 风格 × 2 模式（`settings.rs` 的 `UiStyle`），它只有明暗 + 主题包。只差"深色单独一套文档主题" | P1 |
| 3 | 编辑器 Editor | 🟡 部分 | 能力大多在，**缺的全是开关**（换行、缩进、配对、实时渲染、无选区复制整行） | **P0** |
| 4 | 图像 Image | ⬜ 没有 | 只有一个"问地址"的弹框；**粘贴/拖入图片的地基也没有** | P1 |
| 5 | Markdown | 🟡 部分 | 行内公式与 physics **有**；下标/上标/高亮/警告框/代码块行号**没有** | P1 |
| 6 | 文件 Files | 🟡 部分 | 默认扩展名**写死两份**、最近文件后端 0 命中、拖放开着没人接 | P1 |
| 7 | 导出与导入 | 🟡 部分 | 只有"含/不含样式"两档；**不依赖 Pandoc 的那几条**可做（自定义 CSS / 纸张 / 页边距） | P1 |
| 8 | 快捷键 | ⬜ 只读 | 条目从 `MENUS` 读，**不可改**（第 45 项 (c) 已经把它变成用户诉求） | P1 |
| 9 | 工具栏 | 🟡 部分 | 工具栏**有**，但**不进设置、刷新即复位** | P1 |
| 10 | 高级设置 | ⬜ 没有 | 我们就是一份 TOML（`paths.rs`），照"打开主题文件夹"抄一遍即可 | P1 |
| 11 | 操作系统 | ⬜ 没有 | 恢复上次会话 / 托盘 / 单实例都没有 | P2 |

**⚠️ 绝对不能照做的**（与已定口径冲突 / 版权 / 没意义，逐条有理由）：

| 不照做的 | 为什么 |
|---|---|
| **内置或兼容 Typora 主题**（主题市场那一族） | 版权。用户原话「请不要内置typora主题。会侵权。」；`themes.rs` 顶上写着"一个都不内置"。⚠️ 我们保留的"打开主题文件夹"指的是 `~/.config/nota/themes`，**不是**它的目录 |
| **任何"同 Typora"式的界面文案** | 用户口径（`docs/07` §1）。落地约束：上面每一条新选项的标签与说明都得**自述其作用**，不许拿对标当卖点 |
| **保存时缩进宽度**、**忽略连续空白**、**智能标点**、**标题/列表标记的写法转换** | 与「**不改用户字节**」直接冲突（`strict_markdown` 的"只改显示、不动字节"那条口径）。可接受的形态只有一种：**只重排"我们自己刚生成的那段"，绝不动用户手打的既有文本** |
| **Pandoc 的一切**（路径 / 安装指引 / PDF 引擎 / Markdown 变体 / 导入格式族） | 已拍板：不内嵌不依赖（环境不可控 + 等于承认 HTML 由别人生成，而我们已有屏幕同源的渲染路径）。⚠️ **不含 Pandoc 的导出选项不在这一条的射程内**——那些可以做 |
| **联网与账号类**（匿名统计 / 检查更新 / 激活） | 我们无遥测、无许可证、无自建更新服务器。也不该放一个"我们没实现的"上报开关 |
| **第三方图片上传链**（PicGo / iPic / 按 YAML 自动上传） | 不替用户去下载世界；且把用户所有图片路径交给第三方二进制是**隐私决策**。真要留，唯一可接受形态是**用户自己给一条命令** |
| 窗口样式 Classic/Seamless、Windows 右键"新建"、界面多语言 | 依次是 macOS 专属外观（且与 7 风格重复）、Windows 注册表、已拍板不做 |
| **拼写检查**（半条） | 中文写作里"拼写检查"这个前提本身要重问。⚠️ 顺带记一笔：我们自己的输入框全都写着 `spellCheck={false}` 且**没有注释说明理由** |

**最小可交付**：下一批只做三页——**通用 / 编辑器 / 文件**。判据是同一条：
这三页的条目**几乎全是"接线 / 加开关"**，不动 schema、不需要新存储、不需要新渲染器；
而看起来最像的两页（图像 / Markdown 语法扩展）各自有一条**前置**没做完
（粘贴图片入库 / 行内 schema），单开一批会做出一堆半成品。

⚠️ **怎么验**：后端新字段照 `settings.rs` 现有的用例加三条（默认值 / 落盘名 / 老文件补默认值），
`cargo test --lib`；前端**没有测试运行器**，所以只能 `tsc` + `vite build` 干净（那是"没写坏"，
**不是"能用"**）+ 开窗目检（`docs/06` §5.1）；菜单/勾选/键位进 `tools/menu-harness`。
⚠️ **"自动保存真的写盘了""拖放真的插进去图了"这类只能人点**——
按 §10 第 3 条：✅ 的判据是"有人在界面上点过"。
