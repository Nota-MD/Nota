## 1. 插件放哪

### 1.1 两个落点

| 落点 | 路径 | 谁往这儿放 |
|---|---|---|
| **用户插件目录** | `$XDG_DATA_HOME/nota/plugins`（一般是 `~/.local/share/nota/plugins`） | 用户自己装的。算这个路径的函数是 `paths::user_plugins_dir()`（`src-tauri/src/paths.rs:35-37`） |
| **内置插件目录** | 开发态与打包态**不一样**，见下 | 2026-10-09 起由**另一个仓库**（`Nota-plugins`）提供 |

⚠️⚠️ **2026-10-09：内置插件的源码搬去了独立仓库**——`Nota-plugins`，与主仓库
**同级放着**（工作区里 `Nota/` 与 `Nota-plugins/` 并排）。所以**本文件里凡是写
`plugins/<id>/…` 的地方，指的都是那个仓库里的路径**，不是本仓库的。分工照
`Folio-plugin` / `Vellum-extensions` 那两套的体例，`Nota-plugins/README.md` 里有
那张分工表。

内置目录由 `paths::builtin_plugins_dirs()` 算（`src-tauri/src/paths.rs`），
它返回的是一个**列表**（同名插件**先扫到的算数**）：

| 什么时候 | 返回什么 |
|---|---|
| **debug 构建**（`cfg!(debug_assertions)`） | 设了 **`$NOTA_PLUGINS_DIR` 就只认它**（显式覆盖）；否则 ① **同级仓库** `<主仓库>/../Nota-plugins/plugins` → ② 老落点 `<主仓库>/plugins`（独立之前自带的那份，留着只是让老检出还能跑） |
| **打包后** | `resource_dir/plugins`（由 `tauri.conf.json` 的 `bundle.resources` 拷进去，见 §1.5） |

⚠️ **debug 构建为什么会扫那几档**：`CARGO_MANIFEST_DIR` 是
`src-tauri/`，往上一级是主仓库、再上一级就是工作区（`paths.rs`）。这样做的目的是
**改完 Lua 存盘不用重编 Rust**——插件是脚本，读一次就换了。

⚠️ 但**不用重编 ≠ 不用重启**。插件只在 `setup()` 里加载一次
（`lib.rs` 的 `PluginHost::discover`），所以改完 Lua 要**重启应用**才生效。
`docs/06` §3.5 记了同一件事。

### 1.2 扫描顺序与去重

两个落点**都存在就都扫**（`paths.rs:41-43`），规则是：

```
用户目录 先扫  →  内置目录 后扫
```

去重的键是**清单里的 `id`**，不是目录名——**先到者胜**，
所以"用户装的同名插件覆盖内置的"是这条循环顺序自然的结果，不用额外判
（`plugin/mod.rs::discover()` 里的 `seen` 与 `channels`，⚠️ 别记行号——2026-09-29 拆 `types.rs` 之后它挪过一次）。

⚠️ **为什么按 `id` 而不是按目录名**：目录名是文件系统的事，用户可以随便改；
`id` 是清单里声明的、插件之间互相引用的名字。用目录名去重会出现
"改个文件夹名就多出一份插件"这种事（`plugin/mod.rs:7-11`）。

### 1.3 目录形状：正好一层

`find_manifests()` 认**两种形状**（`plugin/manifest.rs:266-286`）：

```
plugins/<目录>/
├── plugin.toml        # ✔ 形状一：<dir>/plugin.toml
└── main.lua
```

或者：

```
plugins/<外层>/
└── <插件目录>/
    ├── plugin.toml    # ✔ 形状二：<dir>/<id>/plugin.toml
    └── main.lua
```

两种都认，是**为了开发时少写一层**。⚠️ 注意形状一的判断是**短路**的：
如果 `<dir>/plugin.toml` 存在，就**只看它**，不再往里扫子目录
（`manifest.rs:269-272`）。同一个目录里既放 `plugin.toml` 又放插件子目录时，
后者会被静默忽略。

#### 1.3.1 多文件：`require` ✅（2026-09-27 起）

**一个插件不再只有一个 `.lua`。** 插件目录里可以放任意多个 `.lua`，入口脚本用
`require` 拿：

```lua
-- plugins/我的插件/main.lua
local 曲线 = require("chart")          -- <插件目录>/chart.lua
local 色   = require("ui.palette")     -- <插件目录>/ui/palette.lua
local 表   = require("kit")            -- <插件目录>/kit/init.lua 也行
```

名字里的 `.` 就是目录分隔（与 Lua 的惯例一致），两种写法都认：`<名>.lua` 和
`<名>/init.lua`。

⚠️ **模块名必须是 ASCII**（`chart`、`ui.palette` 可以，`图表` 不行）——理由与
变量名同一条（`docs/13` §0.6）：Lua 的 `isalpha` 不认 UTF-8 字节。而且这里的代价
比变量名更大：**报错信息本身会变成乱码**，而报错正是它唯一的用处。

⚠️ **只在本插件自己的目录里找**，用的是与 `nota.fs.*` 完全相同的那把尺
（`fs::resolve_in`：绝对路径拒、`..` 算掉、软链逃逸拒）。下面这些一律当场报错：
`require("/etc/passwd")`、`require("../别的插件/x")`、`require("a..b")`。
**插件之间不能靠 `require` 互相引用**——插件是各自独立的单元，一个插件的目录
不归另一个插件读。

⚠️ 与真 `require` 的其余差别，以及"为什么不把 `package` 一起装回来"，
见 `docs/12` §5.9。这里记住两条就够用：

- **`.so` 永远拿不到**（插件不许有 C 扩展，那是绕过整个沙箱的一条路）；
- **循环 require 报一句人话**，不是把栈撞死。

**什么时候该拆文件**：本仓有一条硬线——任何单个源码文件不得超过 1000 行
（`docs/08`）。在这之前，四个内置插件里有三个长到 997~999 行、顶着那条线，
其中一个**一个字都加不进去**了。现在它们可以按"一块逻辑一个文件"拆开。

⚠️ **五条从第一个真用户身上学到的**（写作统计 2026-09-27 从一份文件拆成四份：
`main.lua` 1000 → **938** 行，旁边 `ticks.lua` 289 ／ `ledger.lua` 170 ／ `long.lua` 172；
⚠️ 2026-10-04 它又长了回来、于是**照同一条判据拆了第五份**：`main.lua` 1055 → **985**
＋ `cards.lua` **141**，详见本节第一条与 `docs/13` §14.4）：
⚠️ **2026-10-07 现数**：`main.lua` **902** ／ `cards.lua` **155**（那天 idle 那一屏也摆成表盘，两处各长了十几行）——上面那句"拆到多少"是那次拆完当时的数，行数**每次都该现量**。

- **先拆"不碰状态"的那一截**。跨文件的状态（谁改了它、什么时候改的）在多文件插件里
  是最难查的一类问题，而纯函数没有藏身处——写作统计拆走的正好是"刻度与数怎么写"
  （`spread` / `three_ticks` / `num_text` …），一行状态都没搬。⚠️ 同一天它又照这条
  拆了两次（`days.txt` 的文件格式、长期那本账的算法），**两次都没遇到新问题**。
  ⚠️ **2026-10-04 拆第五份（`cards.lua`）时，这条判据第一次遇到「要读状态」的一截**：
  那几个函数要读本轮的字数、时长、相位，而 `require` 是**单向**的（子模块反过来引
  `main.lua` 就是一个环）。解法是**一张显式递进去的 `ctx` 表**（`main.lua::card_ctx()`），
  而不是把状态搬进子模块——⚠️ 那张表**只许读**：它要是被写，就成了「藏在参数里的
  状态」，那正是这条判据要躲开的东西。
- ⚠️ **模块级的译文不能等 `nota`**：`nota` 要到 `on_load(nota)` 才到手，而模块是在
  `require` 那一刻求值的（`main.lua` 的顶层）。所以子模块里的 `T` 要先是一个
  "原样返回"的桩，等 `on_load` 里用 `bind_text(T)` 换掉——**别在子模块顶层要求 `nota`**。
- ⚠️ **改完自测脚本也要动**：`tools/` 下那些桩测试跑的是**真 Lua `require`**
  （不是宿主那个沙箱版），所以要自己把插件目录加进 `package.path`，并且注意
  `package.loaded` 的缓存**跨实例**（沙箱里每份插件一份新 Lua，缓存不跨）。
  `docs/06` §5.29b 那段跑法旁边写着这件事。
- ⚠️ **拆出来的每个 `.lua` 都在闸门的扫描面里**（2026-10-09 起这条简单了）：
  以前插件在主仓库、而那几道闸**只扫 `src` 与 `src-tauri/src`**，所以新拆出来的文件
  得**人工补进 `tools/doc-sync-check.sh` 的 `PAIRS`**——写作统计上这个坑**犯过两次**
  （整个目录漏登记、拆出来的两个文件漏登记），教训是"**在'拆'的那一步就补，别回头统一登记**"。
  ✅ 搬去 `Nota-plugins` 之后，那个仓库自己的闸（`tools/check.sh`）是**按目录扫**的
  （`find plugins tools`），所以"漏登记"这一类**在结构上不可能再发生**。
  ⚠️ 但那条教训本身留着：**判据要按目录扫，不要按名单扫**——名单迟早会漏。
- ⚠️ **"没数据就不画"在用户眼里等于"这块没做"**（2026-10-07 一天里为这一条改了两次）：
  写作统计的面板上，「② 小字概览」「④ 本轮那条记录卡」「① 长期那张热力图」原来各写着
  一条"没有就**整块不发**"——逻辑上都说得通（省一次拼字符串、省 182 个格子），可**新装
  的机器打开面板看到的是"一片什么也没有"**，用户的原话是「默认手表界面哦」＋
  「"长期记录"也要默认显示哦」。⇒ 一块**表盘**该有的东西（标题、格子、那个 `0`）得先
  在那儿摆着，数据是**往格子里填**的，不是"有数据才有格子"。
  ⚠️ **代价也一起记着**：那一块每秒重画一次，空着也重画（真嫌费，正确的做法是让前端
  缓存那一格，而不是把块吞掉）。⚠️ 反过来也有边界：**连"能不能画"都做不到时才不发**
  （长期那块在 `long.stats` 拿不到日期时仍然一个块都不发——没有日期轴就没法铺格子）。

### 1.4 ⚠️ 两个插件不能占同一个事件通道

清单里的 `id` 允许 `.`（`nota.git`、`nota.ai` 就是这么写的，反域名风格），
而事件通道名里的 `.` 会被归一成 `-`（`manifest::channel_id()`，`manifest.rs:251-261`）。
于是 `nota.git` 与 `nota-git` 这两个**都合法**的 id 会占同一个通道
`plugin:nota-git:…`。

撞了事件就分不清是谁发的，而且是"多发一条事件"这种最难查的症状，
所以 `discover()` 会**把后到的那个直接判为加载失败**，并在错误信息里说明
（`plugin/mod.rs:88-102`）。插件列表里会出现一行标红，理由写着
「事件通道 `plugin:<归一化的 x>:…` 已被 `<另一个 id>` 占用」。
**换一个 id 即可。**

### 1.5 那四个插件放哪儿（2026-10-09 起：独立仓库）

⚠️⚠️ **源码在 `Nota-plugins` 那个仓库里**（与主仓库同级；见 §1.1 那段）。主仓库
这边只剩"宿主怎么读它们"，三句话：

| | |
|---|---|
| **开发态** | 什么都不用做：debug 构建自动扫同级仓库的 `plugins/`（想指别处就设 `NOTA_PLUGINS_DIR`） |
| **打包态** | 主仓库 `tauri.conf.json` 的 `bundle.resources` 里那条 `{"../../Nota-plugins/plugins": "plugins"}`（⚠️ **键相对 `src-tauri/`**，所以是两级 `..`）——bundler 把整棵目录拷进资源目录，**装出来的包里才有这四个** |
| **要"不自带"** | 把上面那条删掉，装出来的包就一个插件都没有，用户在「设置 → 拓展 → 从文件安装…」里自己装（`Folio-plugin` 那边走的就是这条路）。**换这一档是一行的事** |

⚠️ **那条键的写法有讲究（目录 vs glob），而且必须真拆包验**，完整说明见
`docs/08` §6 第 3 步。**它不影响插件编写。**

⚠️ **别把这条和 §1.6 混了**：这一节说的是"**内置**插件怎么跟着 Nota 的安装包走"
（不需要打包工具、不需要签名，用户也卸不掉）；§1.6 说的是"**第三方**插件怎么从
一个文件装进用户的机器"（要打包、可以签名、装了能卸）。两条路都通到同一个
`plugins/<id>/` 形状上。

### 1.6 ⭐ 装、卸、停用，以及包的签名（2026-09-25 接好）

这一节是**插件分发**那一半的口径。四条约定先摆在前面：

1. **宿主只解包、不打分、不签名。** 打包那半在 `tools/pack-plugin.py`，跑在**作者**
   的机器上；私钥永远不该出现在装了 Nota 的机器上（`package.rs:13-14`）。
2. **签名只证明"没被改过"，不证明"是谁给的"**，所以「验证通过」和「可信」是两件事
   （见下面「三种结论」）。
3. **只有一条硬拒路径**：包里**有**签名但验不过。没签名、或者签名者不认识，都装得进来。
4. **停用 = 真卸载**（2026-09-25 改的语义）。这是本节对插件作者影响最大的一条，
   单独有一小节。

#### 1.6.1 包长什么样

`.nota-plugin` 就是一个 **zip**（后缀是它自己的，内容不是）。里面：

```
<根>/
├── plugin.toml            # ✔ 必须在**根**上，与 §1.3 是同一个文件名
├── main.lua               # 入口，文件名由清单的 entry 决定
├── …                      # 想带什么带什么（图标、模板、更多 lua）
└── nota-signature.toml    # 可选。签名块，见 1.6.4
```

| 限制 | 值 | 为什么 |
|---|---|---|
| 解开后总字节 | 32 MiB | ⚠️ **防 zip 炸弹**：宿主是**先全解到内存里**再验签的，没有上限的话，一个 4 KiB 的包能把进程 OOM 掉 |
| 单个文件 | 16 MiB | 同上 |
| 条目数 | 2048 | 同上（外加"这不是插件包"的早退） |
| 单个路径长度 | 512 字节 | 超长名字本身就是攻击面 |

包内路径的规矩（`package.rs::路径合法吗`，**这是安全函数**）：反斜杠一律当分隔符、
不许绝对路径与盘符、不许 `.` / `..` / 空段。违反的包**当场拒**，理由写明。
⚠️ 它只在**解包时**校验一次，之后一律用归一过的字符串，落盘时不再验第二遍。

#### 1.6.2 签的是什么：**载荷摘要**，不是 zip 字节

这正是"重压一遍包签名还成立"的原因。算法三条，**两份实现必须一字不差**
（`package.rs::包::摘要` 与 `tools/pack-plugin.py::摘要`）：

1. 条目**按路径排序**（zip 里条目顺序是打包工具的自由，不该影响签名）；
2. 每条算成 `路径 UTF-8 字节 + 0x00 + 内容 sha256 的 32 字节`；
3. 把这些拼起来再 sha256 一次，得到 32 字节。

⚠️ **签名块自己不参与摘要**——它要是参与了就成了自指。所以它是"**附加在包上的**"
东西，不是"包里的"东西；装完之后它**不会**落进插件目录
（`package.rs::包::从文件们` 会先把它摘掉）。

⚠️ **两处实现怎么保证没跑偏**：`tools/pack-plugin.py` 里的常量（`清单文件` /
`签名文件` / `包后缀` / 那四条上限）是**照抄** `package.rs` 的，改一边忘了另一边，
症状是"包看着好好的、装的时候说签名对不上"。所以动摘要算法 = **同时动三处**
（`package.rs`、这个文件、`pack-plugin.py`）。

#### 1.6.3 作者侧：`tools/pack-plugin.py`

要 `openssl`（OpenSSL 3 自带 ed25519），不需要别的依赖。

⚠️ **这个脚本 2026-10-09 起在插件仓库里**（`Nota-plugins/tools/pack-plugin.py`，
与那四个插件的源码同一个仓库）——下面的命令**在插件仓库的根目录跑**。签名那三条
口径（谁签、防的是什么、加了什么）不受影响。

```bash
# 1) 造一把签名钥匙（只做一次）。⚠️ 私钥自己收好，别提交进仓库。
python3 tools/pack-plugin.py --new-key ~/nota-签名钥匙.pem

# 2) 打包 + 签名
python3 tools/pack-plugin.py plugins/git --key ~/nota-签名钥匙.pem
#   → 输出 plugins/git-0.1.0.nota-plugin（默认 <id>-<版本>.nota-plugin，可用 -o 改）

# 3) 不签名也打得出来（自己装着试的时候够用，界面上会显示「未签名」）
python3 tools/pack-plugin.py plugins/git

# 4) 收到别人的包，先看看是谁签的、有没有被改过
python3 tools/pack-plugin.py --verify 别人给的.nota-plugin
```

脚本会**跳过**点开头的文件/目录（`.git`、`.DS_Store`）、`__pycache__`、
`node_modules` 与符号链接，并逐条挡住上面那四条上限——这些判据与宿主读的一侧
是同一套。⚠️ 它**只读**清单取 `id` / `version` 来起输出文件名，**不改**清单。

#### 1.6.4 签名块的形状（`nota-signature.toml`）

```toml
[signature]
algorithm  = "ed25519"                    # 只认这一个
key_id     = "f0ff3745c5e0d154"           # = sha256(公钥)[..8] 的十六进制，给人和给查表用
public_key = "…base64…"                   # 32 字节原始公钥（标准字母表，带 = 补位）
signature  = "…base64…"                   # 64 字节签名
signed_at  = "2026-09-25"                 # 只是给人看的，验签不看
```

⚠️ **`key_id` 是算出来的，不是随便起的名字**：宿主验签时会拿包里的公钥**重算**一遍
再对比（`package.rs:237-244`），对不上就拒。不这么做的话，改一栏 `key_id`
就能冒充用户已经信任过的那把钥匙。同理，`plugins.toml` 里存的也是**公钥本身**
（base64）而不是指纹——指纹反推不回去，而「信任」那颗按钮要的是公钥。

#### 1.6.5 三种结论，和「信任」这颗按钮

| 验签结论 | 界面上 | 装得进来吗 | 怎么变成"已验证" |
|---|---|---|---|
| `verified` | 自装 · **已验证** | ✅ | —— |
| `unknown` | 自装 · **未知签名者** | ✅（**这是刻意的**） | 行上那颗「信任」→ 把指纹记进信任库 |
| `unsigned` | 自装 · **未签名** | ✅ | 只能重新签一个包再装 |
| **有签名但验不过** | 装不了 | ❌ **唯一的硬拒** | —— |

**为什么"未知签名者"要给装**：拒掉它等于"任何新作者都发不出插件"。签名在这里要防的
是**被改过**（那个是硬拒），不是"没打过招呼"。装进来、标出来、再问一句要不要信任
——用户刚选完文件那一刻，正是他知道这包从哪儿来的时候。

**TOFU + 显式信任**：信任库是 `$XDG_CONFIG_HOME/nota/trusted-keys.toml`，
用户可读可改（删掉 = 全都回到"未知签名者"）：

```toml
[keys.f0ff3745c5e0d154]
name       = "nota.git"        # 只是注释，验签不看它
public_key = "…base64…"
added_at   = "2026-09-25"      # ⚠️ 填的是 **UTC** 的今天，界面不显示它
```

⚠️ **没有"全局信任任何一个签名"这种选项，也不该加**（`package.rs:452-453`）：
那等于把签名降级成一个校验和，而校验和拦不住任何有心人。

#### 1.6.6 装 / 卸 / 停用，各自意味着什么

| 动作 | 命令行 | 做了什么 | 不可逆？ |
|---|---|---|---|
| **装**（或升级同一个 id） | `nota_plugin_install(path)` | 解包 → 校验清单 → 查事件通道撞名 → **验签** → 解到临时目录 → `rename` 搬到落点 → 记账 → 当场加载 | 升级会覆盖旧版本 |
| **卸** | `nota_plugin_uninstall(id)` | 只对**用户目录**下的插件有效；先 `on_unload`（丢掉 Lua 状态）、再删掉插件目录、再忘掉那笔账 | ⚠️ **是**，插件目录真的没了 |
| **停用** | `nota_plugin_set_enabled(id,false)` | 记进 `plugins.toml`，跑 `on_unload`，**把 Lua 状态整个丢掉** | 重新启用就回来 |
| **启用** | `nota_plugin_set_enabled(id,true)` | 记进 `plugins.toml`，**重新从头加载**（`on_load` 会再跑一次） | —— |

几条必须知道的细节：

- **装的时候顺序是刻意的**：所有会失败的检查都做完，**才**动磁盘。一次失败的安装
  不该留下半个插件目录；⚠️ **装同一个 id 是升级**——旧的先挪开（`.旧-<pid>`）、新的
  就位、最后删旧的，中间任何一步失败都把旧的挪回去。
- **`plugin-settings/<id>.toml` 不动**（AI 插件的 API key 就在那里）：那是**用户的**
  东西，不是插件的一部分。卸载、升级都留着。
- **内置插件卸不掉**（`removable == false`，「卸载」那颗按钮就不出现）。
- ⚠️ **停用过的插件在启动时不会新建 Lua 状态**（`LuaPlugin::disabled`），
  所以它"真的不存在"——这正是「删了拓展那项功能就完全不复存在」那条要求。

#### 1.6.7 ⚠️ 停用 = 真卸载：`on_load` 必须能跑第二次

2026-09-25 之前，停用只是"不再把命令派发过去"，Lua 状态留着；现在停用会
**跑 `on_unload` 并把状态丢掉**，重新启用时**从零加载**。对插件作者的要求：

- **`on_load` 要幂等**：它会在"启用"时被调，**每次启用一次**，不是"应用活着一辈子一次"。
  在 `on_load` 里往文件追加东西、往外部注册什么、`os.execute` 起个进程的——
  重新启用就会再来一遍。要么写成幂等的，要么把副作用挪进 `on_unload` 能收干净的地方。
- **`on_unload` 不再只是退出时那一次**：停用、卸载、窗口关闭都会调它。它能拿到的
  清理时机变多了，这是好事——**该在 `on_unload` 里放的东西现在真的有用了**
  （以前"停用"绕过它，只能等退出）。
- ⚠️ **命令/面板/菜单的注册是跟着 Lua 状态走的**：停用之后那些注册就没了，面板与
  菜单栏会一起消失（前端在启停/装卸之后会**重拉**一遍清单，见 `ui/usePlugins.ts` 的
  「装 / 卸 / 启停之后必须重拉」）。

⚠️ **别把"停用"当"暂停"用**：它现在是"这个功能彻底不在场"，不是"先歇会儿"。
真需要"暂停"语义的插件得自己实现（比如留一个开关变量，而不是靠宿主停用它）。

#### 1.6.8 两个记账文件

| 文件 | 在哪 | 谁写 | 里面是什么 |
|---|---|---|---|
| `plugins.toml` | `$XDG_CONFIG_HOME/nota/plugins.toml` | 宿主（装/卸/启停/信任） | 每个 id 一笔：`enabled`、`signature`、`key_id`、`public_key` |
| `trusted-keys.toml` | 同目录 | 宿主（用户点「信任」） | 指纹 → 公钥。**用户可读可改** |

⚠️ **删掉 `plugins.toml` = 恢复出厂**：debug 构建下插件**默认开**
（`cfg!(debug_assertions)`），发布构建下**默认关**——发布版连内置插件都不打包，
所以"一条干净的 `plugins.toml`"意味着"什么都没有"。这个判据写在
`installed::没记过时开不开()`，改它之前先读那儿上面那段理由。

#### 1.6.9 ⭐ 导出：把一个**已经装着的**插件打回成包（2026-09-27 加）

用户 2026-09-27：「完全没有拓展管理面板。做一个。可以**导入，导出和卸载**拓展」。
**导入**（§1.6.6 的「从文件安装…」）与**卸载**本来就在，缺的只有**导出**
（`src-tauri/src/plugin/export.rs`，323 行）。

**两个用例**：

1. **内置插件卸不掉**（`removable == false`，「卸载」那颗按钮不出现）——想把它拷出去
   改一改、或者只是想看看官方的插件长什么样，**导出是唯一的一条路**；
2. 自己装的插件改过之后要发给别人、或者卸载前留一份备份。

⚠️ **它跟"打包"不是一回事**：`package.rs` 文件头那句「包是只读的」管的是**作者侧的
造包**（`tools/pack-plugin.py`，要拿私钥签名，私钥绝不能进宿主）；这一条做的是
**把磁盘上已经躺着的那份原样收拢**，一个字节都不用签，也不该替作者签。

**⚠️ 包里没有用户的东西**：插件的**设置**（`plugin-settings/<id>.toml`——AI 插件的
API 密钥就在那儿）与**数据**（`plugin-data/<id>/`）**本来就不在插件目录里**
（三个目录各自分开，`paths.rs`），所以它们不会被打进去。⚠️ **这不是靠一份排除名单
做到的**——改这条流程时别把这条性质弄丢：把密钥打进一个要发给别人的包里，
是最坏的一种"顺手"。

**签名：验得过就带上，验不过就摘掉**（三档就是 `导出报告.signature` 那三个值）：

| 情形 | 包里那枚 `nota-signature.toml` | 别人装的时候 |
|---|---|---|
| 载荷还是签的那一份（用户没改过） | `kept` **原样带上** | 照旧「已验证 / 未知签名者」，作者那道防线一点没丢 |
| 用户改过任何一个字节 | `dropped` **必须摘掉** | 带着对不上的签名，在别人机器上走的是**硬拒**那条路（"有签名但验不过"）——收到的人**装不上**，而且报的是"这个包被改过"，看起来像发的人做了手脚 |
| 这插件本来就没签名 | `none` | 未签名的包，谁都能装，界面上也如实那么写 |

⚠️ **宿主不支持"改过之后重新签一遍"**（私钥不在这台机器上，见文件头），所以
"改完还能署名"这件事**做不到**，也不该由宿主替作者做。推论：**导出完那句提示
必须说清签名去了哪儿**（`ui/usePlugins.ts::签名去向说明`），只报一句"导出成功"
是不合格的——`dropped` 那一档只有这句话能告诉用户。

**界面上在哪**：**设置 → 拓展**那一页（`ExtensionsPane.tsx` 的「导出…」，
**内置插件也照给**）。右侧「插件」栏**不管导出**：那一栏是"出问题时第一眼看的
地方"，装 / 导出 / 卸载三件事的完整版在设置那一页，两边用的是 `usePlugins` 的
**同一份数据与同一批动作**（`docs/04` §3.5）。

## 2. `plugin.toml` 逐栏说明

清单整个是**一段** `[plugin]`（解析结构是 `ManifestFile { plugin: PluginMeta }`，
`manifest.rs:129-131`）。缺了这一段，得到的是 TOML/serde 的一句
`missing field \`plugin\``。

### 2.1 逐栏表

| 栏 | 必填？ | 默认值 | 类型 | 校验规则 | 写错了会怎样 |
|---|---|---|---|---|---|
| `id` | **必填** | — | string | 非空；只允许**小写字母、数字、`.`、`-`、`_`** | 空 → 「id 不能为空」；有别的字符 → 「id `X` 只能用小写字母、数字、`.`、`-`、`_`」 |
| `name` | **必填** | — | string | 无 | 缺 → serde 的 `missing field \`name\``（TOML 解析错） |
| `api` | **必填** | — | 整数 | **必须恰好等于宿主那个常量**（当前 `2`，`NOTA_PLUGIN_API_VERSION`） | 不等 → 「插件 `{id}` 需要 API 版本 {要的}，宿主是 {宿主那个}」，**拒载**。见 §4 |
| `langs` | 可选 | `[]`（**空 = 不协商**） | string 数组 | 语言标记（`zh-CN`、`en`…，走 `lang.rs::规范`）；**必须含 `en`** | 缺 `en` → 「``langs`` 里没有 `en`（现在写的是 `["zh-CN"]`）——英语是必须有的兜底……」，**拒载**。一写就参与协商，见 §2.4 |
| `version` | 可选 | `"0.0.0"` | string | 无 | — |
| `entry` | 可选 | `"main.lua"` | string | **插件目录内的相对路径**：不许含 `..`，不许绝对路径 | 违规 → 「entry `X` 必须是插件目录内的相对路径」 |
| `description` | 可选 | `""` | string | 无 | —（⚠️ **这一栏能在语言表里改写**：保留键 `description`，§2.4 ②） |
| `authors` | 可选 | `[]` | string 数组 | 无 | — |
| `license` | 可选 | `""` | string | 无 | — |
| `capabilities` | 可选 | `[]`（**空 = 纯声明式插件**） | string 数组 | 每一项必须是 §3 表里的字面量 | 不认识的值 → 「不认识的能力 `X`（见 docs/11 的能力表）」，**拒载**（见下） |

校验的实现在 `Manifest::from_meta()`（`manifest.rs:320`，一直管到 405）
与 `Capability::parse()`（`manifest.rs:143`）。`langs` 那一段紧接着 id/entry
在 `manifest.rs:374-388`，`[devserver]` 段另有一个 `check_devserver()`
（`manifest.rs:419`），因为它的两条罪状是**越界**而不是"写错了"。
⚠️ 上面这张表只管 `[plugin]` 那一段：**`[devserver]` 与 `[[settings]]` 是两个平级的
顶层段**（写法和校验各见 §2.5 与 `docs/12`），一张 `[plugin]` 表里没有它们的栏位。
⚠️ **`name` / `description` 这两栏是"可以被语言表改写"的**（保留键，§2.4 ②）：清单里写的是**主语言**，也就是**英语**（用户 2026-09-27 定：「英文才是主语言，中文才是翻译包」）——所以 `plugin.toml` 里这两行一律写英语，中文挪进 `lang/zh-CN.toml`（那两行在语言表里就叫 `name` / `description`）。⚠️ **只有这两栏**能这么改写：`id` 是身份（事件通道、命令名、账本全靠它），一个字都不能随语言变。⚠️ 也**没有**要求你把 `T("…")` 里的中文改成英文——插件自己的文案键仍然是作者写下的那句原文（§2.4 ①）。

### 2.2 ⚠️ 四个容易踩的坑

**① 未知能力是"拒载"，不是"忽略"。**
`Capability::parse()` 对认不出的字符串**返回 `Err`**（`manifest.rs:143-160`），
并在清单校验时被折成 `NotaError::Manifest`。理由写在函数注释里：
**悄悄忽略会变成"插件作者以为申请到了、实际没有"的静默降级**——
那类 bug 要等插件跑起来、在某个具体功能上表现异常才发现。

**② 字段名拼错是"静默忽略"，不报错。**
`PluginMeta` 上**没有** `#[serde(deny_unknown_fields)]`，所以
`capabilites = [...]`（少一个 `i`）这种拼写错误**会被 serde 直接丢掉**，
插件变成一个**没有任何能力**的插件。症状是运行期 `nota.fs` 是 `nil`
（`attempt to index a nil value`），而不是加载失败。
⚠️ 这是本节排查代价最高的一条：**加载成功不等于清单读对了**。

**③ 能力重复会被去重，不报错。**
`from_meta()` 里 `if !capabilities.contains(&cap)` 才 push（`manifest.rs:369-371`），
所以写两遍同一个能力不会报错，也没有任何提示。

**④ `langs` 缺 `en` 是"拒载"，但它不检查 `lang/` 下的文件。**
见 §2.4——这条容易反着理解。

看真实写法直接读文件，这里只指出几处**刻意的设计**：

### 2.4 ⭐ `langs`：插件界面的语言协商与文案表（2026-09-25 定）

> 代码在 `lua/api/i18n.rs`（插件侧那个 `nota.i18n` 表）与 `src/lang.rs`
> （"什么算一种合法语言"的唯一权威）。这一节的规矩两边同一套。

**要什么**：`[plugin]` 表里写一行 `langs = ["zh-CN", "en"]`，然后在**插件目录**下
放 `lang/<tag>.toml`，一种语言一份。不写 `langs` 的插件**完全不参与协商**，
也不显示那句提示——它是"只说自己写死的那一种语言"的插件，宿主不去猜。

**① 键就是原文。** 译文表是**一张平表**，键是插件作者自己写下的那句原文：

```toml
# plugins/git/lang/zh-CN.toml
# ⚠️ 下面这两行是**保留键**（②），而且通常**不必写**——清单里那两栏本来就写英语；
#    只有要换一种英语说法时才写。
name        = "Git"                    # 保留键：这个语言下插件叫什么名字（改不了 id）
description = "查看改动、比对差异、提交。"  # 保留键：列表里那一行小字（同上）
"Refresh"   = "刷新"
"Commit"    = "提交"
```

⚠️ **2026-09-28 起主语言是英语**，所以内置那四个插件的原文写英语、译文进
`lang/zh-CN.toml`（就是上面这份的样子）；`lang/en.toml` 不再写了（英语是原文，
那份表只是把 `main.lua` 里的字抄一遍）。

Lua 那边取：

```lua
local function T(s) return nota.i18n.text(s) or s end
nota.ui.notify(T("Committed"))
```

`text()` 取不到就返回 `nil`，所以 `or s` 这个兜底是**标准写法**。
推论：译文表里**只需要写要翻译的那些键**，不需要跟原文一一对应；
作者母语那份表几乎是空的。这条规矩的好处是**插件代码里没有键名**，
读完 `main.lua` 就等于读完了文案表。
⚠️ **② 两个保留键：`name` 与 `description`**（`description` 是 2026-09-27 加的，实现在 `lua/api/i18n.rs` 的 `语言包::名字` / `语言包::描述`）。它们**不是插件自己的文案**，是"宿主认得的"两栏，分别**盖掉清单里的 `name` / `description`**（插件栏的页签名、插件列表里那一行小字）。三条规矩：

- **主语言是英语**（用户 2026-09-27 定：「英文才是主语言，中文才是翻译包」）——清单里那两行一律写英语，**中文挪进 `lang/zh-CN.toml`**；
- 于是**英语表通常不必写这两条**（它和清单同值），要写的多半是别的语言那份；
- ⚠️ **只有这两栏**能被语言表改写：`id` 是身份，一个字都不能随语言变；⚠️ 也**没有**要求你把 `T("…")` 里的中文改成英文——**插件自己的文案键仍然是作者写下的那句原文**（汉语插件就是汉语原文），"英语是主语言"这条落在清单那两行和"必须含 `en`"上，不落在你自己那些键上。

⚠️ **一类例外：原文不在 `T("…")` 里的时候**（2026-09-26 补）。上面那句
「读完 `main.lua` 就等于读完了文案表」有一个**已知的例外**：`plugins/ai` 的预设名
写成 `label = "润色"` 存在一张**模块级常量**里，到画面板 / 注册菜单时才
`T(PRESETS[id].label)` 现取。它**只能**这么写——模块级求值时 `nota` 还没到手
（`T` 还是占位符，见上面那个 `local function T` 的写法），写成 `T("润色")`
等于把**没翻**的原文存进表里。代价是 `tools/i18n-check.sh` 光看 `T("…")`
认不出这几条键，会把它们判成「代码里找不到这句原文」的**废键**而报 FAIL，
所以那道闸**额外认一种写法**：插件 Lua 里 `label = "…"` 的字面量也算键。
⚠️ **别为了迁就闸门把这种写法掰成 `T("…")`**——那样坏的是插件本身。
反过来，你要用别的键名做同一件事，得先去那道闸里补一条，否则它会冲你报 FAIL。

⚠️ **两族表，别混**（2026-09-27 补）：上面这一套讲的是**插件自己的** `lang/<tag>.toml`。
**应用自己**的中文表在 `src/i18n/zh*.ts`（**四份**：`zh.ts` 汇总 ＋ `zh-ui.ts` 界面骨架 ＋
`zh-settings.ts` 偏好设置 ＋ `zh-runtime.ts` 钩子与报错；⚠️ 2026-09-28 翻转之前这几份
是**英文**表 `en*.ts`，英语那时是译文），那是**宿主内部的事**——
插件作者**一个键都不该往那里加**，也拿不到它（`text()` 只查你自己目录下那张表）。
⚠️ 分辨办法很简单：**要翻译的字在 `main.lua` 里 → 你的表；在 Tauri 的 `.rs` 或
前端的 `.tsx` 里 → 宿主的表**。两边共用同一套语言标签（`lang.rs::支持的语言`）、
同一个匹配规则（`匹配`）、同一个兜底语言（`en`），所以**书写规矩看上去一样**，
但**文件在哪、谁维护**完全不同。⚠️ 宿主那几份表的键数是会变的（2026-10-04
`bash tools/i18n-check.sh` 报**界面 1008 条键 ／ 中文表 999 条**，那 9 条差是**故意留着的**
——`Markdown` / `LaTeX…` / `PDF…` 这些是产品名与格式名，中文界面上显示英文原文才对，
见那道闸自己打出来的"不算错，是欠账"；2026-09-27 那次是 857 / 857、2026-09-26 是 732 / 732），
插件的键数只看你自己那张表。

**② `ok` 只看清单，不看文件。** `nota.i18n` 给你四个成员：

| 成员 | 是什么 |
|---|---|
| `app_lang` | 应用现在的语言（`"zh-CN"` / `"en"`） |
| `lang` | 按协商结果给你用的那个语言；**没声明 `langs` 时是 `nil`** |
| `ok` | 应用语言是否在 `langs` 里。`false` → 宿主会在插件条目上挂「此插件不支持您的语言」 |
| `text(s)` | 查表；查不到返回 `nil` |

⚠️ **`ok` 是"清单里有这个语言吗"，不是"`lang/` 下有这个文件吗"。**
声明了 `zh-CN` 却没放 `lang/zh-CN.toml`，`ok` **照样是 `true`**——
文件缺失只是让 `text()` 一路返回 `nil`（退回原文），**不会**把 `ok` 翻成 `false`。
理由：`ok` 是"要不要跟用户说这句话"的开关，而"这个插件根本没做过中文"
和"做过但文件损坏了"是两件事，后者该在日志里说（只在调试模式下打印），
不该在界面上把话说过头。

**③ 匹配规则（`lang.rs::匹配`）：先精确，再只往粗的匹配。**
应用语言 `zh-CN` 能匹配插件的 `zh`，**反过来不行**（插件声明 `zh-CN`、
应用是 `zh` 时匹配不上，退回 `en`）。所以**声明得比应用语言更细是安全的，
更粗才有风险**。`zh_CN.UTF-8` 这种写法会先被 `lang.rs::规范` 归一成 `zh-CN`。

**④ `en` 是强制的，缺了就拒载。** 不是"自动补一个 `en`"——补的话插件作者
永远不知道自己漏了兜底语言，而用户会在某个语言下看到一片 `nil`。
**兜底语言就是英语**（用户 2026-09-25 定的）。

> ⚠️ **别把这条兜底与应用自己那条混一起（2026-09-26 拆开的）。**
> `lang.rs` 里现在有**两个**兜底常量：`插件兜底` = `en`（就是本节这条，
> **对插件作者的要求**）与 `应用兜底`（**应用自己**的落点：设置里「跟系统走」
> 而系统语言认不出来、或用户写了个应用没有的语言时，界面落到哪一门）。
> 拆开之前两者共用一个 `兜底 = "en"`，于是中文用户会看到
> **英文外壳配中文插件文案**（用户 2026-09-26 报的「界面中英混杂」）。
> 所以：**插件侧看到的兜底永远是 `en`**（这一节讲的全对，跟 `应用兜底` 怎么变都无关）。
> ⚠️ 但**应用界面那一边同一天里变过一次**，写在这里是为了"看见两个 `en` 别以为
> 它们是同一个东西"：`应用兜底` 上午先改成 `zh-CN`（那时英文表只覆盖插件那一面，
> 落到 `en` 会把界面切成两半），下午英文表铺到整个界面之后，**又按常量注释里写下的
> 条件翻回 `en`**。所以今天**两边同值**，但它们是两个概念、两个常量——`应用兜底`
> 哪天再动，**与你的插件无关**，这一节讲的一条都不会变。
> 📌 2026-09-28 补：前端语言那天整个翻了（**英语成了原文**，中文成了翻译包），
> `应用兜底` 仍是 `en`，而且**它那个前提条件（"英语表覆盖齐了"）不再需要看**——
> 英语是原文，完整性由构造保证。你的插件这边**一个字都不用改**。

> ⚠️⚠️ **这句话什么时候真会出现（2026-09-26 在无头窗口里验过，别照直觉推）**：
> 插件**必须**含 `en`，而应用语言眼下就两种（`zh-CN` / `en`）——所以**应用语言是
> `en` 时，「此插件不支持您的语言」这句话不可能出现**。但**反过来很容易出现**：
> 一枚只声明 `langs = ["en"]` 的插件（**这是合法的**，`en` 在里面）碰上应用语言
> `zh-CN`，`ok` 就是 `false`。实测（临时探针插件、应用语言 zh-CN）：插件栏那一行
> 显示英文名 `Language probe` ＋ **「此插件不支持您的语言」** ＋ 一枚「英语」小标签，
> 而宿主自己的字（`自装` / `禁用` / `卸载`）仍是中文。⚠️ **「只写英语的插件 ＋ 中文
> 用户」正是这句话要服务的主场景**，不是边角料——`en` 是强制的，所以「只写英语」
> 是常态。
> ⚠️ 这里原来写的是**「要让那句提示真能出现，应用得先支持第三种语言」，那句是错的**
> （把「`en` 时不会出现」错推成了「眼下不会出现」），2026-09-26 改掉。
> **唯一真取不到的**是这句话自己的**英文译文**（应用语言是 `en` 时它压根不出现），
> 留着是为了第三种语言进来的那天。

**⑤ 插件永远拿不到路径。** `nota.i18n.text()` 只收**键**；
`lang/<tag>.toml` 的完整路径由宿主用**插件自己的目录**拼出来。
没有"插件指定去哪读文件"这个口子——和 `[devserver]` 的 `entry` 是同一条纪律。

**⑥ 改语言要重启。** 应用语言在 `lib.rs` 里算一次；插件的表是在 `on_load` 里读的。
界面能感知（前端跟着 `nota_app_lang` 走），但**插件那半要重启才生效**。
这是现状，不是设计目标（见 `docs/07` 的欠账一节）。

### 2.5 ⭐ `[[settings]]`：请宿主画一格设置（2026-10-04 定）

> **写作统计是第一个用户。** 用户 2026-10-04 要的是一根滑杆：「统计某一个德尔塔 t 内的
> 打字数量。这个德尔塔 t 可以在**拓展的设置页面**更改，默认为 5 秒。应该是一个托条，
> 从 1 秒到 1 分钟可选。」——于是宿主第一次有了"**替插件画一格设置**"这件事。
>
> ⚠️ **2026-10-10：从一种控件加到三种（`range` / `text` / `toggle`）。** 第二个用户是
> AI 助手，用户那句是「**API等设置专门放一个窗口**」——它那五格设置（接口地址、模型名、
> 密钥、可读上限、边生成边显示）从前挤在自己面板的最下面，那天整块搬到了这一页上。
> 那五格里有两种不是滑杆：地址与模型是**文本**，密钥是**文本 ＋ 遮屏**，开关是**开关**。

#### 形状

顶层数组，与 `[devserver]` **平级**（不是 `[plugin]` 里面）：

```toml
[[settings]]
key     = "base_url"          # 必填。存进设置文件时用的键
kind    = "text"              # range（滑杆，默认）／ text（文本）／ toggle（开关）
label   = "Endpoint URL"      # 必填。给人看的名字（**写英语**，见下）
help    = "An OpenAI-compatible URL …"   # 可选。名字下面那句小字
placeholder = "https://…"     # text：输入框里那句灰字（要翻译）
secret      = true            # text：画成密码框（只管显示，不改存储）
default_text = "gpt-4o-mini"  # text：用户还没填过时框里显示什么

[[settings]]
key        = "stream"
kind       = "toggle"
label      = "Show answers as they are written"
default_on = true             # toggle：不写就是关

[[settings]]
key     = "window_seconds"   # 必填。存进设置文件时用的键
kind    = "range"            # 可选，默认就是它
label   = "Speed window"     # 必填。给人看的名字（**写英语**，见下）
help    = "How many seconds …"  # 可选。名字下面那句小字
min     = 1                  # range 必填
max     = 60                 # range 必填
default = 5                  # range 必填
step    = 1                  # 可选，默认 1
unit    = "s"                # 可选，读数后面跟的那个单位
```

| 栏 | 必填？ | 默认值 | 校验规则 | 写错了会怎样 |
|---|---|---|---|---|
| `key` | **必填** | — | 非空；只允许 **ASCII 字母、数字、`-`、`_`**（**不许有点**，见下） | 空 → 「key 不能为空」；有点或怪字符 → 「key `X` 不合法……」；**同一条重复** → 「有两格用同一个 key」 |
| `kind` | 可选 | `"range"` | 认得出才行：`range`（滑杆）／`text`（文本）／`toggle`（开关） | 别的值 → 「kind `X` 认不出：只有 `range`（滑杆）、`text`（文本）与 `toggle`（开关）三种……」 |
| `label` | **必填** | — | 去空白后非空 | 空 → 「`[[settings]] X` 没写 label」 |
| `help` | 可选 | `""` | 无 | — |
| `min` / `max` / `default` | **只有 `range`** | — | 三个都要有、都是有限数、`min < max`、`default` 落在区间里 | 缺一个 → 「……min / max / default 三个都要给（少了范围或者默认值的滑杆画不出来）」；出界或颠倒各有各的话。⚠️ 写在别的档位上 → 「是 `text`，不该写 `min / max / default / step`（那是 `range` 的）」 |
| `step` | 可选（`range`） | `1` | 在 `(0, max-min]` 之间 | 违规 → 「step (X) 不合法：要在 0 与 N 之间」 |
| `unit` | 可选（`range`） | `""` | 无 | —（⚠️ **不进 i18n**：`s` / `%` / `px` 两门语言写出来一个样）。⚠️ `text` / `toggle` 上写它**报错**：那两档没有读数 |
| `placeholder` | 可选（`text`） | `""` | 无 | —（⚠️ **要翻译**：它是一句话，与 `unit` 那条不同） |
| `secret` | 可选（`text`） | `false` | 布尔 | —。⚠️ **只管显示**（`type = "password"`）：那份设置文件还是明文的 |
| `default_text` | 可选（`text`） | `""` | 无 | — |
| `default_on` | 可选（`toggle`） | `false` | 布尔 | — |

校验在 `plugin/settings_decl.rs::check_settings()`（2026-10-04 从 `manifest.rs` 拆出，
理由见那份文件头）。**六条罪状，每条都是"能挡在门口的就别留到运行时"**（与
`check_devserver` 同源）——写错了就该当场说，而不是等用户去拖一根不会动的滑杆。
⚠️ 第 ④ 条（2026-10-10 加）是**档位与字段对不上**：`toggle` 上写着 `min = 1` 是很自然
的一种笔误（从上面那格复制下来忘了删），而它的后果是那个字段**一声不响地不生效**。

#### ⚠️ 三条硬规矩

**① 写了 `[[settings]]` 就**必须**申请 `settings.own`。**
宿主画的那一格的**值写的就是插件自己那份设置文件**（`plugin-settings/<id>.toml`）——
没申请却让宿主从旁边去写，等于绕过能力表开了一个口子。缺了直接**拒载**。
⚠️ **反方向不报**：只有 `settings.own`、什么设置都不声明的插件（AI 那种，
设置界面它自己在面板里画）是**正常**的，见下面那张分工表。

**② `key` 里不许有点。**
规则与 `lua/api/settings.rs` 那条**一字不差**：点号会让 TOML 把
`a.b = 1` 读成一个**嵌套的表** `[a] b = 1`，而设置文件那一侧是按"平铺的键"读的——
症状是这个键**永远读不出来**，而配置文件看着完全正常。

**③ `label` / `help` 写英语原文，译文进插件自己的语言表。**
和 `name` / `description` 同一条规矩（§2.4 ②）：宿主拿清单里那句原文去
`lang/<tag>.toml` 里查，**查不到就照原文显示**。所以中文用户要看到中文，
就得在那个文件里加一行 `"Speed window" = "速度窗口"`——**键就是清单里这句原文**。

#### 值存在哪、谁写、谁读

| | 界面谁画 | 值存在哪儿 | 谁写进去 |
|---|---|---|---|
| 有 `[[settings]]` | **宿主**（`设置 → 拓展`那一页） | 插件设置文件 | 用户拖滑杆 / 敲文本框 / 拨开关 → 宿主的 `nota_plugin_setting_set` |
| 只有 `settings.own` | 插件自己（面板里那套） | **同一个文件** | 插件的 `nota.settings.set` |

- 文件：`~/.config/nota/plugin-settings/<插件 id>.toml`，纯文本，目录 `0700` / 文件 `0600`。
- 插件**读**这一格：`nota.settings.get("window_seconds")`（见 `docs/13` 的设置那两节）。
- 两种同时用**不冲突**：文件是同一个，键各是各的。
- ⚠️ **默认值两边都有一份**（清单里的 `default` 与插件里那个常量）：清单那份是给界面
  画的，插件那份是"文件被手改坏了"时的兜底。**两份要一致**——不一致的表现是
  「滑杆能拖到 60，而插件按 20 算」，界面上完全看不出来。
- ⚠️ **值可能被手改**：用户可以拿编辑器直接改那个文件。宿主画滑杆时会把值
  **夹进 `[min,max]` 并按 `step` 对齐**（`SettingDecl::夹紧`），插件那一侧**还要自己再夹一次**
  （它不能假设宿主一定先跑过，同一条口径的完整说明在 `lua/api/settings.rs`）。

#### 加一种新控件要动哪儿

⚠️ **2026-10-10 走过一遍这条路**（`range` → 加上 `text` / `toggle`），下面是那次
实际动过的六处——**再加第四种时照这条清单走，一处都不能漏**。认不出的 `kind` 是
**报错**不是降级。

1. `plugin/settings_decl.rs` —— `SettingDecl` 加字段、`check_settings` 加那一档的判据
   （**连同"别的档位不该写这个字段"那一条**）、`求值` / `收值` 两个 match 各加一条；
2. `plugin/types.rs` —— `PluginSetting` 那个"发给前端的形状"跟着加
   （⚠️ 形状是**平铺**的，用不上的字段填默认值：IPC 两边那份类型就不必写成联合类型）；
3. `plugin/mod.rs::设置格` —— 把新字段填进去（**值怎么读回来**就在那儿，`求值` 里）；
4. `src/bridge/types.ts` 的 `PluginSetting` —— 前端要认得出这个 `kind`；
5. `src/ui/settings/panes/ExtensionsPane.tsx` —— **按 `kind` 分派**画哪个控件
   （那里现在是一个三岔的 `s.kind === …`，注释里标着这一处）；
6. 本节这张表 ＋ `docs/13` 设置那一节。

⚠️ 前端**不许**出现 `if (p.id === "nota.stats")` 这类按插件 id 的特判：这一页画的是
**清单声明的形状**，不是某几个插件的表。

## 3. ⭐ 能力表

> **本节是代码注释里引用的那张"`docs/11` 能力表"。**
> `Capability::parse()` 报错时会说「不认识的能力 `X`（见 docs/11 的能力表）」
> （`manifest.rs:159`）——指的就是这里。

### 3.1 先看清楚：能力只管一件事

⚠️ **能力申请的粒度是"装不装某张子表 / 某个函数"，不是"能不能调用"。**
没申请的能力，那个子表**根本不存在**——不是"存在但调用时报错"。
设计口径写在 `lua/api/mod.rs:3-10`：不装空壳，因为空壳既让插件作者在开发期
发现不了问题（写完才失败），也让"权限"变成运行时的检查而不是结构上的隔离。

### 3.2 每个能力值开放了什么

> 📌 **口径**：这一列说的是**宿主 API 的可见性**——"申请了它，可以调到哪些 `nota.*` 成员"。
> 它**不**等于"插件没有能力做别的"；那件事由 Lua 那边收得多紧决定。
> 2026-09-22 起标准库已收紧到只剩 `coroutine`/`table`/`string`/`utf8`/`math`
> （`io`/`os`/`package`/`require`/`loadfile`/`dofile`/`debug` 全为 `nil`，
> 见 `docs/12` §5 与 `docs/07` BUG-10），**所以现在这两句话可以一起读：
> 申请不到的能力，插件确实没有别的路去做。**


| `capabilities` 里的字面量 | 开放 `nota.*` 的哪些成员 | **授予它 = 信任插件做这些** |
|---|---|---|
| `document.read` | `nota.document.get_text()` / `.get_path()` / `.get_title()` / `.get_revision()` / `.is_dirty()` / **`.get_selection()`**（`lua/api/document.rs`） | **读**当前活动文档的全文、磁盘路径、标题、版本号、脏标记、**用户当前选中的那段字**。⚠️ **"当前活动文档"是后端的活动文档**，可能与用户当前查看的那份不一致（`docs/07` BUG-6）。⚠️ `get_selection()` 给的是 `{ text, empty }`（或 `nil` ＝ 不知道），**不是偏移量**——理由见下一格 |
| `document.write` | `nota.document.set_text(text)` / `.append_text(tail)` ／ **`.insert_at_cursor(text)`**（`lua/api/document.rs`） | `set_text` / `append_text` 是**整篇替换**活动文档的文本（写完发事件让前端换掉编辑器内容）。⚠️ **`.insert_at_cursor(text)` 不一样**（第 14 项，2026-10-04）：它**一个字节的镜像都不改**，只发一条编辑意图让编辑器落一笔**真 ProseMirror 事务**——撤销栈、光标、滚动位置都活着，所以"在光标处插一句"该用它，不该拿全文自己拼。⚠️⚠️ **插件永远拿不到光标偏移量，这是量出来的、不是没做**：Markdown 字符偏移在块边界上不存在（`docs/05` §5.2b 那张表），给了就一定会被拿去拼错 |
| `fs.read` | `nota.fs.read(path)` / `.exists(path)` / `.list(path)`（`lua/api/fs.rs:30-72`） | 读**工作区围栏内**的文件与目录名。⚠️ 围栏的裁决在 `resolve_in()`：只收相对路径、`..` 在碰文件系统之前就算掉、符号链接逃逸会拒、**没开工作区时一律拒绝**——详见 `docs/13` |
| `fs.write` | `nota.fs.write(path, text)` / `.remove(path)`（`lua/api/fs.rs:74-98`） | **在工作区内新建/覆盖/删除文件**（写会自动建父目录）。⚠️ 这是**破坏性**的：`remove` 删的是真文件，没有回收站 |
| `process.git` | `nota.git.run(argv)` / `.status()` / `.diff(staged)` / `.repo_root()`（`lua/api/git.rs:55-137`） | **起 `git` 这一个子进程**，工作目录锁死在围栏内，并拒绝 `-C` / `--git-dir` / `--work-tree` / `--namespace`。⚠️ **已知边界（不是漏洞，是记录）**：`git config --global` 这类会写用户全局配置的子命令挡不住——参数层面分不清它跟合法的 `git config --get`。所以这个能力等于"**能对本机做 git 能做的事**"，装插件时该按这个尺度信任（`git.rs:25-27`）。⚠️ 它不是通用 subprocess，**增加别的进程之前需要先读这段** |
| `process.devserver` | `nota.devserver.probe/start/status/open_in_browser/log/stop`（`lua/api/devserver.rs`） | **起清单里 `[devserver]` 段声明的那一条命令**（`cmd` / `args` / `entry` / `probe_args` / `project_marker`…），并把它 `http://localhost:<port>` 嵌进面板的 `frame` 块。⚠️ 与 `process.git` 同一条判据：放行的是**那一条命令**，不是"任意命令"——`nota.devserver.start` **只收"哪份文档"**，交不出第二个程序名来。⚠️ `start` 是**阻塞**的（最长 180 s，等端口起来），**不许在 `on_load` 里调**。⚠️ `probe` 有**两个档**：`probe{}` **不等**（有结论就回，没有就回一张 `state = "checking"` 并在后台探，探完宿主发事件叫前端重拉），`probe{force=true}` **才等**（最多 20 s）——⚠️ **面板的 `render` 里只能用不等那一路**，不然那一页要等 1.3 s（最坏 20 s）才画得出来（`docs/07` BUG-36）。⚠️ `state` 一共**四个**词（`ready` / `missing` / `unknown` / `checking`），最后一档**不是结论**——细节见 `docs/13` §13.3a；⚠️ 插件自己那侧还能多出**第五档 `notheme`**（2026-09-26 补），它不是宿主给的，是插件拿下面那个 `need` 判出来的。⚠️ `probe` 还收一个**可选** `probe{need = "node_modules/@slidev/theme-default"}`：问的是"**这份文档还缺什么**"，宿主拿文档的绝对路径**连同各层父目录**去找那个相对路径（插件自己办不到——`nota.fs` 只认工作区内的相对路径，`resolve_in` 拒绝对路径）。⚠️ 回话在 `need_found` 里，**三档**（没问 `nil` / 有 / 没有），别当布尔用——§13.3b。判据是"**宿主只回答有没有，不解释那是什么**"：`notheme` 这个词、那句"装一个就行"，全是插件写的⚠️ 一个插件**同时只有一个**开发服务器会话。⚠️ 申请了它却没有 `[devserver]` 段 = 能力空转，**加载时就报错**（`manifest.rs:419` `check_devserver`）。⚠️ 它是给"删掉插件这项功能就彻底不存在"的那类重功能准备的（`plugins/slidev` 就是第一个用户） |
| `ui.open_url` | `nota.ui.open_url(url)`（`lua/api/ui.rs:101-148`） | **把用户的系统浏览器打开到某个地址**——⚠️ **这是唯一一个"插件能让用户跳出 Nota"的口子**，所以边界卡在**协议**上：**只认 `https://`**，别的 scheme 一律拒（`file:` / 自定义 scheme 等于把用户送到别处）。用途是"去官网看文档"——⚠️ **`plugins/slidev` 用它去的是安装指南**（`https://sli.dev/guide/`，只在探测说"这台机器跑不起来"那两档的按钮组里出现），**不是**"用浏览器打开预览"：那条走 `nota.devserver.open_in_browser`（两道闸的判据之别见 `docs/13` §13.4）。要在 Nota 里说话仍然走 `nota.ui.notify` |
| `network.http` | `nota.http.request(spec)` / `.get(url或表)` / `.post(url或表)` / **`.stream(spec, on_chunk)`**（`lua/api/http.rs`） | 声明了它等于信任插件**把文档内容发到任意地址**——这是整张表里最重的一条。**两道围栏**：`https://` 随便，`http://` **只放行回环**（本机大模型服务用）；响应体 2 MiB、请求体 1 MiB 封顶。⚠️ **它是阻塞的**（跑在 `spawn_blocking` 线程里，界面不冻）——不想一次等完就用 `.stream`（2026-10-04 加，契约见 `docs/13` §9.1）：读一块交一块，⚠️ **块的边界既不是行边界也不是字符边界**（跨 UTF-8 由宿主兜住，所以最小单位是一个字符），一行 `data:` 横跨两块是常事。⚠️ 它**不负责往界面上画字**，要"边生成边显示"还得在回调里调 `nota.ui.stream`（`docs/13` §8.6）——那是**推**，因为跑着的时候宿主握着锁、`refresh` 那条拉的路回不来。⚠️ 密钥不写死在插件里——用 `settings.own` 存 |
| `ui.notify` | `nota.ui.notify(msg, level)`（`lua/api/ui.rs:35-53`） | 在界面上弹一条提示条。⚠️ 它能**冒充宿主的口径**对用户说话（提示里看不出是插件发的），所以不用它做误导性文案。⚠️ 这是三条里**唯一推事件**的（`nota:notify`），所以**在 `on_load` 里调它，前端还没起来，那条提示会静默丢掉**（Tauri 的 `emit` 对没有监听者的频道是静默成功的） |
| `ui.panel` | `nota.ui.register_panel(spec)`（`lua/api/ui.rs:75-227`） | 在**右侧栏**声明**一个页签（一页）**，`render` 里返回一串内容块决定它长什么样（**面板 DSL**，**十五种** `kind`，见 `docs/13` §8.5）。⚠️ 右侧栏**一次只显示一个插件的那一页**（2026-09-24 起，用户要求"两个拓展不能同时占用"）——别的插件那一页不会与它同时显示，但也**不刷新**：用户切过去时现拉（`docs/04` §右侧栏）。⚠️ **它推的不是事件，是状态**：写进 `nota_panels` registry，前端挂载后拉一次（BUG-13，见 §5.7）。⚠️ `render` 是**每次拉都现跑**的——里面必须是"此刻"，不是"加载时"。⚠️ 写 `wide = true` 让这一页占满（见 `docs/13` §8.2）；⚠️ 写 `live = true` 让宿主**每秒**喊一次"该重拉了"（这一页的 `render` 每秒跑一遍，见下 §3.5 与 `docs/12` §4.7a） |
| `ui.menu` | `nota.ui.register_menu(spec)`（`lua/api/ui.rs:115-149`） | 往菜单里**加条目**，点了回调插件自己注册过的命令。同上，**走 registry 拉**。✅ **2026-09-24 起接进菜单栏了**：合成一栏「插件」，插在「帮助」前面（backlog 第 42 项，规则见 `docs/13` §8.3）。⚠️ `accelerator` 走内置菜单同一条索引、同一条"先到先得"，**内置键位永远赢**。⚠️ 写 `prompt` 就是「点击后先询问一次」（见 §3.5 末）。⚠️ 它和另外三条 `ui.*` 是**任选其一**就能拿到 `nota.ui` 这张表——但"表在"不等于"那几个函数都在"，见 §3.4 |
| `settings.own` | `nota.settings.get(k)` / `.set(k, v)` / `.all()`（`lua/api/settings.rs`） | **读写自己那一段设置**（不碰别人的）：一个插件一个文件，`~/.config/nota/plugin-settings/<id>.toml`，文件 0600、目录 0700。⚠️ **明文，没有加密**——理由见 `docs/12` §"插件设置为什么不加密"。⚠️ `set(k, nil)` 是"删掉这一项"。⚠️ **2026-10-04 起这份文件有两个写者**：除了插件自己，**宿主**也会往里写——前提是清单里声明了 `[[settings]]`（§2.5），用户在「设置 → 拓展」上拖的那根滑杆走的就是宿主的命令。这也是"声明了 `[[settings]]` 就必须申请这个能力"那条硬规矩的由来；两种用法可以同时有，键各是各的 |
| **`data.own`** | **`nota.data.dir` / `.read(name)` / `.write(name, text)` / `.remove(name)`**（`lua/api/data.rs`，2026-09-27 加） | **读写插件自己那个数据目录**：`~/.local/share/nota/plugin-data/<id>/`。⚠️ 它是**第三样**东西，别和上面那两样混：`nota.fs` 围的是**用户的工作区**（没有工作区时整个不能用），`nota.settings` 只存"文本/数字/布尔"三样、没有数组。这一条放行的是一个**目录**＋一串文本文件，插件自己定格式，宿主只保证"这是你的、别人碰不到、跨重启还在"。⚠️ **三条硬边界**（`data.rs` 文件头）：名字只认 ASCII 字母数字与 `.` `-` `_`、**不许子目录**；写是**原子的**（先写 `.tmp` 再 rename）；一次读写 **1 MiB** 封顶（防呆，不是防恶意）。⚠️ 装了它**仍然碰不到**用户的文档——两条能力是两扇门 |

### 3.3 不申请任何能力也有的东西

这些**永远可用**（`lua/api/mod.rs:38-84`），因为它们不碰文档也不碰磁盘，
是插件跟自己、跟宿主说话用的（`nota.diff` 是第四种情况：**纯函数**，
给它一段文本它给一段文本）：

| 名字 | 是什么 |
|---|---|
| `nota.version` | 宿主版本字符串（`env!("CARGO_PKG_VERSION")`，当前 `"0.1.0"`） |
| `nota.api_version` | ABI 号，当前 `2`（`NOTA_PLUGIN_API_VERSION`，`manifest.rs:88`） |
| `nota.i18n` | `{app_lang, lang, ok, text(s)}`——插件自己的**文案表**（2026-09-25）。⭐ **不要能力**：路径由宿主用插件自己的目录拼，插件只交**键**。键就是"作者写下的那句原文"，取不到返回 `nil`（标准写法 `nota.i18n.text(s) or s`）。契约是 §2.4，代码在 `lua/api/i18n.rs` |
| `nota.plugin_id` | 这个插件在清单里声明的 id（**原样**，如 `nota.git`——没归一化） |
| `nota.log.info/warn/error(msg)` | 往宿主 stderr 打一行（⚠️ **默认不打**，要 `NOTA_DEBUG=1`，见 §6.3），前缀 `[nota:<插件 id>]` + 级别 |
| `nota.command.register(name, fn)` | 注册一个命令给宿主/前端调 |
| `nota.event.emit(name, payload)` | 往前端发一个事件 |
| `nota.diff.parse(回答)` / `nota.diff.apply(文档, hunks)` | **改动块**的解析与应用（2026-09-24）。契约与例子见 `docs/13` §11——想写"建议把文档改成这样"的插件就靠它 |
| `nota.time.now()` | **现在几点**（2026-09-27）。⭐ **不要能力**：它交的是**日历读数**（年月日时分秒、星期、时区偏移、今天零点），不是"用户在哪儿"——除了"用户所在时区"这件事本身，它没暴露任何环境信息，而那个偏移就是为了让日期**落在用户那一天**（写进分享图给人看的日期不能是 UTC 的）。⭐ 一次调用＝**一个瞬间**（十一个字段全是从同一个时刻算出来的，不会跨秒）。见 `docs/13` §16.1 |

### 3.4 ⚠️ 装载条件：表的存在 vs 表里成员的存在

这是两层判断，**两者不可混同**：

**第一层——子表装不装**（`lua/api/mod.rs:86-112`）：

| 子表 | 装上它的条件 |
|---|---|
| `nota.document` | `document.read` **或** `document.write` |
| `nota.fs` | `fs.read` **或** `fs.write` |
| `nota.git` | `process.git` |
| `nota.ui` | `ui.notify` **或** `ui.panel` **或** `ui.menu` **或** `ui.open_url`（**四条** `ui.*` 都要列——见下） |
| `nota.devserver` | `process.devserver`（**而且要真有 `[devserver]` 段**，否则加载就报错） |
| `nota.http` | `network.http` |
| `nota.settings` | `settings.own` |
| `nota.data` | `data.own`（2026-09-27 加，`lua/api/mod.rs`）⭐ 它**没有第二层**：这一张表里就四个函数（`dir` / `read` / `write` / `remove`），四个一起出现一起消失——因为它们围的是**同一个目录**，不像 `nota.ui` 那样四条能力各管一件事 |

**第二层——表里装哪些成员**：`document.rs` / `fs.rs` / `ui.rs` 各自**再判一次**，
只装申请到的那几个函数（`ui.rs:62` 判 `UiNotify`、`ui.rs:83` 判 `UiPanel`、
`ui.rs:96` 判 `UiMenu`、`ui.rs:109` 判 `UiOpenUrl`）。

⚠️ **两层是相乘的**，任一层漏一项、那条能力就是**死的**：

| 场景 | 第一层（表在吗） | 第二层（成员在吗） | 结果 |
|---|---|---|---|
| 只申请 `ui.panel` | ✅ 在 | `register_panel` ✅ / `register_menu` ✗ | 表有，但 `register_menu` 是 `nil` |
| 只申请 `ui.menu` | ✅ 在 | `register_menu` ✅ / `register_panel` ✗ | 表有，但 `register_panel` 是 `nil` |
| 一个 `ui.*` 都没申请 | ❌ 表是 `nil` | — | `nota.ui` 整张不存在 |

**第二层那半是 `docs/13` §8 的表格在管的；第一层这半归这一节。**

#### 📌 这条踩过坑：第一层曾经漏了 `ui.menu`（BUG-8，已修）

`api/mod.rs` 那个条件**曾经**只写 `ui.notify || ui.panel`，于是
**只**申请 `ui.menu` 的插件连 `nota.ui` 都拿不到，`register_menu` 自然无从谈起，
**`ui.menu` 这条能力形同虚设**。两个内置插件都申请了 `ui.panel`
（`plugins/git/plugin.toml`、`plugins/ai/plugin.toml`），所以一直没暴露。

**✅ 已在 2026-09-22 修掉**，而且修法不是"直接补一个 `||`"，
而是**让两层同源**：第一层的判据由一张能力清单产生，
那张清单的项数还必须与 `ui.rs` 里判据的个数对得上。

```rust
const UI能力: [Capability; 4] = [Capability::UiNotify, Capability::UiPanel, Capability::UiMenu, Capability::UiOpenUrl];  // api/mod.rs:336-341
fn 装_ui吗(manifest: &Manifest) -> bool { UI能力.iter().any(|c| manifest.has(*c)) }                // api/mod.rs:344
```

⚠️ 那个数组**当时是 3 项，现在是 4 项**——2026-09-25 加 `ui.open_url` 时，
正是"用例遍历这个数组"这套机制逼着一起改的：只往 `ui.rs` 加判据、
忘了往数组里加，`ui_能力清单要和_ui_rs_对得上` 那条用例就红。

`api/mod.rs:102-110` 现在留了一段注释专门记这件事，末尾一句是这一节最需要留意的：
**"里面有判据、外面也得有——两处是相乘的关系，不是一个能代替另一个。"**

**所以：只申请 `ui.menu` 就能拿到 `nota.ui` 和 `register_menu`，不用再"额外多申请一个"。**
`docs/07` 的 BUG-8 就是它（修好之后状态列会改成已修，编号永久保留）。

同批还加了 4 条回归用例（`lua::api::tests`，`cargo test` 从 32 条变 36 条，
计数只在 `docs/06` 记）：**每一条 `ui.*` 能力都能单独装出 `nota.ui`**、
**没申请任何 `ui.*` 就不装**（按能力装表、不装空壳）、
**`UI能力` 与 `ui.rs` 里的判据个数对得上**（`include_str!("ui.rs")` 数
`manifest.has(Capability::Ui` 的出现次数——⚠️ Rust 没有反射，这条推不出来，
所以退一步钉"数量"，注释与断言消息里都写明了"这是提醒不是证明"）、
以及 `#[serde(rename)]` 的名字与 `Capability::parse()` 同口径。

### 3.5 ⚠️ 声明式的两条路：面板与菜单项（**不走事件**）

能力表里那七张子表都是"插件调宿主"；但插件还要能**告诉宿主它有什么**——
面板和菜单项就是这么来的。它们**不走 `nota.event.emit`，走 registry**：

| 形式 | 什么时候发生 | 宿主怎么知道 |
|---|---|---|
| `nota.command.register(name, fn)` | `on_load` 里一次 | 宿主按名字**拉** |
| `nota.ui.register_panel({…, render = fn})` | `on_load` 里一次 | 前端挂载后 `nota_plugin_panels` **拉**；内容靠 `render` 每次现调 |
| `nota.ui.register_panel({…, live = true})` | `on_load` 里一次 | 同上，**但它多一样**：宿主那个每秒的心跳线程**只对 `live` 的页**喊"该重拉了"，所以它的 `render` 一秒跑一遍（`docs/12` §4.7a）。⚠️ **这不是 timer**——插件仍然收不到宿主事件、仍然没有自己的时间，"过了多久"只能从 `nota.document.stats().clock_ms` 拿；三条代价见 `docs/13` §8.2 |
| `nota.ui.register_menu({…})` | `on_load` 里一次 | 前端挂载后 `nota_plugin_menus` **拉**，合成「插件」栏 |
| `nota.ui.refresh([id])` | **想喊的时候**（插件自己知道内容变了） | 推一个 `nota:panel-refresh` 事件，前端收到就重拉那个面板。⚠️ 它推的是**"去重拉"这个动作**，不是内容本身——所以它不违反上面那条"别用推的送状态"。省掉它的症状是：面板显示的是上次拉取时的样子，用户得手动切走再切回来 |
| `nota.ui.review([id])` | **想摊开/收起的时候** | 把一个**已经在册的面板**摊到编辑区（`nil` 收起来）。⚠️ **面板自己负责收起**（用户点"完成"→ 插件调 `nota.ui.review(nil)`）：宿主不知道那些按钮是什么意思（`ui.rs:258-269`）。见 `docs/13` §8.6 |
| ⚠️⚠️ `nota.ui.stream(text)` | **正在生成的时候**（每秒十几次） | 推一个 `nota:plugin-stream` 事件，**载荷里带的就是那段字**（空串＝收工）。⚠️ **这是上面那条规矩唯一的例外**，也是唯一一个**推内容**的接口：它不是"声明"，只是个**临时的显示位**——跑着的时候宿主握着插件锁，`refresh` 那条**拉**的路在这中间回不来（`docs/13` §8.6 有那张图）。⚠️ 所以它只许送"边写边出"那类**看一眼就扔**的东西，宿主也只留最后 8000 字；**收工时照样得 `refresh()` 一次** |

⚠️ **上面这些"状态"不走事件**（最后一行那个 `stream` 是**唯一的例外**，
而且它送的不是状态、是**用一次就扔的临时显示位**——理由见那一行）。
注册发生在**插件加载时**，前端订阅发生在**挂载之后**，
用推的必然漏，而且**漏得静默**：界面显示正常，只是永远空着。
判据一句话：**需要靠"幂等"或"重放"来兜底的设计，通常意味着状态被存了两份。**
（本仓真按"记账 + 重放"写过一版，落地时被推翻 —— `docs/07` BUG-13，完整论述见 §5.7。）

⚠️ **`render` 里不许缓存**：它每次被调都要现算（`docs/13` §8.2）。
存一份快照的症状是"面板显示的是几分钟前的东西，而且看着像是对的"。

⚠️ **写 `live = true` 之前先想清楚 `render` 有多重**：从那一刻起它**每秒跑一遍**，
而且**是在 `plugins` 锁里跑的**（`docs/12` §4.7a）。
`plugins/stats` 里跑的是几次加减乘除（全在内存里），无所谓；
哪天要往 `render` 里加一次子进程或网络请求，先回头看一眼这一行。

⚠️ **`register_menu` 的 `command` 不做校验**，写一个没注册过的名字不会当场报错，
点了才得到 `插件 {id} 没有注册命令 \`{name}\``。**注册菜单之前需要先注册命令。**

**「点击后先询问一次」——`prompt`。** 菜单项和面板按钮都能写一个 `prompt`，
点下去先弹一个单行输入框、把答案并进 `args` 再跑命令：

```lua
nota.ui.register_menu({
  label = "提交…", command = "commit",
  prompt = {
    arg = "message",              -- 答案放进 args.message（**必填**，缺了整个 prompt 当没写）
    label = "提交信息",
    placeholder = "一句话说清这次改了什么",
    secret = false,               -- true → 输入框遮屏（`type=password`）
    hint = "……",                  -- 框下面那行小字
  },
})
```

**要问两个值时**再加 `secondArg` / `secondLabel` / `secondPlaceholder`
（2026-09-26 加的）。⚠️ **前两个都给才算数**，只给一个等于没给：

```lua
    prompt = {
      arg = "name",  label = "Git 身份",  placeholder = "名字，比如：张三",
      secondArg = "email",              -- 第二个答案放进 args.email
      secondLabel = "邮箱",             -- 这一行同时是"要不要问第二个"的开关
      secondPlaceholder = "you@example.com",
    },
```

**只有两个，不会再多**：三个以上的值该是插件自己的设置页（`settings.own`），
不是一个越滚越长的对话框。真要一次问三个，说明该改的是交互设计。

⚠️ **`arg` 缺了就当没写**——不是报错，只是不弹框（没有地方存放答案）。
⚠️ **用户按取消 ⇒ 该命令一次都不会被调用**，命令里不应假设"被调了就是用户答应了"。
⚠️ `secret = true` **只遮蔽输入框的显示，不改变存储方式**——设置是明文的（见 `settings.own`）。
⚠️ 两种 `prompt` 的字段**完全一样**，但归一化在两个地方做（菜单项在宿主
`plugin/mod.rs::读提示`、面板按钮在前端 `ui/panel-nodes.ts::提示`），
最后汇到**同一个**弹框（`ui/plugin-prompt.ts`）。完整字段表见 `docs/13` §8.5。

#### 📌 想写"对话框"式的面板：`message` / `diff` / `input`（2026-09-24）

`docs/13` §8.5 那十六种 `kind` 里有三种是**为了"跟用户来回说话"**加的
（AI 插件是第一个用户，但不是唯一能用的）：

| `kind` | 一句话 | 什么时候用 |
|---|---|---|
| `message` | 一问一答里的一条消息，`from = "user"` / `"ai"` | 有一段**要用户读的话**（模型的回答、历史记录）时用它。不用 `text` 代替：`message` 保留了换行、也区分了谁说的 |
| `diff` | 一块增删对照，`items = { { op = "del"/"add", text } … }` | 需要让用户**看一眼"准备改成什么"再决定**时用它。⚠️ 它**只画**——不认识 `nota-diff` 格式，也不知道点了按钮会怎样 |
| `input` | 输入框 ＋ 发送键，`{ arg, submit, … }` | 用户要**输入一段话**时用它（不是一句话的参数——那种用 `prompt`）。发出去＝调 `submit` 命令、参数 `{ [arg] = 输入 }`，**与按钮无区别** |

⚠️ **`input` 不是"面板里的表单"**：一次只带**一个值**、发出去就清空
（组件里 `set草稿("")` 在结果回来**之前**就清，因为那条输入马上会变成对话里的
一条消息、重拉时整块面板会重画）。需要收两个值就画两块，它不会累积。

**"AI 改文档"那条完整的路**（照抄 AI 插件那一份就行，`docs/13` §11 有格式的全部规矩）：

```lua
-- 1. 让"回答"里可能带一个 ```nota-diff 围栏块（这是你和模型之间的约定，
--    不是宿主强加的——宿主只提供解析和应用的函数）
local p = nota.diff.parse(answer)        -- { text = 正文, hunks = {...}, bad = 坏行数 }
-- 2. 把正文画成 message、把 hunks 画成 diff，然后**等用户点确认**
-- 3. 用户点的那条命令里才真写：
local new_text, why = nota.diff.apply(nota.document.get_text(), p.hunks)
if new_text then nota.document.set_text(new_text) end
```

⚠️ 上面这几个局部变量名是 **ASCII**（`new_text` / `why`），这不是风格问题：
**Lua 的标识符不许有非 ASCII 字符**（`docs/13` §0.6 有那一行报错原文）。
`--` 注释和 `"…"` 字符串里随便写中文。

⚠️ **不应在拿到回答的那一瞬间就 `set_text`。** 那是本项目最硬的一条产品原则
（**AI 的输出不许直接落进文档**）：模型会犯错，而"文档被悄悄改掉、用户按了
Ctrl+Z 才发现"是最坏的一种错。

## 4. ABI 版本

### 4.1 常量与精确匹配

```rust
pub const NOTA_PLUGIN_API_VERSION: u32 = 2;    // manifest.rs:88
```

清单里的 `api` 栏**必须恰好等于**它：

```rust
if meta.api != NOTA_PLUGIN_API_VERSION {
    return Err(NotaError::PluginApiMismatch { id, wanted: meta.api, have: NOTA_PLUGIN_API_VERSION });
}                                              // manifest.rs:345-351
```

不匹配得到的是**一条可读的错误信息**：「插件 `nota.git` 需要 API 版本 1，宿主是 2」
（措辞在 `error.rs:39`）。
这个错误发生在 `Manifest::load()` 里，所以 ⚠️ **不匹配的插件根本不会出现在插件列表里**
——只在启动日志里有一行（见 §6.1）。

### 4.2 为什么是精确匹配而不是 `>=`

理由与 Folio 的 `FO_PLUGIN_API_VERSION` 同一条
（写在 `manifest.rs:76-87` 那段常量注释里）：**宿主与内置插件永远同批构建**，
`>=` 只会让"插件作者以为存在一个他没见过的新版本"这种事发生。
号一变，内置插件同批改号，**没有迁移动作**（`1 → 2` 就是这么走的：
两个内置插件同批改成 2，谁都没写迁移代码）。

⚠️ 这条依赖 `AGENTS.md` §0.5 那条"首次提交 GitHub 之前不必兼容老插件"的口径。
**它是有触发条件的，会到期**：一旦对外发布，老插件就得能加载，那时"精确匹配"
要么改成 `>=`，要么给出迁移路径。

### 4.3 什么时候该动号

三条判据（`manifest.rs:80-83`，原文照抄）：

| 改动 | 动不动号 | 为什么 |
|---|---|---|
| 给 Lua 侧的 `nota.*` 表**增加**成员 | **不动** | 老插件照样跑——它不知道的新成员，对它就是不存在 |
| **改名**某个 `nota.*` 成员 | **动** | 老插件会**静默拿到别的东西**（或者拿到 `nil`） |
| **改变**某个成员的**语义** | **动** | 同上：名字还在，行为变了 |
| 增删 `capabilities` 里的取值，**并让它影响放行** | **动** | 老插件的清单可能申请了不再存在的值（那会被拒载），或者漏申请新拆出来的值（那是静默降级） |

一句话：**加东西不动号，改东西/删东西动号。**

### 4.4 三个"版本"别搞混

| 名字 | 在哪 | 是什么 |
|---|---|---|
| `api` 栏 / `nota.api_version` | 清单里 / Lua 侧 | **ABI 号**，当前 `2`。宿主与插件之间的契约版本 |
| `nota.version` | Lua 侧 | **宿主应用的版本**（`0.1.0`，来自 `Cargo.toml` 的 `package.version`） |
| `version` 栏 / `PluginInfo.version` | 清单里 / 前端 | **插件自己的版本**。`plugin.toml:12` 的注释明确说了：**不代表 ABI** |

⚠️ 所以一个插件写 `version = "9.9.9"` 而 `api = 2` 是**完全合法**的。

## 5. 生命周期

### 5.1 入口脚本的形状

入口脚本（清单里的 `entry`，默认 `main.lua`）**按模块写，最后 `return` 一张表**：

```lua
local M = {}

function M.on_load(nota)
  nota.command.register("git.status", function() ... end)
end

function M.on_unload()
  -- 可选；不写就是没活要干
end

return M
```

（这段形状照抄 `lua/mod.rs:26-42` 的模块注释。）

### 5.2 两个回调

| 回调 | 必填？ | 签名 | 什么时候被调 | 抛错会怎样 |
|---|---|---|---|---|
| `on_load` | **可选** | `on_load(nota)` | **每加载一次一次**：启动、装完、以及**每次「启用」**。模块表里 `on_load` 是函数才调。⚠️ **必须幂等**，见 §1.6.7 | ⚠️ **整个插件判为加载失败**（`state = failed`），界面上标红。见 §5.4 |
| `on_unload` | **可选** | `on_unload()`（无参） | **每卸载一次一次**：窗口 `Destroyed`（`lib.rs:95-104` 的 `on_window_event` → `unload_all()`）、**「停用」**、**「卸载」** | ⚠️ **只记不抛**：往 stderr 打 `[nota] 插件 {id} 的 on_unload 出错：{e}`，卸载流程不被一个插件的失败卡住（`lua/mod.rs:346-350`） |

`on_load` 收到 `nota` 表**当参数**（`lua/mod.rs:306-322`），
所以可以写 `function M.on_load(nota)` 完全不依赖全局——**推荐这种写法**。

### 5.3 宿主怎么存你的模块表

模块表被塞进 Lua 的**命名注册表值** `nota_module`（`lua/mod.rs:313-315`），
命令表塞进 `nota_commands`（`lua/api/mod.rs:137`）。

⚠️ **为什么用 registry 而不是 globals**：插件**可以合法地把全局 `nota` 覆盖掉**
（`lua/mod.rs:312-313`）。用全局存宿主自己的东西，那个名字就归插件所有了。

### 5.4 ⚠️ `on_load` 抛错 = 整个插件加载失败

这是插件作者最容易吃亏的一条。**`on_load` 里做的任何事抛了错，用户看到的是
"这个插件坏了"**——哪怕真实原因只是"用户还没打开文件夹"。

实例（`docs/07` BUG-2）：Git 插件在 `on_load` 结尾刷一次状态，而
`nota.git.status()` 当时对"没有工作目录"直接抛错——于是**"用户还没打开文件夹"
被显示成"这个插件加载失败"**，侧栏里赫然一行标红，而插件本身没有任何写错的地方。

修法分两头，**两头都需要知道**：

1. **宿主侧**已经把"环境不具备"折成一张 `code != 0` 的结果表
   （`lua/api/git.rs:29-41` 的"两种失败要分开"），插件正常处理即可；
2. **插件侧**再包一层 `pcall`（`plugins/git/main.lua:184-192`）——
   注释里写明了这是**刻意的**，不是防御性编程的迷信：
   "将来宿主新加的任何一种环境失败"都不会再变成一次误判。

```lua
-- plugins/git/main.lua:189-192
local ok, err = pcall(refresh, nota, true)
if not ok then
  nota.log.warn("首次刷新改动失败：" .. tostring(err))
end
```

### 5.5 加载失败不会带走宿主

`LuaPlugin::load()` **不返回 `Err`**，而是返回一个 `state = Failed(原因)` 的实例
（`lua/mod.rs:193-215`）。理由很实在（`plugin/mod.rs` 的文件头）：插件是用户自己装的
第三方代码，让一个写错的 Lua 脚本变成"应用打不开"，用户**连去禁用它的界面都进不去**。

同样的道理：`Load`/`on_load` 整个过程都在插件**自己的** Lua 状态里跑，
一个插件崩溃了影响不到别的插件，也影响不到宿主。

### 5.6 ✅ 曾经的两个不一致（2026-09-25 已结清）

这两条原本是"知道就好，不用绕"的现状；现在都不成立了，留着是为了让
按老文档写过的插件作者知道**行为变了**：

| 原来的现象 | 现在是什么样 |
|---|---|
| `PluginState::Disabled` 从来没被构造过（死变体） | ✅ 真的会构造了：停用的插件由 `LuaPlugin::disabled(manifest)` 表示，**没有 Lua 状态**（`lua/mod.rs`） |
| **禁用不等于卸载**，重新启用**不会**重跑 `on_load` | ✅ 反过来：**停用 = 真卸载**，重新启用**会**重跑 `on_load`。⚠️ 所以 `on_load` 必须幂等（§1.6.7） |

⚠️ 一句话记住：**停用之后那个插件"不在场"**，不是"在但不动"。它声明的面板、菜单项、
命令全都一起消失。要"暂停"语义得插件自己实现。

### 5.7 ⭐ 声明是状态 → 拉；发生是事件 → 推

**这是写 `nota.ui.*` 之前必须知道的一条**，也是插件作者最容易忽略的一条。

在 `on_load` 里调 `register_panel` / `register_menu` 时，那一刻是**插件加载时**
（`setup()` 阶段）——而 WebView 连 `listen()` 都还没注册。如果宿主拿事件把它推给
前端，**它会静默丢掉**：Tauri 的 `emit` 对没有监听者的频道是**成功返回**的，
日志里一点痕迹都没有。现象就是"面板时有时无"，取决于加载耗时与启动流程的先后。

| 分类 | 例子 | 走哪条 | 为什么 |
|---|---|---|---|
| **声明（状态）** | `register_panel` / `register_menu` / `command.register` | **registry，宿主拉** | 状态是"现在有哪些"，问一次就得到全量；推的话还要解决"前端起来之前的那些怎么办" |
| **发生（事件）** | `notify` / 插件自己的 `plugin:<id>:<name>` | **推**（`emit`） | 事件是"此刻发生了一件事"，攒着没意义、重放还会重复 |

**判据一句话**：**需要靠"幂等"或"重放"来兜底的设计，通常意味着状态被存了两份。**
（这条有实例：本仓真按"记账 + 重放"写过一版设计，写进了两处文档，落地时被推翻，
见 `docs/07` BUG-13。）

实际影响：

- ✅ 面板/菜单**注册一次就够**，不用管前端什么时候起来，也不用在 `on_load` 里
  自己 `emit` 一遍；
- ⚠️ 但**同一个插件里不应重复注册同一个 `id`**——`register_panel` 会**当场报错**
  （不是静默覆盖）。多半是复制粘贴改漏了；静默覆盖会让人对着"点下去
  跑的是另一个函数"排查很久；
- ⚠️ `notify` 是**推**的。**在 `on_load` 里调它，那条提示会丢**——
  想报"插件已加载"这类话，用 `nota.log.info`，不用 `notify`。

## 6. 怎么调试一个插件

### 6.1 ⚠️ 加载失败有**两个完全不同的显示面**

**这是本节最要紧的一条。** 同样是"插件没起来"，看的地方不一样：

| 失败发生在哪 | 界面上 | 终端里 | 插件在列表里吗 |
|---|---|---|---|
| **清单读不了**（TOML 语法错、缺 `name`、`id` 非法、`api` 不匹配、未知能力、`entry` 逃逸） | **什么都不显示** | `[nota] 插件清单读不了：{原因}`（`plugin/mod.rs` 的 `discover()`） | ❌ **不在**——连 `id` 都可能没解析出来 |
| **清单 OK，但加载失败**（入口脚本不存在、Lua 语法错、`on_load` 抛错、事件通道撞名） | 侧栏「插件」页**一行，标红**，下面一段错误原文 | 可能没有任何输出（除插件自己 `nota.log.*` 打的） | ✅ 在，`state = "failed"` |

**所以：插件列表里没有它 → 查终端那行日志；列表里有它但标红 → 看那一段错误原文。**

⚠️⚠️ **2026-09-25 起"终端里"那一列要先 `NOTA_DEBUG=1` 才有**：宿主所有
stderr 输出（包括插件的 `nota.log.*`）都归了调试闸门，默认一行不打
（`docs/06` §3.1）。**不设那个变量时，"终端里什么都没有"是正常的**，
不代表插件没问题——这是本节最容易白花半小时的一处。

### 6.2 界面上在哪看

**右侧插件栏**（`src/ui/PluginDock.tsx` 的 `PluginDock`）；
⚠️ 2026-09-22 之前它在左侧栏的第三页，现在整栏搬到了右边，
`Sidebar.tsx` 里已经没有 `PluginList` 了。每一行渲染的是 `api.plugin.list()` 返回的
`PluginInfo`（`plugin/types.rs` —— 2026-09-29 从 `plugin/mod.rs` 拆出，`plugin::PluginInfo` 这条老路径靠 `pub use` 转出、没变）：

| 字段 | 显示成什么 |
|---|---|
| `name` / `version` | 插件名与版本 |
| `id` | 小字一行——**出错时报这个号最有用** |
| `description` | 描述 |
| **`error`** | 只有 `state == "failed"` 时有值，渲染成 `.plugin-error` 那一段 |
| `state` | `"loaded"` / `"failed"` / `"disabled"`，同时决定 `<li>` 的 class（`plugin-loaded` / `plugin-failed` / `plugin-disabled`） |
| `capabilities` | 清单里申请到的**原始字符串**（不是解析后的枚举） |
| `origin` | `builtin`（跟着安装包/仓库来的）或 `user`（用户自己从文件装的）。渲染成「内置 / 自装」，判据是**目录落点**，见 §1.6.6 |
| `signature` / `key_id` | 装进来时的验签结论与签名者指纹（`None` = 这笔账没记过，比如内置插件）。渲染成「已验证 / 未知签名者 / 未签名」 |
| `removable` | `origin == "user"`。**决定「卸载」那颗按钮出不出来** |

行上那几颗按钮（`ui/usePlugins.ts::插件动作`）：

| 按钮 | 什么时候出现 | 干了什么 |
|---|---|---|
| **停用 / 启用** | 总是（`state == "disabled"` 时写「启用」） | `nota_plugin_set_enabled`。⚠️ **真装卸**，会有一小会儿延迟 |
| **卸载** | 只有 `removable` | `nota_plugin_uninstall`，**不可逆**，弹宿主自己的确认框（文案里明说"设置文件留着"） |
| **信任** | 只有 `signature == "unknown"` | `nota_plugin_trust`，把签名者指纹记进信任库，然后变成「已验证」 |
| **从文件安装…** | 那一栏的标题旁边 | 弹文件框选 `.nota-plugin` / `.zip`，装完若签名者不认识会**当场**问一句要不要信任 |
⚠️ **导出不在这张表里**：它只在**设置 → 拓展**那一页（`ExtensionsPane.tsx` 的「导出…」）。⚠️ 这一栏**只管装 / 卸 / 停用 / 信任**这四件"会改状态"的事，而导出**不改任何状态**（所以它不弹确认框）；完整的三件事见 §1.6.9。
⚠️ **界面上这一块一律叫「拓展」**（用户 2026-09-27：「这个功能统一为拓展」）——所以按钮与提示里写的是「拓展」「拓展包」；`plugin` 只留在**代码与文档**里（英文才是主语言、中文是翻译包），两边共用的那份文案在 `ui/pluginText.ts`。

⚠️ 这一栏**是「插件」那一页**（2026-09-24 起右侧栏是页签式的，`docs/04` §右侧栏）。
`register_panel` 声明的面板**各占自己的页签**（`location == "right"` 的），
而**没有落脚处**的面板（`location` 写了别的值——2026-09-22 之前默认是
`"sidebar"`，所以老插件会掉进这组，见 `docs/07` BUG-14）就列在**这一页里面**，
外加上面那张表的插件清单。
**「没有落脚处」这一组是有意留的**：宁可把"声明的面板没人要"摆出来，
也不要静默丢掉——BUG-14 就是这么被新代码当场报出来的。
### 6.3 日志：`nota.log.*`

```lua
nota.log.info("开始刷新")
nota.log.warn("首次刷新改动失败：" .. tostring(err))
nota.log.error("...")
```

打到宿主 **stderr**，前缀是 `[nota:<插件 id>]`（`lua/api/mod.rs:52-62`）。
多插件同时刷输出时靠这个前缀分清是谁。

⚠️⚠️ **默认一行都不打**（2026-09-25 起）：这一族和宿主自己的日志走**同一道
调试闸门**（`src-tauri/src/log.rs`），**要 `NOTA_DEBUG=1` 启动才看得到**
（`docs/06` §3.1）。两条推论：

- **别拿 `nota.log.*` 当用户提示**——它历来只到 stderr（用户看不到），
  现在默认**连开发者的终端也不到**。要对用户说话走 `nota.ui.notify`（§7）。
- **别以为"没输出 = 这行没跑到"**：先看闸门开了没有。
  §6.4 那条"用兜底日志让失败可见"的经验，前提就是**开着闸门调试**。

⚠️ **参数只有一个**（任意 Lua 值，宿主会渲染成文本）。
`nota.log.info("a", "b")` 的第二个参数不会被打出来。

### 6.4 ⚠️ 最值钱的一条经验：`pcall` 兜底日志

`docs/07` §2 在 BUG-3 下面单独记了一段，**和写插件直接相关**：

> BUG-3（带点的插件 id 让每次 `emit` 都抛错）是"**加载成功、静默失效**"那一类——
> 插件列表里一切正常，错误只在**第一次发事件**时出现。
> 抓到它的过程：BUG-2 修完之后加了 `pcall` + `nota.log.warn` 兜底，
> **是那条兜底日志把错误打出来的**——没有它，BUG-3 会继续潜伏。

**做法**：`on_load` 里任何"可能因为环境而失败"的调用，都包一层 `pcall` +
`nota.log.warn`。这不是防御性编程，而是**让失败可见**。

### 6.5 命令调不通时的三个可能

| 症状 | 先查这个 |
|---|---|
| `插件 X 没有注册命令 \`Y\`` | 命令名拼错了，或者 `nota.command.register` 那一行没跑到（比如 `on_load` 在它之前就抛了） |
| `插件 X 重复注册命令 \`Y\`` | **同名覆盖是刻意报错的**（`lua/api/mod.rs:148-152`）：多半是复制粘贴改漏了。静默覆盖会让人对着"点下去跑的是另一个函数"排查很久 |
| `插件 X 已被禁用` / `插件 X 加载失败，无法执行命令：…` | 后端状态不对，去侧栏「插件」页看那一行 |

### 6.6 不开窗能测到哪一层

见 `docs/08` §6 第 4 步那张四档表（清单单测 / Lua 解释器跑入口 / Xvfb 看侧栏 /
`xdotool` 点菜单）。**最省事的一档是看启动日志里那个数字**：

### 6.7 ⚠️ 从宿主 API 炸出来的错误**带一大段栈**，要自己掐

这是 2026-09-24 目检时发现的（`docs/07` BUG-20），**凡是会把错误显示给人看
的插件都会碰到**：

宿主那些 Rust 回调返回的 `Err`，会被 mlua 包成 `CallbackError`，并在末尾
**缀上一整段 `stack traceback:`**（`mlua-0.12.1/src/util/error.rs::callback_error`）。
所以 `pcall(nota.http.post, ...)` 抓到的不是"连不上服务器"这一句，
而是从宿主一路到插件 Lua 文件的一大段——写进面板/通知里，一次失败就能占满界面。

**做法**：把要给人看的那一句截出来。参考实现是 AI 插件里的 `clean_error`
（`plugins/ai/main.lua`，`docs/13` §12.2 那张表里 `202-222` 那一行）：

```lua
local function clean_error(e)
  local s = tostring(e)
  local cut = string.find(s, "stack traceback:", 1, true)  -- ① 从这儿截断
  if cut then s = string.sub(s, 1, cut - 1) end
  s = (string.gsub(s, "^runtime error: ", ""))             -- ② 去掉包装前缀
  return trim(s)
end
```

⚠️ **两条需要分清**：

- **给人看的**（面板、`nota.ui.notify`）→ 截干净。
- **给作者看的**（`nota.log.warn`、`pcall` 兜底日志，见 §6.4）→ **原样打**，
  栈在那里正是需要的东西。§6.4 那条"最值钱的经验"靠的就是日志里有栈。

⚠️ 截断之前需要想清楚**要留什么**：有些失败的原因就藏在被截掉的那半里
（比如 `nota.http` 的响应体校验错）。**先分清"环境问题"还是"插件写错了"，再决定截到哪儿**。

📌 根源在宿主那一侧的边界上，**没修**——正确的做法是让 `nota.http.*` 这类
"环境类失败"改成返回结果表而不是抛错（与 `nota.git` 那条"两个失败通道"
同一个口径，见 `src-tauri/src/lua/api/git.rs` 文件头）。
在那之前，**每个插件都需要自己截一次**。

## 7. 插件之间怎么协作（现状）

**目前没有正式的协作机制。** 能用的只有两条路，而且两条都只实现了一半：

| 路 | 现状 |
|---|---|
| **调别人的命令** | 宿主有 `find_command_owner()`（`plugin/mod.rs`，先做"第一个匹配"）。⚠️ 但前端调命令时**必须显式给 `plugin` 参数**（注册者的 id），不能凭命令名推测是哪个插件的——两个插件重名时猜错就是**静默调到另一个插件**（`commands/plugin.rs:36-38`） |
| **订阅别人的事件** | ⚠️ **没有人在听插件频道**。前端的事件表里**十个**宿主事件（`src/bridge/ipc.ts:654-772`：notify / document-changed / plugin-panel / plugin-review / native-menu / focus-state / focus-beep / file-changed / second-instance / format-key），插件发的 `plugin:<id>:<名字>`（拼频道在 `lua/api/mod.rs:217`）全部**发出去就被丢掉** |

⚠️ **那个数 2026-09-28 重数过一次**：本节原先写「五个」，而那五个是 2026-09-25
那一遍数出来的；之后陆续补进来的**五条**（`focus-state` / `focus-beep` /
`file-changed` / `second-instance` / `format-key`）**本节一条都没跟上**。
⚠️ 它们**不影响本节的结论**（那五条全是宿主自己的频道，跟"插件发的没人听"这件事无关），
但数错了就是数错了——**与 `docs/01` 通道 B 那张总表同一天、同一批对齐**，
理由也是同一条：**「一共 N 个」这种数要么现数、要么别写**。

⚠️ **那"五个"是怎么来的（2026-09-25 数过）**：曾经是**六**个，
第一条被删的是 `slidev-stopped`（`nota:slidev-stopped`）——它唯一的发法是 `lib.rs`
里预览窗那个 `Destroyed` 分支，"用户把预览窗叉了"。预览从独立窗口搬进右侧插件栏之后，
那个窗口只是**这场会话的一个视图**，叉掉它不再结束会话，于是这条事件**没有生产者了**，
同批删掉（`lib.rs` 那个分支现在故意空着，但**不能连 `match` 一起删**：
不按 label 分派的话，叉掉预览窗会把插件全卸掉）。
⚠️ 后来补上的两条是 `plugin-panel`（`nota.ui.refresh` 喊的"我这边的面板内容变了"）
与 `plugin-review`（`nota.ui.review` 摊开/收起编辑区那一块）——它们推的都是
**"此刻变了"这个动作**，不是状态，所以不违反 BUG-13 那条判据：**收到就去重拉**。
⚠️ **数这个数只能对源码**：`grep -rn 'emit(' src-tauri/src/` 与 `ipc.ts` 的 `events`
表两边对着看。**以"发了的那个"为准**——没有生产者的订阅永远不会来，而没有监听者的 `emit`
在 Tauri 里是**静默成功**的，两头都不报错。

所以"让别的插件代为计算"这条路目前是**不通的**：AI 插件 2026-09-24 大改时**不再尝试走它**——
要文档就直接 `nota.document.get_text()` 取整篇（`plugins/ai/main.lua:371`），
以前那个"问 git 插件要 diff、要不到就回退全文"的 `scope = "diff"` 已经删掉了。
真要做"只要局部改动"，补的是前端那边的订阅端，属于 backlog **第 17 项**（Git 插件的前端面板）。

⚠️ **注意第 17 项和第 16/38 项不是同一个根因**（这一点曾经记错过）：
第 16 项讲的是"**声明类**走错了通道"——已按「声明是状态 → 拉」修掉（BUG-13），
第 38 项是它的下游，已结清。第 17 项讲的是"**数据类**事件没人消费"——
结论不一样：`plugin:<id>:<name>` 这条通道对**发生类**数据**是正解**，
缺的只是前端那边的订阅端。**不能把结论推广成"事件机制不该用"。**
