## 0. 读之前：六条通则

### 0.1 调用约定

| 形态 | 例子 |
|---|---|
| 位置参数 | `nota.log.info("开始")`、`nota.event.emit("git:status", t)` |
| 一张表当参数 | `nota.git.run({ "add", "-A" })`、`nota.ui.register_panel({ id = "git" })` |
| 一个表当参数（可选） | `nota.git.diff(true)`；`nota.command.register("x", function(args) … end)` 里的 `args` |

⚠️ **没有命名参数、没有重载、没有 `nil` 占位跳参**。想省一个参数就得写成
`function(args)` 收一张表——`plugins/ai/main.lua:80-82` 就是这么收 `args.scope` 的。

### 0.2 ⚠️ 失败有**两条完全不同的通道**（写插件的第二课）

| 通道 | 什么时候 | 插件怎么处理 |
|---|---|---|
| **抛 Lua 错误** | **插件自己写错了**：传了禁止的参数、参数类型不对、命令名重复、能力没申请 | 不要 `pcall` 掉。这是开发期的 bug，应当直接暴露出来（`docs/11` §6.4 只要求给**环境类**调用兜底） |
| **返回一张 `code ~= 0` 的结果表** | **环境不具备**：没开工作区、目录不是 git 仓库、没装 git | **正常处理**，把 `stderr` 里的原因说给用户听 |

这条分界线是 `src-tauri/src/lua/api/git.rs:29-41` 那段注释的正文，是**出过一次问题之后才写下来的**
（伪装的后果见 §7.3）。除 `nota.git` 外，`nota.fs` 的**读取失败**也走第一条通道
（抛 `读文件失败 …`）。

### 0.3 错误信息一律是中文人话

所有 `NotaError` 的 `Display` 都写成人话（`src-tauri/src/error.rs:1-5` 的口径），
经 `lua_err()`（`api/mod.rs:32-34`）折成 `mlua::Error::RuntimeError`。
所以插件里 `pcall` 抓到的字符串是可以**直接给用户看**的，不用再包一层解释。

⚠️ 反过来说：**在 Lua 里抛的错也有机会回到用户面前**。
命令回调抛错时，宿主会把它裹成 `Lua 出错（插件 {id}）：{message}`
（`error.rs:44-48`）——所以 `error("没有找到配置文件")` 这种写法比 `error("nil")` 强得多。

### 0.4 哪张表在不在，取决于清单

⚠️ **不是"每张表都在、调用时报没权限"**。没申请对应能力的子表**根本不存在**（`nil`）。
逐条判据见 `docs/11` §3.4；`nota.ui` 那两层的相乘关系见 §8.4。

### 0.5 Lua 值怎么变成前端看得见的东西

`nota.event.emit` 的 payload 与命令的返回值都要过一遍 `lua_to_json()`
（`api/mod.rs:217-248`）。规则：

| Lua 值 | 变成 |
|---|---|
| `nil` | `null` |
| `true` / `false` | 布尔 |
| 整数 / 浮点 | 数字（`NaN` / `inf` → `null`，因为 JSON 没有它们） |
| 字符串 | 字符串 |
| **表**：`raw_len() > 0`（有连续整数键 `1..n`） | **数组** |
| **表**：否则 | **对象**（⚠️ **只收字符串键**，非字符串键**被静默丢掉**） |
| 其它（函数 / userdata / 线程） | `format!("{other:?}")` 的**调试字符串** |

⚠️ 两条实战推论：
1. **不要把 `function` 塞进 payload**——它不会报错，会变成一个像
   `Function(0x7f…)` 的字符串发到前端，等到前端渲染时才暴露问题。
2. **一张同时有数组部分和字典部分的表**走数组那条路，**字典那半会丢**。
   `{ is_repo = true, entries = {...} }` 这种表 `raw_len()` 是 0（没有 `[1]`），
   所以走对象分支——`plugins/git/main.lua:110` 与 `:119`（`is_repo` 那两处）
   正是这个形状，没问题。

⚠️ 还有一条不在这个转换里、但同样需要注意的：**没有异步、没有协程 API**。
一次 `nota.*` 调用是同步阻塞的。

⚠️ 这里原先还写着"**没有 `require`**，想拆多文件也做不到"——**2026-09-27 起不成立了**：
沙箱里补了一个只在本插件目录里找 `.lua` 的 `require`（§0.7）。剩下没变的是
"没有异步"：`nota.*` 全都是同步阻塞的，多文件改变不了这件事。

### 0.6 ⚠️⚠️ 变量名一律 ASCII，中文只许出现在注释和字符串里

**这不是风格建议，是"插件能不能加载"的分界线。**

Lua 的标识符只认 `[A-Za-z_][A-Za-z0-9_]*`：词法分析里那个 `lislalpha` 用的是 C 的
`isalpha`，而 `键` 的 UTF-8 字节（`0xE9 …`）在**任何 locale 下都不算字母**。
所以 `local 键_密钥 = "api_key"` 是**语法错误**：

```lua
local 键 = 1     -- ✗ 语法错误，整份插件加载失败
local key = 1    -- ✓
local 说明 = "密钥"  -- ✓ 字符串里的中文随便写
-- 注释里的中文也随便写 ✓
```

**代价是不对称的**：Lua 报的是 `<name> expected near '<\233>'`，
看到这句话很难想到"是用了中文变量名"，而症状是**面板和菜单一起消失**
（`on_load` 根本没跑到）。本仓在 2026-09-24 遇到过这一次——
两份内置插件的**每一行**都没执行过，代码却是"写完"的样子。

**不依赖记性的做法**：`src-tauri/src/lua/mod.rs` 里有一条用例
（`内置插件都能被_lua_编译`）会把 `plugins/*/main.lua` 逐个编译一遍。
写在仓库之外的插件，用 `luac -p your-plugin/main.lua` 检查一遍——
`lua -e "assert(loadfile('main.lua'))"` 等效，只需一条命令。

⚠️ 这条**只**管名字。中文的注释、字符串、字段名（`{ label = "提交信息" }`，
键是 `label` 那个 ASCII 词）全都不受影响——Lua 的字段名是字符串，不是标识符。
⚠️ 用 `t.中文键` 这种写法同样不行：那是语法糖，`t.名字` 里的 `名字` 也是标识符。

### 0.7 `require`：插件自己的多文件 ✅（2026-09-27 起）

沙箱里**有一个 `require`**，但它是宿主装的（`lua/mod.rs::装require`），
**只认本插件目录里的 `.lua`**：

```lua
local chart = require("chart")      -- <插件目录>/chart.lua
local 色    = require("ui.palette")  -- <插件目录>/ui/palette.lua（`.` = 目录分隔）
local kit   = require("kit")         -- <插件目录>/kit/init.lua
```

| 与真 `require` 的差别 | 后果 |
|---|---|
| 只认 `.lua`（**.so 永远拿不到**） | 插件不许有 C 扩展——那是绕过整个沙箱的一条路 |
| 只在本插件目录内（与 `nota.fs.*` 同一把尺） | `require("/etc/passwd")`、`require("../别的插件/x")` 当场报错；**插件之间不能互相 `require`** |
| 没有 `package` / `package.path` | 搜索路径是死的（就上面那两种写法），插件改不了 |
| 循环 require **报错**（不是栈溢出） | 报错里直接写着"`x` 在求值过程中又 require 了自己" |
| 模块名**必须 ASCII** | 与 §0.6 同一条理由，但这里更糟：**报错信息本身会变成乱码** |

⚠️ **一个模块只求值一次**，第二次拿的是**同一个表**（不是"长得一样的表"）——
真 `require` 的语义。所以模块里存的状态（缓存、注册表）跨调用是活的，
可以放心用。什么都不返回的模块按真 `require` 的老规矩**当 `true`**。

⚠️ **`.so` / `package` / `io` / `os` / `debug` 一个都没回来**：补的是**一个函数**，
不是那个标准库（`docs/12` §5.9 有这张账）。

⚠️ **拆出来的每个 `.lua` 都要补进 `tools/doc-sync-check.sh` 的 `PAIRS`**（在"拆"的
那一步就补）：那道闸只扫 `src` 与 `src-tauri/src`，**不看 `plugins/`**，插件全靠那张表
逐条写，而"一个插件目录里该有几个 `.lua`"闸门没法自己知道。写作统计上这个坑犯过两次
（整个目录漏登记 ＋ 拆出来的两个文件漏登记），完整的账在 `docs/11` §1.3.1。

## 1. 身份（永远可用）

这三项不申请任何能力就有（`api/mod.rs:41-43`）。

| 字段 | 类型 | 值 | 来源 |
|---|---|---|---|
| `nota.version` | string | **宿主应用**的版本，当前 `"0.1.0"` | `env!("CARGO_PKG_VERSION")`，编译期定死 |

⚠️ `nota.plugin_id` 与事件通道里那段 id **不是一个字符串**：

## 2. `nota.log`（永远可用）

```lua
nota.log.info(msg)
nota.log.warn(msg)
nota.log.error(msg)
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `msg` | **任意 Lua 值**（`mlua::Value`） | 只有一个参数 |

**返回值**：无。
**失败**：不会失败——`eprintln!` 的返回值被丢掉（`api/mod.rs` 的 `nota.log` 那一族）。
**去哪了**：宿主 **stderr**，前缀 `[nota:<插件 id>]` + 级别：

```
[nota:nota.git] INFO 开始刷新
[nota:nota.git] WARN 首次刷新改动失败：...
```

⚠️ **默认一行都不打**（2026-09-25 起）：这一族和宿主自己的日志走**同一道调试闸门**
（`src-tauri/src/log.rs`），**要用 `NOTA_DEBUG=1` 启动才看得到**。所以：

- 写插件时**不要**指望 `nota.log.*` 能让用户看到什么——它对用户从来都是不可见的
  （只到 stderr），而现在是**默认也不可见**；
- 要对用户说话，用 `nota.ui.notify`（§8.1）——但那需要 `ui.notify` 能力；
- 自己调试时先开闸门，`docs/06` §3.1 是那份说明书。

`msg` 的渲染规则（`value_to_text()`，`api/mod.rs`）：
`nil` → `"nil"`、布尔 → `true/false`、整数/浮点 → 十进制、字符串 → 原样、
**其它类型 → `format!("{other:?}")` 的调试字符串**。
⚠️ 关着闸门时这个渲染**根本不会被调用**（`日志!` 宏的参数不进格式化），
所以它不会是性能负担。

⚠️ **第二个参数不会被打出来**：`nota.log.info("a", "b")` 只输出 `a`。
要拼字符串自行用 `..`（可能为 `nil` 的值先 `tostring()` 一下）。

## 3. `nota.command.register(name, fn)`（永远可用）

```lua
nota.command.register("refresh", function(args) … return { ok = true } end)
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `name` | string | 命令名。**空字符串会被拒** |
| `fn` | function | 回调。**收一个参数 `args`**（前端传来的 JSON 转成 Lua 值） |

**返回值**：无。
**失败**：两种都**抛 Lua 错误**（`api/mod.rs:141-152`）。

| 情况 | 错误原文 |
|---|---|
| `name == ""` | `命令名不能为空` |
| 同名已经注册过 | `插件 {id} 重复注册命令 \`{name}\`` |

⚠️ **同名覆盖是刻意报错的**（`api/mod.rs:148-152`）：多半是复制粘贴改漏了，
静默覆盖会让人对着"点下去跑的是另一个函数"排查很久。
两个插件之间**不冲突**——命令表是每个插件一份（`api/mod.rs:119-121` 存进
registry 的 `nota_commands`）。

**回调被调用时**：`f.call::<Value>(args)`（`lua/mod.rs:359-374`）——
**就一个参数**，且**返回值会被序列化回前端**（§0.5 的规则）。
回调里抛错 → 宿主裹成 `Lua 出错（插件 {id}）：{message}`。

⚠️ **注册时机**：任何时刻都行（包括 chunk 顶层），但只在 `on_load` 里注册最稳——
`on_load` 一抛错整个插件就判失败，那时注册过的命令也调不到（`docs/11` §5.4）。

⚠️ **前端调命令时必须给 `plugin` 参数**（注册者的 id）：命令名只在**插件内部**唯一。
凭命令名推测是哪个插件的，两个插件重名时就会**静默调到另一个插件**（`docs/11` §7）。

## 4. `nota.event.emit(name, payload)`（永远可用）

```lua
nota.event.emit("git:status", { is_repo = true, branch = "main", entries = {} })
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `name` | string | 事件名，**后半段由插件自定** |
| `payload` | 任意 Lua 值 | 走 `lua_to_json`（§0.5） |

**返回值**：无。
**失败**：抛错，原文 `发事件 {channel} 失败：{e}`（`api/mod.rs:183`）。

### 4.1 ⚠️ 通道名 = `plugin:<归一化 id>:<name>`

```rust
let channel = format!("plugin:{plugin_id}:{name}");   // api/mod.rs:180
```

其中 `plugin_id` 不是清单里的原样字符串，而是过了 `channel_id()`
（`manifest.rs:251-261`）的版本：**非字母数字字符（`-` 与 `_` 除外）映射成 `-`**。
所以：

| 清单里的 id | 事件名的前缀 |
|---|---|
| `nota.git` | `plugin:nota-git:` |
| `my_plugin` | `plugin:my-plugin:` |
| `git` | `plugin:git:` |

⚠️ **为什么必须归一化**：Tauri 的事件名**不认点号**（只允许字母数字和
`-` / `/` / `:` / `_`），原样发出去会得到一句
`only alphanumeric, '-', '/', ':', '_' permitted for event names`。
这就是 **BUG-3** 的现场——它属于"**加载成功、静默失效**"那一类：
插件列表里一切正常，错误只在第一次发事件时出现（`docs/07` §2 的教训）。

⚠️ **归一化会带来撞名**：`nota.git` 与 `nota-git` 两个都合法的 id 占同一个通道，
所以 `discover()` 会把后到的那个**直接判为加载失败**（`docs/11` §1.4）。

### 4.2 ⚠️⚠️ 前端**目前没有在听**插件频道

宿主自己的事件只有两个，都在前端的事件表里（`src/bridge/ipc.ts:199-202`）：

| 键 | 事件名 |
|---|---|
| `notify` | `nota:notify` |
| `documentChanged` | `nota:document-changed` |

⚠️ **曾经是四个**，另外两个是 `nota:plugin-panel` / `nota:plugin-menu`——
那两条**是错的，已经删掉**（BUG-13）：面板与菜单是**声明（状态）**，
注册发生在插件加载时、订阅发生在挂载之后，**推必漏**。它们现在走 registry 被**拉**
（§8.2 / §8.3）。**判据：声明是状态 → 拉；发生是事件 → 推。**

**插件发的 `plugin:<id>:<名字>` 一条都不在里面。** 也就是说：
`nota.event.emit` 今天**发得出去、没人收**——不报错，什么都没发生。

⚠️ 这不是"用错了"，是**接线的另一头还没做**（backlog 第 17 项）。
⚠️ **注意第 17 项的结论和第 16/38 项不一样**：那两项讲的是"**声明类**走错了通道"
（已修），本条讲的是"**数据类**事件没人消费"——`plugin:<id>:<name>` 这条通道
对**发生类**数据**是正解**，缺的只是前端那边的订阅端。
**不能把结论推广成"事件机制不该用"。**

`plugins/ai/main.lua:26-32` 就是照这个现状写的：它想靠事件问 git 插件要 diff，
注释里写着"本轮先直接返回 nil，让调用方回退到全文"。
**所以写插件时不要把逻辑押在"对面收到事件了"上。**

### 4.3 方向只有一个

`nota.event` 只有 **`emit`** 这一个函数：**插件 → 前端**。
**前端 → 插件**那条路走**命令**（§3），两条路各管一头，不可混同（`api/mod.rs:143-147`）。

## 5. `nota.document`（需 `document.read` 或 `document.write`）

⚠️ 两层判断：**表**要 `read | write`（`api/mod.rs:94`）；
**表里的成员**各自再判（`document.rs` 里判读、判写各一个 `if`）。
所以只申请 `document.read` 的插件拿到的 `nota.document` 上**没有** `set_text` 这一个成员。

⚠️ **写不只是「改镜像」**（2026-10-04，第 14 项起）：`set_text` / `append_text` 是
**整篇替换**（改后端镜像 ＋ 发 `nota:document-changed`），而 `insert_at_cursor`
**一个字节的镜像都不改**——它发的是**编辑意图** `nota:document-edit`，
落地的人是前端编辑器。两条路为什么必须分开、以及为什么不能给插件偏移量，
见 `docs/05` §5.2b。

### 5.1 读（`document.read`）

| 函数 | 返回 | 没有活动文档时 |
|---|---|---|
| `nota.document.get_text()` | string | **`""`**（`document.rs:32-37`） |
| `nota.document.get_path()` | string \| **nil** | **`nil`**（`document.rs:42-47`） |
| `nota.document.get_title()` | string | **`""`**（`document.rs:51-56`） |
| `nota.document.get_revision()` | integer | **`0`**（`document.rs:60-65`） |
| `nota.document.is_dirty()` | boolean | **`false`**（`document.rs:69-74`） |
| `nota.document.stats()` | table | 一份**空文档**的快照：`chars=0` / `words=0` / `lines=0` / `revision=0` / `path=nil`（⚠️ `clock_ms` **照给**，见下） |
| `nota.document.get_selection()` | table \| **nil** | **`nil`**（⚠️ 与上面几条**不一样**，见下） |

⚠️ **`get_selection()` 的 `nil` 与上面那几个「空值」不是同一样东西**：
* `nil` ＝ **我不知道**——没有活动文档，**或者**编辑器还没报过（刚打开、正没挂编辑器）；
* `{ text = ""; empty = true }` ＝ 我知道，光标是个点、没选东西；
* `{ text = ""; empty = false }` ＝ 我知道，选中了一个**原子**（图片、公式）。

⚠️ 所以**别用 `text == ""` 代替 `empty`**：后两种情况的 `text` 都是空的，
靠 `text` 分不开，而它们该走的代码路正好相反。⚠️ `nil` 与空表也**不能混**——
糊成一种，插件就没法决定「要不要退回 `get_text()` 自己算」。

⚠️ **读一律不抛错**：没有活动文档时给"空"而不是报错。这是刻意的——
"问一个现在没法回答的问题"和"越权"是两回事，前者不该让插件抛错，
否则 `on_load` 里查一下状态就会变成"插件加载失败"（与 §7.3 同一个教训）。

⚠️ **`revision` 是干什么的**：一个单调递增的整数，`sync()` 里**只有文本真的变了**才
`+1`（`document/mod.rs:220-230`）。插件靠它判断"上次看到的还是不是现在这份"。
⚠️ 它**不是**文档的全局版本号，是这份文档自己的。

⚠️ **`stats()` 是给"要算速度"的插件加的**（2026-09-26，第一个用户是
`plugins/stats`）。它一次给六样：

| 字段 | 是什么 | 空文档时 |
|---|---|---|
| `chars` | **码点数**（`chars()`），与状态栏那个「N 字符」同一个口径（前端是 `[...text].length`） | `0` |
| `words` | **「字/词」数**（2026-09-27 加）：**中文一个字算 1 ＋ 一段连续的英文/数字算 1 个词**（`document.rs::词数`） | `0` |
| `lines` | `split('\n')` 的段数 | **`0`**（⚠️ 不是 1——空文档没有行） |
| `revision` | 同 `get_revision` | `0` |
| `path` | 同 `get_path` | `nil` |
| `clock_ms` | 自 Nota 启动起算的毫秒 | **照给**（它是进程时钟，与有没有文档无关） |

⚠️ **`clock_ms` 是这六个里唯一"本来拿不到"的东西**：沙箱里**没有 `os`**
（`lua/mod.rs` 的硬化名单抹掉了），所以插件此前拿不到**任何形式的时间**——
这也正是 `docs/13` §13.3a 里"探针结论有缓存、而插件自己顶不掉"那条的由来。
补一条 `stats()`，而**不是**给沙箱开一个 `os.time`：开了 `os` 就同时开出
`os.exit` 和 `os.execute`（`docs/12` §6 那张表），代价远不止一个时间戳。

⚠️ 它是**单调时钟**（`Instant` 出身），**不是墙上时间**：插件要的从来只是
"两次之间差了多少"，而墙钟会被对表、时区、夏令时拨来拨去（差值甚至能是负的，
画出来的曲线会往回跑）。名字刻意**不叫 `now`**——那会让人以为能拿去显示"现在几点"。
⚠️ 起点是 `OnceLock` 里的**全进程唯一一份**（每次现取 `Instant::now` 当零点，
两次调用减出来的差值毫无意义）。

⚠️ 数的是**后端这份镜像**（前端 `nota_doc_sync` 推上来的那一份），不是磁盘上的文件；
而且前端那条路有 **500ms 防抖**，所以这个数最多落后半秒。对"每秒采样一次"够用，
但别拿它当"用户此刻敲到了第几个字"。

### 5.1a `chars` 与 `words` 是两件事（2026-09-27）

⚠️ **为什么会有第二个长度字段**：用户那天点名「**注意，如果是英文的话要统计词**」
——`chars` 那条口径对中文是对的、对英文是**错的**：`hello` 是 5 个「字」，
写一句英文的读数虚高四五倍，而"字/分钟"是要拿给人看的。

`words` 的规则**故意只有一条**（没有分词器、没有词典、不数 token——用户明确说
「如果 token 拆分器写的代码量太多的话就不用了」）：

| 输入的一段 | 算几 |
|---|---|
| 连续的 ASCII 字母/数字（`hello` / `Nota2`） | **1** |
| 其中的 ASCII 撇号不断词（`don't`） | **1**（不是 2） |
| 其余**非空白**字符（汉字、全角标点、emoji） | 各 **1** |
| ASCII 标点与空白 | **0**（`Hello, world!` 是 **2**） |

⚠️ **已知的三处不精确**（故意的，改之前先看 `document.rs::词数` 顶上那段）：
连字符**断词**（`well-known` 算 2）／破折号与弯引号这类**非 ASCII 标点算 1**／
不认代码与 URL（`https://a.b/c` 会拆成好几个词）。

⚠️ **`chars` 没有删**：它仍是"码点数"这个量的唯一来源（`plugins/stats` 换成
`words` 之后暂时没有别的消费者，但它是通用量，不是给某一个插件开的专用口子）。
⚠️ **两者不要混着展示**：同一块界面上要么全是「字/词」、要么全是「N 字符」。


⚠️ **BUG-6：`get_text()` 给的"活动文档"可能与用户正在看的那份不是同一个**。
切标签时前端只 `setActiveId(id)`，从不调 `api.doc.setActive`，于是后端的活动文档
只被 `new` / `open` / `close` 改过。**后果对插件是实的**：用户点着标签 A 在看 A，
`nota.document.get_text()` 返回的是**最后一次新建/打开的那份**——
AI 助手按这个路径写回就会**改错文档**。写会改文档的插件之前需要先读 `docs/07` BUG-6。

### 5.2 写（`document.write`）

| 函数 | 参数 | 返回 | 失败 |
|---|---|---|---|
| `nota.document.set_text(text)` | string | 无 | 没有活动文档 → **抛** `没有活动文档` |
| `nota.document.append_text(tail)` | string | 无 | 同上 |
| `nota.document.insert_at_cursor(text)` | string | **boolean** | **不抛**（发不出去时返 `false`，见下） |

**副作用（`set_text` / `append_text` 两个才有）**：改完后端镜像 → 发一条
`nota:document-changed`（`document.rs::emit_changed`）：

```json
{ "id": <文档 id>, "text": "<改完之后的全文>", "origin": "plugin" }
```

⚠️ 事件名与宿主自己发的**完全一致**（`origin` 字段用来区分是谁改的）。
**前端不必区分**——都是"后端这份和前端不一致了，来取"（`document.rs:120-123`）。

⚠️ **`set_text` 是整篇替换语义**：撤销栈断掉、光标跳走、表格列宽之类的排版状态全丢。
⚠️ 「在光标处插一段」**现在有一条正经路**（第 14 项，2026-10-04）：
`nota.document.insert_at_cursor(text)`。它**不改镜像**，只发一条编辑意图
（`nota:document-edit`），由前端用**一笔真 ProseMirror 事务**落地——
撤销栈、光标、滚动位置全都活着。

⚠️ 但**插件依然拿不到光标偏移量**，这是**故意**的：Markdown 字符偏移这个坐标系
在块边界上**不存在**（在列表项开头插字会多出 `- `、两段之间插字会多出空行），
给了就一定会被拿去拼错。量测钉在 `tests/caret-snapshot.test.ts` 第三组，
设计说明在 `docs/05` §5.2b。**想改正文就交意图，别自己拼字符串。**

⚠️ **除了「插一段」，别的都还没有**：替换选区、包围选区、按偏移删除都没有——
`op` 字段给以后留着（前端遇到不认识的 `op` 会**丢掉**，不会拿 `text` 硬当插入）。
`plugins/ai/main.lua:108-116` 那种"读全文自己拼再 `set_text`"的写法在
**整篇替换**的场合仍然是对的（追加模式先看末字符是不是 `\n`，再决定补几个空行），
只是不该拿它做"在光标处插一句"。

⚠️ **`sync()` 里有一步值得知道**：它会把标题重新从正文里推一遍
（`document/mod.rs:228` 调 `derive_title`），并且把 `dirty` 置 `true`。
所以插件写一次文档，**标签页标题可能跟着变**（正文里第一个 `# ` 标题变了的场合）。

⚠️ **`append_text` 的实现是"读全文 + `push_str` + `sync`"**（`document.rs:100-113`），
不是真正的追加。文档大时它每次都是 O(全文)。

## 6. `nota.fs`（需 `fs.read` 或 `fs.write`）

⚠️ 表要 `fs.read | fs.write`（`api/mod.rs:94`）；`read` / `exists` / `list` 归
`fs.read`，`write` / `remove` 归 `fs.write`（`fs.rs:27-28` 起的两个 `if`）。

### 6.1 ⭐ 围栏：这是宿主**唯一**的安全边界

`fs.rs:1-14` 的文件头写得很直接："**这是本仓唯一一处安全边界，不能只靠'看着对'**"。
裁决全在 `resolve_in(root, given)`（`fs.rs:117-167`）——**纯函数、不依赖 Tauri**，
所以它有 5 个单元测试（`fs.rs:169-233`）。

**三步，缺一不可**：

| 步 | 做什么 | 拒掉的错误原文 |
|---|---|---|
| ① | **必须是相对路径**。绝对路径一律拒 | `nota.fs 只接受工作区内的相对路径，收到绝对路径 \`{given}\`` |
| ② | **`..` 在交给文件系统之前**按段算掉（只用 `canonicalize` 挡不住"写新文件"那条路）；`..` 弹出栈底还多就说明跑了出去 | `路径 \`{given}\` 跑到工作区外面去了` |
| ③ | **再比一次规范化结果**，防符号链接。文件还不存在（新建）就退而比**父目录** | `路径 \`{given}\` 经符号链接指向了工作区外面` |

（②③ 的分工：② 管"还没存在"的路径，③ 管"已经存在、但中间某段是软链"的路径。
`fs.rs:6-8` 解释了为什么必须有 ②：不加的话 `fs.write("../../.bashrc", …)`
正好从"文件不存在"这个缝里溜出去。）

**没有打开工作区时**：

```lua
nota.fs.read("a.md")
-- 抛：没有打开工作区，nota.fs 不可用
```

（`fs.rs:104-108`。⚠️ 注意是**一律拒绝**、不是放开——放开会让
"没开文件夹"变成一条**绕过围栏的路**，见 `fs.rs:10-11`。）

5 个用例钉住的就是这四条：`普通相对路径能过`、`点开头的清除掉但不越界`、
`绝对路径直接拒`、`用点点爬出去要拒`（含"里面绕一圈是合法的"）、
`符号链接指向外面要拒`。

### 6.2 函数

| 函数 | 能力 | 返回 | 失败 |
|---|---|---|---|
| `nota.fs.read(path)` | `fs.read` | string（文件全文） | 路径裁决不过 → 抛（§6.1 的三句之一）；读不到 / 不是合法 UTF-8 → 抛 `读文件失败 {path}：{source}` |
| `nota.fs.exists(path)` | `fs.read` | boolean | ⚠️ **路径裁决先跑**：越界照样抛错，不会返回 `false` |
| `nota.fs.list(path)` | `fs.read` | **已排序**的 string 数组 | 不是目录 / 读不到 → 抛 `读文件失败 {path}：{source}` |
| `nota.fs.write(path, text)` | `fs.write` | 无 | **会自动建父目录**（`fs.rs:79-82` 调 `ensure_dir`）；写不了 → 抛 `写文件失败 {path}：{source}` |
| `nota.fs.remove(path)` | `fs.write` | 无 | 删不了 → 抛 `写文件失败 {path}：{source}` |

⚠️ **`list` 的排序是 Rust 的字节序**（`fs.rs:67` 的 `out.sort()`），
对中文名就是 UTF-8 字节序（≈ 码位序），不是拼音。**不要假定"目录在前"**——
它把文件和目录**混在一起**排，也不说明哪个是目录。

⚠️ **`remove` 只删文件**（`std::fs::remove_file`，`fs.rs:93`）：给一个目录会失败，
而且**没有递归删除**。⚠️ 删掉就是删掉了，**没有回收站**——
这是 `fs.write` 那条"授予它 = 信任插件做破坏性操作"的实处（`docs/11` §3.2）。

⚠️ **没有的**：`mkdir`（`write` 会一并建父目录，这是唯一建目录的路径）、
`rename`、`copy`、读目录树。要这些得走 `nota.git`（如果确实是仓库里的操作）
或者等后续轮次。

### 6.3 ⚠️⚠️ 这道围栏只管走 `nota.fs` 的调用——但**别的刀已经在 2026-09-22 收走了**

**先说现在（2026-09-22 起）**：插件的 Lua 状态里**没有** `io` / `os` / `package` /
`loadfile` / `dofile` / `debug`，所以"用 `io.open` 绕过围栏"这条路
**已经不通了**。§6.1 这套裁决**现在是插件真正的文件系统权限边界**。

⚠️ `require` 是这一串里**唯一**在 2026-09-27 被补回来的（插件多文件，§0.7），
但它**只在本插件目录里找 `.lua`**：读不到 `/etc/shadow`、也走不出自己的目录。
所以上面那句话仍然成立——**绕围栏的那条路还是不通**，变的是"插件可以有几个
源文件"。

**再说这条为什么曾经是假的**（留着当教训）：mlua 的 `Lua::new()` 号称"安全子集"，
实际只等于"不能加载 C 模块"——`io` / `os` / `package` **全都在**。所以在那之前，
一个只申请了 `ui.notify` 的插件照样能 `io.open("/etc/passwd")`、`os.execute("rm -rf ~")`，
§6.1 那套裁决只是**对走 `nota.fs` 的调用所做的约束**，不代表插件没有别的途径。

⚠️ 这条的完整实测证据与机制见 `docs/12` §5，缺陷编号是 `docs/07` BUG-10。
**写插件的人只需要知道结论**：要碰文件就申请 `fs.read` / `fs.write`，
**没有旁路**；想"绕过围栏读取"是做不到的。

## 7. `nota.git`（需 `process.git`）

单层判据：`manifest.has(Capability::ProcessGit)` → `nota.git` 整张表（`api/mod.rs:98`）。

### 7.1 围栏三条

| # | 内容 | 在哪 |
|---|---|---|
| 1 | **只能起 `git` 这一个进程**，不是通用 subprocess | `git.rs:18`、`git.rs:166-167` |
| 2 | **工作目录锁死**：优先工作区根，没开工作区就退到**活动文档所在目录** | `挑工作目录()`（`git.rs:230-237`）+ `working_dir()`（`git.rs:212-223`） |
| 3 | **拒绝会重定向目标目录的参数**：`-C` / `--git-dir` / `--work-tree` / `--namespace`，**等号写法也拒** | `禁止的参数`（`git.rs:53`）、`run_git()` 开头（`git.rs:171-186`） |

第 3 条的必要性写在 `git.rs:22-23`：**只锁 cwd 是不够的**——
`git -C /elsewhere` 一句话就把 cwd 绕过去了。

⚠️ **已知边界（不是漏洞，是记录，`git.rs:25-27`）**：`git config --global`
这类会写用户**全局配置**的子命令**挡不住**，因为参数层面分不清它跟合法的
`git config --get`。所以 `process.git` 的实际含义是
**"能对本机做 git 能做的事"**，装插件时该按这个尺度信任。

**每次运行都设的环境变量**（`git.rs:192-194`），为的是不让交互式提示把界面卡死：

| 变量 | 值 |
|---|---|
| `GIT_TERMINAL_PROMPT` | `0` |
| `GIT_PAGER` | `cat` |
| `GIT_EDITOR` | `true` |

### 7.2 ⭐ 两种失败必须分开

**这是本节最要紧的一张表。** 同一个 `nota.git`，失败分两类，
**一类抛错、一类返回结果表**（`git.rs:29-41`）：

| 哪一类 | 什么时候 | 行为 |
|---|---|---|
| **调用错误**（插件写错了） | 传了 `-C` / `--git-dir` / `--work-tree` / `--namespace`（含 `--git-dir=/x` 写法）；参数不是字符串 | **抛 Lua 错误**，原文见下 |
| **环境未满足**（环境不具备） | 没开工作区**且**没有活动文档的目录；没装 `git` | **正常返回结果表**：原因在 `stderr`，`code` 非零 |

调用错误的原文（`git.rs:174-184`、`git.rs:247-251`）：

| 情况 | 原文 |
|---|---|
| 传了禁止的参数 | `nota.git 不接受 \`{arg}\`：它会把操作目标改到工作区之外` |
| `--git-dir=/x` 写法 | `nota.git 不接受 \`{head}=…\`：它会把操作目标改到工作区之外` |
| 参数不是字符串 | `nota.git.run 的参数只能是字符串，收到 {type_name}` |

⚠️ **为什么必须分开**（`git.rs:33-37`）：
调用错误是**插件作者**的问题，必须让他看见，**不能让它伪装成一次正常的 git 运行**；
而"这个目录不是 git 仓库"与"`git status` 在不存在的仓库里失败"是**同一类事**，
插件的处理方式也该是同一种。

### 7.3 ⚠️ 不分开会出真事（BUG-2 的现场）

`working_dir()` **曾经**对"没有工作目录"直接 `Err`。而 git 插件的 `on_load` 结尾
要刷一次状态——于是**"用户还没打开文件夹"被显示成"这个插件加载失败"**：
侧栏里赫然一行「失败」，而插件本身没有任何写错的地方。

修法是两头：

| 头 | 做了什么 |
|---|---|
| **宿主** | `挑工作目录()` 返回 `Err(String)` 而不是抛错，由调用方折成一张结果表（`git.rs:225-237`）。那条用例就叫 `两个都没有是环境不具备不是插件坏`（`git.rs:301-308`） |
| **插件** | `plugins/git/main.lua:189-192` 再包一层 `pcall` + `nota.log.warn`——注释里写明这是**刻意的**：为了"将来宿主新加的任何一种环境失败"都不会再变成一次误判 |

### 7.4 六个函数与**返回表的键名**（⚠️ 有一个坑）

| 函数 | 参数 | 返回表 |
|---|---|---|
| `nota.git.run(argv)` | **string 数组**（Lua 数组，位置参数） | `{ code, stdout, stderr, ok }` |
| `nota.git.status()` | 无 | `{ code, raw, stderr }` |
| `nota.git.parse_status(raw)` | `status()` 给的那串 `raw` | `{ branch, entries = { { index, work, path, orig?, state } … } }` |
| `nota.git.log_graph(n)` | 行数上限（可选，默认 60，夹在 1–200） | `{ code, ok, stderr, rows = { { art, hash?, parent?, refs?, subject? } … } }` |
| `nota.git.diff(staged)` | `staged`：`true` 就加 `--cached`（可选，默认 `false`） | `{ code, text, stderr }` |
| `nota.git.repo_root()` | 无 | **string**（仓库根绝对路径）或 **`nil`** |

`status` 与 `diff` 实际跑的 argv：

```rust
["status", "--porcelain=v1", "-z", "-b"]        // git.rs:89
["diff", "--no-color"] (+ "--cached")           // git.rs:107-110
["rev-parse", "--show-toplevel"]                // git.rs:128
```

⚠️ `--porcelain=v1 -z` 是**给程序读的稳定格式**（不做颜色、不做分页）。
`-z` 的分隔符是 **NUL 而不是换行**（这样路径里能有空格和换行），
按 NUL 切完还要注意**重命名/复制会多跟一个路径**。

⚠️⚠️ **2026-09-26 起，切这两份文本的活儿在宿主里，不在插件里**：

| 函数 | 它替插件做的 | 为什么不让插件做 |
|---|---|---|
| `parse_status(raw)` | 按 NUL 切、认出重命名多吃一段、按 `index` / `work` 两个字符**归类** | 归类是"这四个词各是什么意思"的判据源，而**话术**（`已暂存` / `已修改`）才是插件的事 |
| `log_graph(n)` | 跑 `git log --graph`、切图线与字段、认出连接线行、取第一个父提交 | 格式串与解析是**一对**（见 `git.rs` 里 `图格式`），分开写就会漂；而且这两件事都能用单元测试按死 |

于是 `plugins/git/main.lua` 里从前的 `parse_status` / `get_log` / `split_row`
**都删了**，调用点改成一行 `nota.git.parse_status(r.raw)`。
这就是"Lua 插件拆不开（没有 `require`）＋ 1000 行上限"撞在一起时的出路：
**该由宿主做的事搬回宿主**（`docs/11` §变量名那条讲的是另一半）。

**四类状态，一个字都不许自己编**（`state` 字段就这四个值，
归类判据在 `git.rs::归类`，词与颜色在插件的 `STATES` 表）：

| `state` | 什么时候 | 插件那张表里的词 / 语气 |
|---|---|---|
| `untracked` | `??` | `未跟踪` / `muted` |
| `staged` | 只有 `index` 那一列有字 | `已暂存` / `success` |
| `staged-dirty` | `index` 和 `work` 两列都有字 | `已暂存且有新改动` / `warn` |
| `modified` | 只有 `work` 那一列有字 | `已修改` / `warn` |

⚠️ `entries` 是 **Lua 数组**（下标从 **1** 起，`ipairs` / `#` 按这个算）；
`orig` 那条**只有重命名/复制才有这个键**（没有时是 `nil`，
插件里正好写 `e.orig and T("原名：%s", e.orig) or ""`）。
⚠️ **别拿 `state` 当"工作区/暂存区"两个布尔用**：它已经把两列压成四种情况了。

`log_graph` 的 `rows` 也是 Lua 数组，一行一项：

| 键 | 有谁有 | 说明 |
|---|---|---|
| `art` | 全都有 | 左边那截图线，**原样字符串**（空格是画图的一部分，别 `trim`） |
| `hash` | 只有提交行 | ⚠️ **没有这个键 = 这是一条纯连接线行**（图上那两个字符什么提交都不是）。判据是"有没有 `hash`"，不是"字是不是空的" |
| `parent` | 提交行 | **第一个父提交**的短哈希；**根提交是空串 `""`**，不是缺字段 |
| `refs` | 提交行 | 分支/标签标签，**两头的括号和空格已经被去掉**（`HEAD -> main`） |
| `subject` | 提交行 | 提交标题 |

⚠️ 合并提交的键通向**第一个父**（`parent` 就是它），
"它和另一个父之间改了什么"这条路由**不存在**——要那个得 `run({ "diff", A, B })` 自己拼。
⚠️ **方向要插件自己理正**：`git log` 是**从新到旧**排的，直接拿
"先点的那颗 → 后点的那颗"去跑 `git diff A B`，"红 = 删"就会有一半是假的。
`plugins/git/main.lua::set_compared` 用 `git merge-base --is-ancestor` 判完再把顺序摆正，
那是这个判据的唯一一处。

⚠️⚠️ **注意：`ok` 这个键不是每张表都有。** 结果表的构造点不一样：

| 谁 | `code` | 取文本的键 | `stderr` | **`ok`** |
|---|---|---|---|---|
| `run` 成功 | 进程退出码 | `stdout` | ✅ | ✅ `code == 0` |
| `status` 成功 | 进程退出码 | `raw` | ✅ | ❌ **没有这个键** |
| `diff` 成功 | 进程退出码 | `text` | ✅ | ❌ **没有这个键** |
| `log_graph` | 进程退出码 | `rows` | ✅ | ✅ `code == 0` |
| `parse_status` | **没有 `code`** | `entries` / `branch` | — | — |
| 上面几个「没有工作目录」 | **`-1`** | 各自那个键 = **`""`**（`parse_status` 除外：它不碰 git，没有这条） | ✅ 原因 | ✅ `false` |

（`git.rs:69-74` / `:91-95` / `:112-116` / `没有工作目录的结果()` `:146-157`。）

**所以判断失败一律用 `r.code ~= 0`，不用 `r.ok`。**
在 `status()` / `diff()` 成功的那条路上 `r.ok` 是 **`nil`**（假值），
写 `if r.ok then` 会把"成功"判成"失败"。

⚠️ `parse_status` 是**唯一的纯函数**（一段文本进、一张表出，不碰 git 也不碰磁盘），
所以它**没有失败这一说**，也就没有 `code` / `ok` / `stderr` 三个键——
它和 `nota.diff` 那张表是同一类（§11.2）。

⚠️ 现状的实证：`plugins/git/main.lua` 里判失败用的是 `r.code`
（`refresh` / `review_blocks` / `panel_content` / `commit` / `init_repo` / `set_identity`
等处），写 `r.ok` 的两处都是**亲手给全了 `ok` 的那两张表**
（`run_diff` 的 `nota.git.run`、`graph_blocks` 的 `nota.git.log_graph`）。
所以这个注意点**今天没有触发**。它是那种"下一个人按习惯写 `if r.ok` 就会出错"的注意点。

⚠️ **「没有工作目录」的结果表为什么要把空串给全**（`git.rs:141-145`）：
插件拿到的表要长得**跟成功时一样**，少一个键会让 Lua 那边在 `..` 拼接时失败于
`attempt to concatenate a nil value`——**那才是把环境问题伪装成插件 bug 的做法**。

⚠️ `repo_root()` 是唯一一个"拿不到就给 `nil`"的：工作目录未知、
或者 `rev-parse` 非零（不是仓库）都返回 `nil`，**不抛错**（`git.rs:122-134`）。
所以 `plugins/git/main.lua:159-161` 直接 `return { path = nota.git.repo_root() }`——
`path` 可能是 `nil`，前端要能接住。

⚠️ **`repo_root()` 返回的是 `stdout.trim()` 过的**（`git.rs:132`），
其余三个函数的文本**都是原样、没有 trim**。

## 8. `nota.ui`（需 `ui.notify` / `ui.panel` / `ui.menu` 中**任意一个**）

这张表一共有五个成员：`notify`（§8.1）· `register_panel`（§8.2）· `register_menu`（§8.3）
· **`refresh` 与 `review`**（同归 `ui.panel`，§8.6）。

### 8.1 `nota.ui.notify(msg, level)` —— 需 `ui.notify`

| 参数 | 类型 | 说明 |
|---|---|---|
| `msg` | string | 必填 |
| `level` | string（可选） | 归一化，见下 |

**返回值**：无。**失败**：发事件失败 → 抛 `发通知失败：{e}`（`ui.rs:48`）。

**`level` 归一化表**（`normalise_level()`，`ui.rs:188-201`）：

| 传进去 | 得到的 |
|---|---|
| `"warn"` 或 `"warning"` | `warn` |
| `"error"` | `error` |
| `"success"` | `success` |
| **其它任何东西**（含 `nil`、拼错的词） | `info` |

⚠️ **认不出的一律当 `info`，不报错**——这是刻意的（`ui.rs:186-187`）：
"别把插件的笔误变成一次报错，那会让人为了一个无关紧要的通知层级去读栈"。

**发出去的事件**（`ui.rs:38-52`）：`nota:notify` —— **这是 `nota.ui` 三条里唯一推事件的**

```json
{ "plugin": "nota.git", "message": "已提交", "level": "success" }
```

⚠️ `plugin` 字段是**清单里的原样 id**（不归一化——归一化只用在**事件名**上）。

⚠️⚠️ **它是「推」的，所以存在时序竞争**：在 `on_load` 里调 `notify`，
那一刻 WebView 还没起来，**这条提示会静默丢掉**（Tauri 的 `emit`
对没有监听者的频道是成功返回的）。想报"插件已加载"这类话，用 `nota.log.info`。

### 8.2 `nota.ui.register_panel(spec)` —— 需 `ui.panel`

```lua
nota.ui.register_panel({
  id = "git", title = "Git", location = "right",
  render = function() return { { kind = "text", text = "现在是这样" } } end,
})
```

| `spec` 字段 | 必填？ | 默认 | 说明 |
|---|---|---|---|
| `id` | **必填** | — | 缺 → 抛 `register_panel 需要 \`id\` 字段` |
| `title` | 可选 | **`id`** | 侧栏上显示的名字 |
| `icon` | 可选 | `nil` | |
| `location` | 可选 | **`"right"`** | `"right"` = 右侧插件栏；**别的值不会报错**，但那块面板会落进右栏的「没有落脚处」那一组（用来把"声明的面板没人要"摆出来） |
| `render` | 可选 | `nil` | **不写就是一块空面板**。写了就是一个**每次拉都现调**的函数，返回一串内容块（§8.5） |
| `wide` | 可选 | `false` | `true` → 这一页摊到**编辑区**里时占得宽（`nota.ui.review`，§8.6）。⚠️ **只管摊到编辑区那一处**：插件栏里那 260px 宽的页签不看这个值。给"预览"这类要留画面地方的面板用（`plugins/slidev`） |
| `live` | 可选 | `false` | `true` → 宿主**每秒**喊一次"该重拉了"，也就是这一页的 `render` **每秒跑一遍**（`heartbeat.rs`，`docs/12` §4.7a）。给"要跟着时间动"的面板用（`plugins/stats`） |

⚠️ **`render` 是"现跑"，不是"加载时算一次"**——它是个函数，不是一张表，
宿主每次要面板内容都重调一遍（`ui.rs` 的 `面板内容()`，有用例钉着这条）。
所以里面必须是**此刻**的状态：该问 git 就问 git，该读设置就读设置。
把结果缓存到一个 `local` 里再返回它，症状是"面板显示的是几分钟前的东西，
而且看着像是对的"——两份内置插件都在文件头把这条写死了。

⚠️ **`live` 只影响 `render` 被拉的频率，它不改变任何别的语义**。宿主那边只有
**一个**每秒的心跳线程，而且它**只喊 `live` 的那些页**——不筛的话 git 那块面板
会一秒起一个子进程（`docs/12` §4.6）。三条代价一并记着：

1. **`render` 里的东西会每秒跑一遍。** `plugins/stats` 里跑的是几次加减乘除
   （全在内存里），所以无所谓；哪天要往 `render` 里加一次子进程或网络请求，
   先回头看这一行。
2. **它在 `plugins` 锁里跑**（`docs/12` §4.7a），所以越短越好——
   它每慢一秒，别处就多等一秒。
3. ⚠️⚠️ **它不是一个 timer。** 插件仍然收不到宿主事件，仍然没有自己的时间；
   "现在过了多久"只能从 `nota.document.stats().clock_ms` 拿（§5.1），
   **不能靠"每次加 1"数出来**——没有任何东西保证"正好一秒"。

**返回值**：无。**失败**：缺 `id` → 抛（上表）；**`id` 与本插件已声明的重名 → 抛**
`插件 {id} 重复注册面板 \`{id}\``。

⚠️⚠️ **它不发事件，它写 registry（BUG-13）。** `register_panel` / `register_menu`
走的是「**声明是状态 → 拉**」：内容写进 Lua registry 的 `nota_panels`，
前端挂载后调 `nota_plugin_panels` **拉**一次。原先那两条事件
（`nota:plugin-panel` / `nota:plugin-menu`）**已经删掉了**——

**为什么必须是这样**：注册发生在**插件加载时**（`setup()` 阶段），
前端订阅发生在**挂载之后**。推的话必然漏，且**漏得静默**——
界面显示正常，只是永远空着，日志里没有任何痕迹。
判据一句话：**需要靠"幂等"或"重放"来兜底的设计，通常意味着状态被存了两份。**
（本仓真按"记账 + 重放"写过一版，落地时被推翻，见 `docs/07` BUG-13。）

⚠️ **`id` 重复注册会当场报错，不是静默覆盖。** 理由同 `nota.command.register`：
多半是复制粘贴改漏了，静默覆盖会让人对着"点下去跑的是另一个函数"排查很久；
面板这边还多一层——重名会让前端两张卡片抢同一个 key。
（⚠️ 这条 2026-09-22 之前的行为是**反的**，那时文档写着"重复注册不报错"。）

### 8.3 `nota.ui.register_menu(spec)` —— 需 `ui.menu`

```lua
nota.ui.register_menu({ label = "提交…", command = "commit", menu = "plugins" })
```

| `spec` 字段 | 必填？ | 默认 | 说明 |
|---|---|---|---|
| `label` | **必填** | — | 缺 → 抛 `register_menu 需要 \`label\` 字段`。**也是重名的判据**（同一个 `label` 注册两次 → 抛） |
| `command` | **必填** | — | 缺 → 抛 `register_menu 需要 \`command\` 字段`。**必须是本插件注册过的命令名**——前端点下去时按这个名回调宿主，宿主再找插件要 |
| `menu` | 可选 | **`"plugins"`** | 放到哪个菜单下。⚠️ **目前只认 `"plugins"`**，见下 |
| `accelerator` | 可选 | `nil` | 快捷键，写法同内置菜单（`"Ctrl+Shift+K"`） |
| `prompt` | 可选 | `nil` | 点击后先询问一次，同 §8.5 那张表（**字段完全一样**） |

**返回值**：无。**失败**：缺字段 → 抛（上表）；`label` 重复 → 抛
`插件 {id} 重复注册菜单 \`{label}\``。

**和 `register_panel` 一样写 registry —— 不发事件（BUG-13）**，
落在 `nota_menus`，由 `nota_plugin_menus` 拉。

**✅ 2026-09-24 接进菜单栏了**（`docs/07` 第 42 项）：拉回来的条目合成
**一栏「插件」**，插在「帮助」前面。合成与摆放的规则在
`src/ui/pluginMenus.ts`（含"`menu` 写别的值怎么办"），要点三条：

| 事 | 规矩 |
|---|---|
| `menu = "plugins"` | 进「插件」栏 |
| `menu` 写别的值 | **不静默丢掉**：照样摆进「插件」栏，标签后缀「（想挂到「X」栏，暂不支持）」，**而且是灰的** |
| 灰不灰的判据 | 就一条：`App.tsx` 的 `menuHandlers` 里有没有它的 id。**没有 = 灰**——不为插件单开第二条判据 |

⚠️ **键位冲突的处理**：`accelerator` 走的是内置菜单**同一条**索引
（`ui/accel.ts::buildAccelIndex`，因为它拿到的就是同一份菜单数组），
规则因此也是同一条：**先到先得**，撞了在 `console.warn` 里点名两条命令、
**前一条生效**。「插件」栏排在「帮助」之前、也就是排在所有内置栏之后，
所以**内置键位永远赢**——插件无法占用 `Ctrl+B`，只会得到一条警告。

⚠️ `command` 那个字段**不做校验**：写一个没注册过的名字不会当场报错，
点了才得到 `插件 {id} 没有注册命令 \`{name}\``。**注册菜单之前需要先注册命令。**

### 8.4 ⚠️ 表的存在性：两层判据

| 层 | 判据 |
|---|---|
| **`nota.ui` 这张表** | `ui.notify` **或** `ui.panel` **或** `ui.menu` —— `装_ui吗()`（`api/mod.rs:301-310`） |
| **表里的成员** | 各自再判一次（`ui.rs:35` / `:56` / `:61`） |

**两层是相乘的**：只申请 `ui.panel` 的插件表是有的、`register_panel` 有、
但 `register_menu` 是 `nil`（调了就是 `attempt to index a nil value`）。

⚠️ **所以第二层列了几条 `ui.*` 判据，第一层就得列几条。** 这是唯一一处**手工维护**、
也是唯一一处漏过东西的地方：

⚠️ **BUG-8：这两层曾经对不上。** `api/mod.rs` 那个条件**漏了 `ui.menu`**，
所以**只**申请 `ui.menu` 的插件连 `nota.ui` 都拿不到，`ui.menu` 这条能力形同虚设。
两个内置插件都申请了 `ui.panel`，所以一直没暴露。

**✅ 已在 2026-09-22 修掉**，而且修法不是"直接补一个 `||`"，是**让两层同源**：
第一层的判据由一张能力清单产生，那张清单的项数还要与 `ui.rs` 里的判据个数对得上。
判据同时剥成了纯函数，好让用例能钉住它（`build()` 要真的 `AppHandle`、构造不出来，
而这条判断是纯的）：

```rust
/// ⚠️ `ui.rs` 里每多一个 `manifest.has(Capability::Ui…)`，这里就要多一项。
/// 两处是**相乘**的关系：里面那个判据决定"表里有没有这个函数"，
/// 外面这个决定"表本身在不在"。漏一个就是 BUG-8。
const UI能力: [Capability; 3] = [Capability::UiNotify, Capability::UiPanel, Capability::UiMenu];  // api/mod.rs:301-305
fn 装_ui吗(manifest: &Manifest) -> bool { UI能力.iter().any(|c| manifest.has(*c)) }                // api/mod.rs:308-310
```

`api/mod.rs:102-110` 现在留了一段注释专门记这件事，末尾一句是本节最需要留意的：
**"里面有判据、外面也得有——两处是相乘的关系，不是一个能代替另一个。"**

回归用例有 4 条（`lua::api::tests`，`cargo test` 因此从 32 条变 36 条，
计数只在 `docs/06` 记）：

| 用例 | 钉住什么 |
|---|---|
| `lua::api::tests::每一条_ui_能力都能单独装出_nota_ui` | **BUG-8 的回归**：遍历 `UI能力` 逐项造清单，每一条都必须能单独装出 `nota.ui` |
| `lua::api::tests::没申请_ui_能力就不装_nota_ui` | 反向：一个 `ui.*` 都没申请时**不该**有表（按能力装表、不装空壳） |
| `lua::api::tests::ui_能力清单要和_ui_rs_对得上` | `UI能力` 的项数必须等于 `ui.rs` 里 `manifest.has(Capability::Ui…)` 的出现次数——**Rust 没有反射，这条推不出来，所以退一步钉"数量"**（注释与断言消息里都写明了"这是提醒不是证明"）；将来谁往 `ui.rs` 加第四个 `ui.*` 判据，它就会失败 |
| `lua::api::tests::能力的_serde_名字与_parse_说同一套话` | `#[serde(rename)]` 与 `Capability::parse()` 的两套名字同口径 |

⚠️ 于是"**加一个新的 `ui.*` 能力**"变成了一件有编译器/用例参与的事：
往 `ui.rs` 加判据 → 对不上 → 用例失败 → 去 `UI能力` 补一项 → 外面那层自动带上。
`docs/08` §6 讲新增能力那类改动时也是这条路子。

### 8.5 面板 DSL：`render` 返回什么

一块内容是一个表，`kind` 字段决定它是哪一种。**只有下面十六种**
（`src/ui/panel-nodes.ts::normalise` 是真相源）：

| `kind` | 字段 | 画成 |
|---|---|---|
| `heading` | `text` | 一小行加粗的标题 |
| `text` | `text`，`tone` | 一段正文，按 `tone` 上色 |
| `fields` | `items = { { label, value, tone } … }` | 左标签右值的几行（设置、状态） |
| `list` | `items = { { title, subtitle, badge, tone } … }` | 一列条目，`subtitle` / `badge` 可省 |
| `buttons` | `items = { { label, command, args, prompt, style, disabled } … }` | 一排按钮，点了调 `command` |
| `empty` | `text` | 居中的一句"这里没有东西" |
| `separator` | — | 一条分隔线 |
| `message` | `text`，`from` | 一问一答里的一条消息（2026-09-24，AI 对话框要的） |
| `diff` | `items = { { op, text } … }` | 一块增删对照（2026-09-24） |
| `input` | `arg`，`submit`，`submit_label`，`placeholder`，`hint`，`multiline` | 输入框 ＋ 发送键（2026-09-24） |
| `frame` | `url`，`alive`，`height` | 嵌一块**本机开发服务器**的画面（2026-09-25，`nota.devserver` 要的，§13） |
| `heatmap` | `title`，`unit`，`days`，`to`，`weeks` | 一格一天的**热力图**（2026-09-27，写作统计的长期那本账要的）：一列一周、从周一起，最后一列画到 `to` 那天为止。⚠️ `days` 是**一个字符串**，不是一天一项——宿主那个面板节点上限（200）装不下 26 周；形状见 `ui/heatmap.ts::读热力记录`。⚠️ 它**不认识“今天”**，右端由 `to` 定 |
| `graph` | `items = { { art, text, tone, picked, bond, pick } … }` | 一棵**提交树**（2026-09-26，git 插件要的，见下） |
| `chart` | `value`，`unit`，`label`，`caption`，`points`，`xTicks`，`yTicks` | 一块**会动的数字 ＋ 曲线**（2026-09-26，写作统计要的，§14.4）。⚠️ `points` 是**纯数字数组**、不是坐标对：x 按下标等分，y 按**这一串自己的 min/max** 归一（**不写死 0**——"速度从 0 起跳"和"累计字数从某个非零值起跳"两种曲线，底本来就不一样）。⚠️ **少于两个点不画曲线**（一个点画出来是条横贯的直线，读着像"速度恒定"）。⚠️ 这一段**最大值＝最小值**时曲线摆在中线，不是贴着底（贴底读着像"掉到零了"）。⚠️ `value = ""` 是"这一格**没有数**"（画破折号），**不是 `0`**——写 `0` 的意思是"有结论，就是没在打"。⚠️ **两轴刻度**（2026-09-27 加，用户：「横纵坐标的刻度要标」）：`xTicks` 是 `{ { at = 0.5, label = "-3 分" } … }`，`at` 是 **0~1 的比例**、`label` 是插件自己的一句话（时刻、`-N 分`、`现在`）；不写就是没有横轴刻度（**正常状态，不是坏掉**）。`yTicks` **通常不用写**——空着时宿主按 `points` 的极值推三档（`ui/chart-ticks.ts`），写给那些"纵轴不是数据本身"的图。⚠️ 刻度画成**真值**：位置由数据算，标签是真数——标着 100 的那条线就在 100 的高度上 |
| `cards` | `title`，`items = { { icon, value, unit, caption, points } … }`，`total = { label, value, unit }` | 一串**记录卡**（2026-10-04 加，写作统计要的，§14.4）。版式出自用户当天给的两张运动手表「运动记录」截图：**一条记录一个圆角框**，左边一颗圆图标（`icon` 取 `round` / `today` / `long` / `doc` / `record`，认不出的画成秒表）、右边一个大数 ＋ 一行小字；框底下那行 `total` 是**汇总**。⚠️ 与 `fields` 的分工是**主次**：一个大数配一行小字用 `cards`，几行平级的读数用 `fields`；与 `share` 的分工是**去处**：`cards` 画在面板里，`share` 是那张能发出去的图。⚠️ `total` **不是各条之和**——三条记录的区间互相包着（长期 ⊇ 今日 ⊇ 本轮），加起来是个没有意义的数（写作统计给的是「整篇文档」，标签**故意不写「总计」**）。⚠️ `points` 与 `chart` 同一个形状（**纯数字数组**），折成一张 36px 高的**窄曲线**、**没有刻度**（那个高度摆不下）；少于两个点不画（同 `chart` 那条）。⚠️ `title` 是空串时**不画那行小标题**——`items` 空着的屏幕上没有框给它当标题，但 `total` 照画（那是那种屏上唯一的数） |
| `share` | `title`，`subtitle`，`date`，`label`，`value`，`unit`，`points`，`xTicks`，`stats`，`foot`，`file` | 一张**分享图**（1080×1350 的卡片，2026-09-27 加，写作统计要的，§14.4）。⚠️ **插件只给字段，画的全是宿主**（`ui/share-card.ts`）：版式、配色、品牌、那条被幂函数压过的曲线都在宿主里——理由与"宿主不认识 Markdown"同一条（插件说**什么**、宿主说**怎么显示**）。⚠️ `stats` 是**最多三格** `{ { k, v, small } … }`（版式就是三格，第四格没地方放，多出来的丢掉）；`v` 是**字符串**（怎么格式化是插件的事，同 `chart.value`）。⚠️ `file` 只是**建议**文件名，宿主还要消毒一遍（插件给的字符串会进"另存为"对话框）。⚠️ 卡片上的**纵轴刻度是宿主按 `points` 推的**（`xTicks` 才是插件给的），因为那条轴被 `pow(比, 0.42)` 压过——不压的话一片 20–30 字/分钟的平台会贴着底压成一条直线 |

`tone` 取 `normal` / `muted` / `success` / `warn` / `danger`（`info` `error`
`warning` 是别名，见下）。`style` 取 `normal` / `primary` / `danger`。

**2026-09-24 新加的那三种**：

| | 说明 |
|---|---|
| `message` | `from = "user"` 靠左、`from = "ai"` 靠右，**认不出的 `from` 当 `ai`**。文本**保留换行**（`white-space: pre-wrap`），长词硬折行。⚠️ 上限比别的块宽（20000 字，见下） |
| `diff` | 五种 `op`（见 §11.3 那张表）：`del` 红底 `-`、`add` 绿底 `+`、`ctx` 上下文（不上色）、`hunk` 蓝字、`meta` 灰字——**认不出的 `op` 当 `add`**。是 `<pre>`：**行首空格保留**、长了**不折行**（横向滚动，2026-09-26 起；编辑区那份同样）。⚠️ 它**只是一块显示**——不认识 `nota-diff` 那份格式，也不知道点了按钮会怎样 |
| `input` | `arg` / `submit` **缺一个整块就不画**（跟 `prompt` 同一条规矩：问了也送不出去，不如不弹）。`multiline = true` → `textarea`（**回车换行、Ctrl/Cmd+Enter 发送**）；否则单行（**回车发送**）。发出去的动作就是"调 `submit` 命令，参数 `{ [arg] = 输入 }`"——**与按钮无区别**，只是值来自输入框 |
| `graph` | **唯一一种"一行的两头各是一颗可点的东西"**的块（2026-09-26 加，git 插件那棵提交树要的）：`art` 是左边那截图线（**等宽原样画，空格不折**）、`text` 是右边那串字、`picked = true` 的行加一层底色；`bond` / `pick` 是两颗动作，**各自可以为 `null`**（那一头就画成纯文字——⚠️ 与 `buttons` 那条"没写 `command` 也画成灰的"**故意不同**：树上"这一头没有动作"是正常状态，画成灰的会让整棵树布满灰块）。一颗动作是 `{ command, args, title }`：**没有 `prompt`**（树上的点击都是"看一眼"），**没有 `label`**（那串字是内容不是按钮名），`title` 只当鼠标提示。⚠️ 它**不是画布**：条目内容仍然全是插件给的字符串、由 React 转义，没有任何一条路能把它们变成 HTML 或属性 |
| `frame` | **唯一一处"把外部内容嵌进 DOM"**，所以口子开在这儿、也只开到这么大。⚠️⚠️ **`url` 只能由宿主填**：插件在自己的 `render` 里写 `url` 没用——宿主会把它整个抹掉，再按"**这个插件自己那场 devserver 会话**"填上（`lua/api/devserver.rs::填_frame`）。所以"嵌别人的页面"这条路由**不存在**：没有会话就没有地址。⚠️ 前端还会再判一次（只认 `http://localhost:…` / `127.0.0.1`，别的当"没有地址"）——那不是用来防插件的，是因为这份 JSON 也可能来自别处（手改过的数据、测试）。⚠️ CSP 那边也钉着（`tauri.conf.json` 的 `frame-src` 只列了这两个主机）。⚠️ `alive = false` 表示会话已经收了；`height` 只认数字、夹在 120–2000 之间 |

⚠️ `message` / `diff` / `input` **在插件里看起来是"能说话、能改文档"的东西，
但一件都不是宿主给的能力**：`message` 和 `diff` 只画，`input` 只是把一段文本
变成一个命令调用的参数。**面板 DSL 里没有任何一条路能绕过能力清单。**
`frame` 是唯一一个"外面进来"的口子，而它的地址是**宿主填的**（见上）。

⚠️ **认不出的 `kind` 会如实画成"不认识这种内容块"**，不静默丢掉，
也不猜它是哪一种——所以不要写不在上表里的名字，也不要指望它长得像某一个。
字段类型不对则**退回默认值**（`text` 是数字 → 空串），不会让整块消失。

**三条硬规矩**（`panel-nodes.ts` 文件头有完整理由）：

1. **没有任何一条路能把字符串变成 HTML 或属性。** 全文没有
   `dangerouslySetInnerHTML`，插件塞的额外键**一概不往 DOM 上带**。
   面板里的富文本不是"以后再说"，是**不做**——要表达力就给新 `kind`。
2. **`args` 原样带着，宿主不解析**：它的形状是插件与自己的命令之间的约定。
3. **上限是两侧各自把关**：宿主截大小（文本 20000 字符、每块 200 项、嵌套 6 层），
   前端再截一刀（防手改过的数据）。超了是**截断不是报错**。

⚠️ **那个文本上限 2026-09-24 从 4000 抬到 20000**（`ui.rs::面板文本上限`）：
一条 `message` 就是模型的**一整段回答**，4000 字在长回答上会被**静默截断**
（只留一个 `…`），而用户会以为模型就写了这么多。抬到 20000 之后，
前端那条兜底（`panel-nodes.ts::消息上限`）也调成同一个数；插件那一侧自己
再压在 15000 以下，好让"后面还有内容"这句话由**插件**说出来
（见 `plugins/ai/main.lua` 里 `messages_blocks` 那段注释）。

**`prompt`：点击后先询问一次**（面板按钮和菜单项**共用**这一套字段）：

| 字段 | 必填？ | 说明 |
|---|---|---|
| `arg` | **必填** | 答案放进 `args[arg]`。**缺了 `arg` 整个 `prompt` 当没写**——问了也送不出去，不如不弹 |
| `label` | 可选 | 输入框上面那行字，默认 `"请输入"` |
| `placeholder` / `hint` | 可选 | 占位符 / 底下那句解释 |
| `secret` | 可选 | `true` → 输入框遮屏（`type=password`）。**只遮蔽输入框的显示，不改变存储方式**——`nota.settings` 是明文的 |
| `secondArg` | 可选 | **第二个值**放进 `args[secondArg]`（2026-09-26 加） |
| `secondLabel` | 可选 | 第二个输入框上面那行字。⚠️ **它同时是"要不要问第二个"的开关** |
| `secondPlaceholder` | 可选 | 第二个框的占位符 |

⚠️ **第二个字段：`secondArg` 和 `secondLabel` 两个都给才算数，只给一个等于没给**
（`second*` 三个都当空串，框上只画一行）。理由与 `arg` 那条同源：缺了键名，
用户填的值没有地方放；而宿主的 `PromptDialog` 是"给了 `secondLabel` 才画第二行"，
只给键名的话那个值会被悄悄丢掉。判据只有一处：`plugin/mod.rs::读提示`。

**为什么加它**：Git 要的两个值（`user.name` + `user.email`）是**一对**，
分两次问会得到"填了名字没填邮箱"的中间状态，而那不是合法状态。
**也到此为止**：三个以上的值该是插件自己的设置页（`nota.settings`），
不是一个越滚越长的对话框。

⚠️ **用户取消时该命令根本不会被调用**，不是"收到一个空值"。
所以命令里不需要处理"没填"这种情况——**除非**这个命令还能被别处调用。
（这一条只有一个实现：`src/ui/plugin-prompt.ts::问参数`，面板和菜单都走它，
免得同一个"取消"在两处有两种解释。）

⚠️ **面板按钮的 `prompt` 在前端归一化，菜单项的 `prompt` 在宿主归一化**
（菜单那条路不经过前端白名单）。**两边的字段名必须一样**，因为它们最后
都进同一个 `问参数`——改一处忘了另一处，症状是"菜单里问得出、面板里问不出"。
目前两边都是 **camelCase**（`secondArg`，不是 `second_arg`）：
宿主那个结构体上挂着 `#[serde(rename_all = "camelCase")]`（`plugin/mod.rs`），
`lua/api/ui.rs` 有两个用例按着它（`两个字段的_prompt_读得回来` /
`第二个字段只给一半等于没给`）。

**一个现成的两个字段的例子**（`plugins/git/main.lua::panel_content` 那截）：

```lua
prompt = {
  arg = "name",  label = T("Git 身份"),  placeholder = T("名字，比如：张三"),
  hint = T("git 拿它给每次提交署名"),
  secondArg = "email", secondLabel = T("邮箱"), secondPlaceholder = T("you@example.com"),
}
```

### 8.6 `nota.ui.refresh(id)` / `nota.ui.review(id)` / `nota.ui.stream(text)` —— 同上，都需 `ui.panel`

前两条是"声明是状态 → 拉"那条路上的补充（同 §8.2）：**它们不推内容，只推"该重拉了"**。
第三条是**唯一一条推内容的**，下面单独说。

| 函数 | 参数 | 干什么 |
|---|---|---|
| `refresh(id)` | 面板 id（可省，省略 = 你这个插件唯一那块） | 告诉界面"我这边的面板内容变了"——前端收到就**重拉**一次 `nota_plugin_panel_content`（`render` 现跑，§8.2）。⚠️ 面板那一页**没开着**时不必调：切过去时会现拉（`ui/PluginDock.tsx`）。⚠️ 它是**失效信号，不带内容**：判据是"丢掉它，打开面板仍然对" |
| `review([id])` | 面板 id；**传 `nil` 收起来** | 把**已经在册的**这块面板摊到**编辑区**里看（`ui/ReviewPane.tsx`）——插件栏那 260px 宽，预览、长对话在那儿都嫌窄。⚠️ **同一个面板两处可以同时画**（插件栏那一页与编辑区那一片），内容仍是每次现拉。⚠️ **收起来也得插件自己说**（`review(nil)`）：宿主收不了，它不知道面板上那些按钮是什么意思。⚠️ `register_panel` 里的 `wide` 决定摊开时占多宽（§8.2） |
| `stream(text)` | 一段文本；**空串 = 收工** | ⚠️⚠️ **这个会真的送内容过去**——它就是"边生成边显示"（`docs/07` 第 58 项，2026-10-04 加）。见下面那一段 |

#### ⚠️⚠️ `stream` 是「声明走拉、发生走推」的**唯一例外**（BUG-13）

规矩本来是「**声明是状态**（面板长什么样、菜单有哪些）走**拉**，**发生**（一条提示、一次刷新）
走**推**」，而推的那些**只报"发生了"、不带内容**（`bridge/payloads.ts` 顶上那句话）。
`stream` 破了第二条：**它带的就是内容本身**。

**为什么破**：这条命令跑着的时候（一次 HTTP 请求、几秒钟），宿主一直**握着插件锁**
（`commands/plugin.rs::nota_plugin_call` 从进函数锁到出函数），而 `nota_plugin_panel_content`
要的是**同一把锁**——所以这中间前端喊"重拉"**根本回不来**，`refresh()` 在这儿是死路。

```
nota_plugin_call        → 拿锁 ────────────── 发请求、读回包 ────────────── 放锁
nota_plugin_panel_content →                    等锁 ⏳（一直等到上面放锁）
```

**所以只能反过来：宿主**推**给前端。** 通道是 `nota:plugin-stream`，载荷 `{plugin, text}`，
由 `PluginDock.tsx` 收下、**直接画在面板那列内容的末尾**。

四条口径：

* **推的是"到此刻为止的全文"**，不是这一小段的增量。两端都别自己攒——一边攒一边断线就会错位。
  空串是**收工**（把那段临时的字撤掉）。
* **只留最后 8000 个字符**（`ui.rs::实时上限`）。它是**临时的显示数据**，
  不是第二个"面板内容"口子——真内容仍然要走 `render`。
* **收工时照样得 `refresh()` 一次**，否则面板上留下的只是最后那一眼。
* **别拿它干别的**：传进去的东西**不经 `render`**，也就没有 §8.5 那一套节点校验
  （前端按一条 `message` 处理）。想显示结构化内容，那是 `render` 的事。

⚠️ 正在用它的只有 AI 插件（`plugins/ai/request.lua::stream_request`，每 80 毫秒推一次）。
⚠️ 三条都归 `ui.panel` 管（`register_panel` 的同一件事），不需要额外能力。

## 9. `nota.http` —— 需 `network.http`

```lua
local r = nota.http.post({
  url = "https://api.example.com/v1/chat/completions",
  headers = { authorization = "Bearer " .. key },
  body = { model = "gpt-4o-mini", messages = { { role = "user", content = "你好" } } },
  timeout_ms = 120000,
})
```

| 规格字段 | 默认 | 说明 |
|---|---|---|
| `url` | **必填** | 缺 → 抛。见下面的地址围栏 |
| `method` | 看调用名 | `get` / `post` 会自动填上；`request` 不填就是 `GET` |
| `headers` | 空 | 值只收**文本/数字/布尔**，收到表 → 抛（尽早报错） |
| `body` | 空 | 字符串 = 原样发；**表 = 当 JSON 发**，并自动补 `content-type: application/json` |
| `timeout_ms` | 30 000 | **上限 180 000**，超了**截到上限**不报错（写一个很大的数意图是"可能很慢"）；`0` → 抛 |

三个调用名：`nota.http.request(spec)`、`nota.http.get(url或spec)`、`nota.http.post(url或spec)`。
**返回一张表**：

| 键 | 说明 |
|---|---|
| `code` | HTTP 状态码（integer） |
| `text` | **原样**的响应体字符串 |
| `json` | ⚠️ **响应体能解析成 JSON 时才有这个键**：拆好的表，数组下标**从 1 起** |

⚠️ **4xx/5xx 不是错误。** 宿主关掉了 ureq 的 `http_status_as_error`，
所以配额用完、密钥不对这类话会**原样**回到 `code` + `text` / `json` 里，
由调用方去读、去显示。只有"连不上 / 超时 / 地址不合法"才抛。

⚠️ **`json` 解析不了就不给这个键，也不当错误**——4xx 常常回一整页 HTML，
那时该看的是 `text` 里那段话，而不是一个把原因指错地方的"JSON 解析失败"。
**有了它才不用在 Lua 里抠 JSON**：Lua 没有 JSON 库，用模式匹配去取
`\n` 这类转义一定会错（AI 插件读 `r.json.choices[1].message.content` 靠的就是它）。

**两道围栏**：

| 围栏 | 规矩 |
|---|---|
| 地址 | `https://` 随便；`http://` **只放行回环**（`127.0.0.1` / `localhost` / `::1`，给本机大模型服务用），别的明文地址**直接拒绝**。⚠️ 判定按**主机名**做，`127.0.0.1.evil.com` 不算本机 |
| 大小 | 请求体 1 MiB、响应体 2 MiB（**超了算失败**，不是截断）；重定向最多 5 跳 |

⚠️ **它是阻塞的**：调用发生在 `spawn_blocking` 的线程里（`mlua` 的 `send` 特性），
所以界面不会冻住——但一次调用要等到对方回话为止。
长文生成建议把 `timeout_ms` 提到十几万（`plugins/ai/request.lua` 用的是 120 000）。

⚠️ **`nota.http` 拿不到 `ctx`**（不碰文档、不碰设置）。一个能发 HTTP 的插件
同时能读全文，等于给这条通道加了一个没必要的放大器（`http.rs::build` 的注释）。

### 9.1 `nota.http.stream(spec, on_chunk)` —— 边收边给（2026-10-04 加）

> 2026-10-04 之前这一节写的是「**没有流式**」。第 58 项（「边生成边显示」）把它加上了。
> 加的是**一个函数**，不是把 `request` 改掉——上面那三段（`code` / `text` / `json`）
> 一个字都没动，**已有的插件不受影响**。

```lua
local r = nota.http.stream(spec, function(chunk)
  buf = buf .. chunk                      -- ⚠️ chunk 不是一行，甚至不是一句
  while true do
    local nl = string.find(buf, "\n", 1, true)
    if not nl then break end
    local line = string.sub(buf, 1, nl - 1)
    buf = string.sub(buf, nl + 1)
    -- …… 按行处理 line
  end
  return true                             -- ⚠️ 只有返回 false 才算"我要中断"
end)
```

| | `request` / `get` / `post` | `stream` |
|---|---|---|
| 什么时候回来 | 整份到齐 | 每收到一块就叫一次 `on_chunk` |
| 返回值 | `{code, text, json}` | 上面三个 ＋ **`chunks = N`**（一共交给了几块） |
| 中断 | —— | 回调返回 **`false`** |
| 结果表上多出来的键 | —— | 真被中断时才有的 **`aborted = true`** |

四条**写插件必须知道**的：

* ⚠️ **块的边界既不是行边界、也不保证落在字符边界上**——**跨 UTF-8 那个由宿主兜住**
  （`http.rs::切出完整段` 攒够一个完整字符才交），所以插件这一侧**最小单位是一个字符**。
  但"一行 `data:` 横跨两块"是**常事**，所以上例那个 `buf` 是必需的，不是讲究。
* ⚠️ **回调返回 `false` 才是中断**（用户/插件不想要了）。返回别的值、
  或者干脆不返回（`nil`），都是**继续**。
* ⚠️ **`data: [DONE]` 看见了也别喊停**：SSE 的收尾本来就由服务器关连接。
  把它当"中断"的话结果表上会多一个 `aborted`，而那**不是**事实。
* ⚠️ **同一套地址围栏、同一套大小上限（2 MiB）、同一个 `timeout_ms` 口径**——
  两条路走的是同一个 `build()`。流式**不放松任何一条**。

⚠️ **`stream` 不会自己往界面上画字**。要"边生成边显示"，得在回调里调
`nota.ui.stream`（§8.6）——**两件事、两个函数**：`nota.http.stream` 是"别一次等完"，
`nota.ui.stream` 是"把这一段先画上去"。为什么后者必须是**推**而不是 `refresh`，
§8.6 那段图讲清楚了。

⚠️ **对方不认流式时它不报错**：回一份普通的整段 JSON、一行 `data:` 都没有，
这时 `r.text` / `r.json` 就是那份响应（和 `request` 那条路一样）——所以调用方
**不能**假定"走了 `stream` 就一定拿到了 SSE"。`plugins/ai/request.lua::M.ask`
那三行就是照这条写的：一个字都没收到时**退回整段再要一次**。

## 10. `nota.settings` —— 需 `settings.own`

```lua
local key = nota.settings.get("api_key")      -- 没设过 → nil
nota.settings.set("api_key", "sk-…")          -- 立刻落盘
nota.settings.set("api_key", nil)             -- 删掉这一项（不报错）
local all = nota.settings.all()               -- 一张普通表
```

**一个插件一个文件**：`~/.config/nota/plugin-settings/<安全化后的 id>.toml`
（`nota.ai` → `nota.ai.toml`），**文件 0600、目录 0700**。

| 规矩 | 说明 |
|---|---|
| 键名 | **只认 ASCII 字母数字和下划线**，且**不含点**。`a.b` 在 TOML 里是嵌套表，读回来形状就变了 → 抛 |
| 值的类型 | 文本 / 数字 / 布尔。**表不行**（要存结构就自己序列化成文本） |
| 落盘时机 | **每次 `set` 立刻写**。没有"退出时统一保存"，也就没有"崩了丢设置" |
| 越界 | 只能碰**自己那个文件**——`build()` 拿的是本插件的 id，别的插件的设置够不着 |

### 10.1 ⚠️⚠️ 这份文件从 2026-10-04 起有**两个写者**

| 谁 | 什么时候 | 走哪儿 |
|---|---|---|
| 插件自己 | `nota.settings.set(k, v)` | `lua/api/settings.rs` → 立刻落盘 |
| **宿主** | 用户在「设置 → 拓展」上拖那根滑杆 | `commands/plugin.rs::nota_plugin_setting_set` → 同一个落盘函数 |

宿主那一半是给**清单里声明了 `[[settings]]`** 的插件用的（形状与硬规矩见
`docs/11` §2.5）：那一格的界面由宿主画，值也由宿主写。两条口子**同时开着的
插件是正常的**（写作统计就是这样：窗口那根滑杆归宿主，别的键归它自己），
键各是各的、文件是同一个。

**一致性靠一张进程级的注册表**（`lua/api/settings.rs::注册表()`）：
`plugin id → Arc<Mutex<存储>>`，两个写者拿到的是**同一份内存**，谁也看不见
"盘上是一份、内存里是另一份"。三条口径：

1. **锁序**：注册表那把锁是**外层**的，只用来取 `Arc`，取到就放；
   存储那把锁是内层。**不许在握着存储锁的时候回头去要注册表锁。**
2. **值没变就不写盘**：宿主那一侧每次 `onChange` 都会调过来（滑杆拖动时很密），
   同值比较挡在写盘之前。
3. **键的合法性是唯一一道门**：`键规则()` 被两个写者共用（宿主写进来和插件写进来
   走的是同一个 `写进格`）。宿主那边**还多一道**——只认清单里声明过的键，
   写一个没声明的键直接报错（"没声明过"不是"忘了"，见 `docs/11` §2.5）。

⚠️ 宿主写完之后会发一条 `nota:plugin-panel`（`EVENT_PANEL_DIRTY`，payload 里 `id = nil`）：
"这一页该重拉了"。插件**每一枪现读**那个值（不是在 `on_load` 里读一次缓起来），
所以拖完滑杆下一枪就是新值——这条是那一格"拖了当场看得见"的全部机制。

⚠️ **明文，没有加密。** 这是有意的取舍：密钥要和插件的运行环境放在一起，
而这个环境能读的东西，能读到插件文件的人也能读——加密只能把钥匙藏在同一台机器上，
挡不住真能读这些文件的人。**它挡的是"这台机器上的其他用户"**（靠 0600），
以及"设置被不小心贴进 issue"（靠 UI 遮屏）。完整理由见 `docs/12` §插件设置。

⚠️ **`set(k, nil)` 是"删掉"，不是"存一个 nil"**——TOML 里没有 `nil` 这种东西。
删掉之后 `get` 回到 `nil`，插件那边通常该回落到自己的默认值。

## 11. `nota.diff` —— 改动块与 unified diff（永远可用）

> 2026-09-24 新增。实现 `src-tauri/src/lua/api/diff.rs`（487 行，含 13 条用例）。

**一张"文本进、文本出"的纯函数表**，不需要任何能力：它不碰文档、不碰磁盘、
不碰网络，拿它做不出清单之外的事（跟 `nota.log` 同一类）。

三个函数、两份格式：`parse` / `apply` 认的是**模型写的改动块**（§11.1、§11.2），
`parse_unified` 认的是 **`git diff` 那套**（§11.3）。⚠️ 两份格式**别混用**，
它们的容错方向是相反的（一份"认不出就当正文"，一份"认不出就丢掉"）。

### 11.1 改动块长什么样

一段普通文本，**最末尾**附一个围栏包起来的块：

~~~text
我把第二句改短了。

```nota-diff
- 他慢慢地走了过来。
+ 他走过来。
```
~~~

**三条规矩**（`diff.rs` 文件头有同一张表，`plugins/ai/main.lua` 的
`SYSTEM_PROMPT` 里也有——**改一处要改三处**）：

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **失败 = 什么都没做**：要么给新全文，要么给一句原因，**绝不给半截结果** | "改了一半"比"没改"坏得多：用户按 Ctrl+Z 都不知道该退到哪一步 |
| 2 | `-` 那几行要和文档里**连续的一段逐字一致**（行首的 `-` 和紧跟的一个空格截掉，`-foo` 也收） | 模型常常修改标点、补空格。宁可报"没找到"，也不拿一段近似的文字去猜 |
| 3 | **没有 `-` 行 = 追加到文末** | 没有落点就别猜位置 |

**围栏之外的字**（`正文`）就是"可以直接读的那段话"——它跟改动是两件事：
正文画成对话里的一条 `message`，改动画成一块 `diff`。

容错的地方（**都是"认不出就当普通文本/忽略"，不报错**）：

- 收尾的 ` ``` ` **漏写也认**（到文末为止都算改动块）；
- 围栏行**前后允许有空白**（`trim` 之后整行相等才算数）；
- **空的改动块当没写**（模型偶尔画一个空块表示"不用改"）；
- 围栏里既不 `-` 也不 `+` 的行**数出来（`bad`）、不当改动**——多半是模型混进
  一句解释，或者行首少了标记。面板要把这个数**如实说出来**，不要静默吞掉；
- 多个围栏 = 多处改动，**按出现顺序应用**；第二处先从上一次的落点往后找，
  找不到**再从头找一遍**（模型把顺序写反了）；
- **CRLF 的文档**按行截掉 `\r` 再匹配、join 的时候补回去；换行风格跟着原文走，
  结尾那个换行有就保留（往文末加过行的话也补一个）。

### 11.2 两个函数

```lua
-- ⚠️ 局部名一律 ASCII（§0.6）：`local 新全文` 是**语法错**，不是"能跑但取不到"。
local p = nota.diff.parse(answer)        -- { text = 正文, hunks = {...}, bad = 坏行数 }
local new_text, why = nota.diff.apply(nota.document.get_text(), p.hunks)
```

| 函数 | 参数 | 返回 |
|---|---|---|
| `parse(answer)` | 一段文本 | `{ text = 正文, hunks = {...}, bad = 数字 }`。⚠️ 一个改动块都没有时 `hunks` 是**空表不是 `nil`**，调用方不用分情况 |
| `apply(text, hunks)` | 文档全文 ＋ `parse` 给的那个 `hunks` | 成功给**新全文**；失败给 `nil, why` |

每个 `hunk` 的形状是 `{ del = {"…"}, add = {"…"} }`（行数组，**两边行数可以不一样**：
`add` 空 = 纯删除、`del` 空 = 纯插入）。

⚠️ **`apply` 失败是"返回值"不是抛错**（`nil, 原因` 两个值）：`没找到` 是一个
**正常结果**（用户改了文档、而模型看的是旧版），命令那一侧该把它画成一条对话
消息，而不是一次"命令报错"。原因那句是中文人话，形如：

> 第 1 处改动没找到能对上的原文（`-` 那几行要和文档里连续的一段逐字一致），比如 `他慢慢地走了过来。`

⚠️ `hunks` 里出现非表/非字符串的东西 → **抛错**（那是调用方的 bug，不是模型的
格式问题，所以走另一条通道：见 §0.2）。

### 11.3 `nota.diff.parse_unified` —— 另一份格式：`git diff` 那套

```lua
local files = nota.diff.parse_unified(git_output)
-- { { path = "a.md", added = true, deleted = false, lines = { { op = "del", text = "…" }, … } }, … }
```

**它跟 §11.1 那份不是一个格式**，也别指望一个函数认两种：`diff.rs` 管的是
**模型写的改动块**（可以少围栏、可以混一句解释），这里管的是 `git diff` / `diff -u`
吐出来的 `---` / `+++` / `@@`（**机器生成的**，它不会写错，只会出现没预料到的行）。
两处只共用两样：**挂在同一张 `nota.diff` 下**（作者只需要记一个名字）、
**输出同一个形状**（五元组，见下，也就是 `kind = "diff"` 那块内容块要的行）。

| 返回字段 | 说明 |
|---|---|
| `path` | 显示给用户看的路径：**已经掐掉 `a/`、`b/` 前缀和尾部那个制表符** |
| `added` | 这份文件是**新加的**（`--- /dev/null`） |
| `deleted` | 这份文件被**整个删掉**（`+++ /dev/null`，此时 `path` 是旧路径） |
| `lines` | 逐行，**五种 `op`**（下表）。⚠️ **空数组 = 这份真的一行都没有**（正常只出现在"两份一模一样"这种解析不出来的情况）；二进制文件现在**也有**三行可看 |

`op` 的五个取值（2026-09-26 起，对齐 Folio 那个 Git 拓展的差异视图）：

| `op` | 是什么 | 画成 |
|---|---|---|
| `del` / `add` | 被换掉的原行 / 换上来的新行 | 红底删除线 / 绿底下划线 |
| `ctx` | hunk 里**没变**的那部分（上下文） | 正文色，**没有任何装饰** |
| `hunk` | `@@ -1,4 +1,4 @@`——只标"改在哪一段" | 蓝字 |
| `meta` | `diff --git` / `index` / `---` / `+++` / `\ No newline …` | 灰字 |

⚠️ `text` 对 `del` / `add` / `ctx` **不含行首那个标记**（界面自己补 `+` / `-` / 空格），
对 `hunk` / `meta` 是**整行原样**。

**三条规矩**（`unified_diff.rs` 文件头有同一张表）：

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **只为 `diff --git` 开出来的段落认 `---` / `+++`** | 被删掉的一行完全可能长成 `--- 这一行`（原文是 `-- 这一行`）。判据不是"长得像文件头"，而是"它出现在 `diff --git` 之后、第一个 `@@` 之前"。代价：**裸的 `diff -u`（没有 `diff --git` 行）解析出来是空的**——宁可不画，也不能把正文当文件头 |
| 2 | **上下文行也画**（2026-09-26 改的口径） | 从前只认 `del` / `add`，代价是看不出"改在哪一段"——而紧挨着改动的那几行是谁，正是判断"这一改对不对"要看的东西。现在跟着 hunk 一起画，**额度按画出来的行算**（插件那边 `MAX_TOTAL` 的注释写着这条）。⚠️ 想再加一种 `op` 的话**必须先改前端**：`PanelDiffLine` 的 `op` 是五元联合，多出来的值会被**静默当成 `add`**（画成绿的） |
| 3 | 路径要关掉 git 的转义 | 默认 `core.quotePath=true` 时中文文件名写成 `"\344\270\255…"`、`+++` 行还带引号，那样掐不掉 `b/` 前缀。宿主在 `nota.git` 里统一加了 `-c core.quotePath=false`（§7） |

⚠️ 它一样是**纯函数、不需要任何能力、不碰文档**——一份文本进、一张表出。

### 11.4 ⚠️ 为什么这件事在宿主里，不在 AI 插件里

它跟 AI 插件一起长出来的，但**不是 AI 专有的**：

1. 任何"建议把文档改成这样"的插件都要同一样东西，而界面上那块
   `kind = "diff"` 的渲染**早就是宿主的**（§8.5 的白名单里就有它）。
   一份格式两处实现迟早会漂，漂的症状是"明明一模一样的两行，它说没找到"；
2. 它是**唯一会改坏用户文档**的地方，所以必须能拿单元测试一条条钉住。
   Rust 那边一条 `#[test]` 就够，写在 Lua 里需要先造一个宿主环境；
   `diff.rs` 那 13 条用例就是钉它的（那一轮 `cargo test` 从 121 条变 134 条；
   ⚠️ 那是**当时**的数，总数只在 `docs/06` 记，**当前值以那里为准**）；
3. AI 插件那份文件还要守 1000 行上限（`docs/09` §4）——搬走这 200 行是
   **按职责拆**（插件管对话、宿主管格式），不是为凑行数。

⚠️ **`nota.diff` 只是"解析与应用"**：它**不碰文档**。写进去的那一句
（`nota.document.set_text`）永远在**插件**手里，也就是说——**永远要用户点一下
确认**。这是本项目从第一版起就写着的一条产品原则（**AI 的输出不许直接落进
文档**，样例见 §14.2 文件头那一段）：模型会犯错，而"文档被悄悄改掉、
用户按了 Ctrl+Z 才发现"是最坏的一种错。

## 12. `nota.i18n` —— 插件自己的文案（永远可用）

> 2026-09-25 新增。实现 `src-tauri/src/lua/api/i18n.rs`（含 6 条用例），
> 语言怎么挑在 `src-tauri/src/lang.rs`。

用户那一轮的原话是：

> 优化界面国际化系统。支持多语言。插件也支持。**插件必须包含英语**。
> 如果应用语言在插件语言列表内，则**直接使用**；否则，显示"此插件不支持您的语言"，
> 并且**使用英语**。

### 12.1 规矩只有一条：**键就是原文，缺键就用原文**

```lua
local T = function(s) return s end          -- 模块级存根（那时 `nota` 还没到手）
-- … on_load 的**第一件事**：
T = function(fmt, ...)
  local s = nota.i18n.text(fmt) or fmt      -- 查不到就用自己写的那句
  if select("#", ...) > 0 then return string.format(s, ...) end
  return s
end
```

`nota.i18n.text(key)` 查不到给 **`nil`**（不是空串、不是键名）——所以那句惯用的
`or 原文` 接得住。带来的三件事：

1. 表**只写要翻译的那些键**：`lang/zh-CN.toml` 里就是 `"Stop preview" = "停止预览"`。
   ⚠️ **2026-09-28 起英语是原文**（用户定），所以译文表通常是**中文那一份**、
   英语那份不写；作者原文本来就是中文的插件反过来（`zh-CN.toml` 几乎空的，
   写个 `name` 就够）；
2. "表里少了这条"、"语言文件写坏了"、"压根没声明 `langs`"三种情况退化成
   **同一个行为**：看见作者写下的原文。这比"宿主替它兜底"结实——兜底得有东西可兜，
   而**宿主不认识插件的键**；
3. 作者**零成本入场**：不必先学一套 `panel.title` 那样的命名约定。

⚠️ 代价说在明处：**改了原文就等于改了一个键**，那份翻译会**静默失效**（表现为退回
原文、不报错）。所以译文表里的键是"那一刻的原文"——`tools/i18n-check.sh` ③ 就是
来查这个的（表里有、代码里找不到 = 废键 = FAIL）。

⚠️ Lua 的**标识符不许有非 ASCII 字符**：`local 一句 = …` 是**语法错误**，
不是"能跑但不规范"（§0.6）。中文放进注释和字符串。

### 12.2 四个成员

| 成员 | 是什么 |
|---|---|
| `app_lang` | 宿主此刻在说哪种语言（`zh-CN` / `en`…）。**永远在**，哪怕没声明 `langs` |
| `lang` | 这次实际用的那份表的名字（`"zh-CN"`）。⚠️ **没声明 `langs` 时是 `nil`**——"没得协商"不等于"不知道自己在说什么语言" |
| `ok` | 应用语言**在不在清单的 `langs` 里**。`false` 时界面要说那句「此插件不支持您的语言」 |
| `text(key)` | 取一条文案。查不到 → `nil` |

⚠️⚠️ **`ok` 只看清单，不看文件在不在。** 文件缺失 → 表是空的 → 那个语言下全是原文，
这**恰好**就是 `langs = ["en"]`、一份表都不带的那种插件该有的样子。拿文件缺失去判
`ok = false`，会让这类插件平白挂上一句「此插件不支持您的语言」，恰好把它说反。
文件读不到会**记一条**（走调试闸门，`NOTA_DEBUG=1` 才看得见）。
⚠️ 推论：**`ok` 是"清单成员资格"，不是"翻译齐不齐"**——一份只有三行译文的
`zh-CN.toml` 照样 `ok = true`。

### 12.3 `langs` 与协商（宿主那一侧）

清单里写 `langs = ["zh-CN", "en"]`。三条规矩：

| 规矩 | 为什么 |
|---|---|
| **必须含 `en`** | 英语是没命中时的兜底。⚠️ 准确说是 **`lang.rs` 的 `插件兜底`**（= `en`）——2026-09-26 起宿主里**另有一个 `应用兜底`**（**应用自己**的落点：设置里「跟系统走」而系统语言认不出来时界面落到哪一门。它 2026-09-26 那天走过 `en` → `zh-CN` → `en` 一个来回，今天也是 `en`；📌 2026-09-28 前端语言翻转之后它**不再有条件**了，见 `docs/11` §2.4）。那一条**与插件无关**：**插件侧看到的兜底永远是 `en`**，`应用兜底` 取什么值都不影响本节。作者一定写得出英语、写不出所有语言——这不是"英语优先"，是"总得有一个谁都得给的"（缺了宿主直接判这份清单**不合法**） |
| 清单里的语言**不要求**有对应文件 | 没有就是"这个语言下全是原文"，不报错 |
| **不写 `langs` 就不协商** | 插件栏里不会出现那句话，一律显示 `main.lua` 里的原文——第三方插件按自己的意思来，这是留给它们的自由 |

**怎么匹配**（`lang.rs::匹配`，两边同一套）：

- 语言标记一律按 **BCP-47 短横线写法**比（`zh-CN`）：清单里写 `zh_CN` 也认，文件名
  仍要按规范写法（`lang/zh-CN.toml`）——不然同一门语言会同时存在几个写法；
- **先精确，再按主语言前缀**：应用 `zh-CN`、插件只有 `zh` → 命中（反过来也成立）；
- ⚠️ 前缀匹配**只往"更粗"的一侧退**（`zh-CN` 命中 `zh`），**不做** `zh` 命中
  `zh-CN` 那种猜测：`zh` 的文案未必是给 `zh-CN` 写的（可能是 `zh-TW` 的用词），
  猜错用户看到的是**另一种中文**，比看到英语更让人莫名其妙。

**那句提示在哪出现**：插件栏里这一页的页签名旁边 + 面板顶上。文案由**前端**出
（中文表里那一条，今天住在 `src/i18n/zh-ui.ts`——`zh.ts` 只是四份表的汇总出口）。

⚠️⚠️ **一个反直觉的推论**：插件**必须**含 `en`，而应用语言就两种（`zh-CN` / `en`）——
所以**应用语言是 `en` 时那句提示不可能出现**（匹配 `en` 永远成功）。它今天实际只在
"英文源的插件（`langs = ["en"]`）＋ 中文界面"这一种组合下出现。**那句提示的英文版
因此暂时打不出来**——留着是给以后加语言时用的。

### 12.4 表在哪、叫什么

```text
plugins/你的插件id/
  plugin.toml        langs = ["zh-CN", "en"]
  lang/
    zh-CN.toml       # 只有译文；英语那份不写（见下）
  main.lua
```

- 文件名是**规范过的语言标记**（`zh-CN.toml`）；
- ⚠️ **英语那份 `lang/en.toml` 不写了**（2026-09-28 起）：英语是**原文**，
  那份表活着的每一天都只是在把 `main.lua` 里的字抄一遍。四个内置插件的那一份
  翻转时都删了。⚠️ `langs` **仍然要含 `en`**（上一张表那条要求没变），
  只是**不再要求有对应的文件**——"清单里的语言不要求有对应文件"那条规矩
  现在对 `en` 尤其成立；
- 一份表就是一个**平的** `键 = "字"` 文件（TOML）。⚠️ 键里可以有 `=`、可以有引号，
  但**不要**写嵌套表——`lang::读语言文件` 只收平的那一层；
- **保留键 `name`** = 这个插件**在这个语言下叫什么名字**（插件栏的页签名、插件列表
  那一行都由它覆盖清单里的 `name`）。⚠️ 它**不覆盖 id**：id 是身份，事件通道、
  命令名、账本全靠它，一个字都不能随语言变；
- **保留键 `description`**（2026-09-27 加）= 这个插件**在这个语言下的简介**（插件列表里那一行小字）。规矩与 `name` 全同：只覆盖清单里的 `description`、**改不了 id**；主语言是英语，所以清单里写英语、中文挪进 `lang/zh-CN.toml`，**英语表通常不必写这两条**（§12.3 那三张表里的 `langs` 只管语言，保留键只管名字与简介，两件事）；
- 译文里的 `%` 写成 `%%`（插件的 `T` 走 `string.format`，见 §12.1 那段存根）。
  ⚠️ 占位符的**个数与顺序必须与原文一致**（`T` 是把**译文**丢给 `string.format`
  再把原文的参数喂进去，少一个就错位）；但**宽度可以按目标语言的习惯改**——
  写作统计那条日期就是现成的例子：原文 `"%d-%02d-%02d %02d:%02d"`（给英语的
  `2026-09-28 19:45`），中文写成 `"%d年%d月%d日 %02d:%02d"`（`9月28日` 不补零，
  2026-09-28 就是这么定的）。

### 12.5 ⚠️ 改语言要重启

`应用语言` 是**启动时算一次**的（`lib.rs` 读设置 → `lang::有效语言` → 塞进
`HostContext.应用语言` / `AppState.app_lang`），插件在 `on_load` 里就把表装好了。
前端跟着宿主走（`nota_app_lang`），所以两边一起换，不会出现"界面英文、插件中文"
的中间态。理由写在 `settings/general.rs::language`。

### 12.6 它**不需要任何能力**

和 `nota.diff` 同一条判据：它只读**插件自己目录里**那份 `lang/<tag>.toml`——那是
作者自己带的文件，不是用户的文档、不是任意路径。⚠️ 插件**不能**拿它读别的路径：
`text` 收的是**键**，路径由宿主自己拼（`dir/lang/<规范过的 tag>.toml`）。

## 13. `nota.devserver` —— 起一个本机开发服务器（需 `process.devserver`）

> 2026-09-25 新增。机制的实现在 `src-tauri/src/devserver.rs`（946 行），
> 这张表在 `src-tauri/src/lua/api/devserver.rs`。

### 13.1 它是**通用机制**，不是给某个插件开的后门

"预览当前文档"这件事**不只 Slidev 一家**：Marp、mdBook、VitePress、自己写的静态站点
生成器要的都是同一套——挑一个空闲端口、把当前文档写成入口、起进程、等它通、嵌进面板。
所以**机制留宿主，命令与话术归插件**。`plugins/slidev/` 是第一个用它的（也是内置的
那份活样例）。

### 13.2 ⚠️ 能力放行的是"清单里那一条命令"

程序名与参数模板写在 `plugin.toml` 的 `[devserver]` 段里，随插件一起安装、一起过
签名校验；**Lua 这边交不出第二个程序名来**——`start` 只收"哪份文档"（同 `nota.git`）：

```toml
[devserver]
cmd           = "npx @slidev/cli"     # 整条写成一句，面板上显示的就是这一句
cmd_env       = "NOTA_SLIDEV_CMD"     # 调试旋钮：能整条换掉 cmd
args          = ["{entry}", "--port", "{port}", "--no-open"]
entry         = ".nota-slidev-{doc}.md"
probe_args    = ["--version"]
probe_env     = { npm_config_offline = "true" }
project_marker = "node_modules/@slidev/theme-"
```

⚠️ `project_marker` 是**粗**的一把尺子：它只回答"根里有没有这样的东西"（上例是
"有没有 `@slidev/theme-*` 目录"），回答不了"**文档要的那一个**在不在"。后者**逐份
文档都不一样**（`theme: seriph` 的文档和没写主题的文档要的不是同一个包），写不进
清单——所以它是**每次调用带上来的**入参，见 §13.3b。

⚠️ 反过来说：一份**签过名的恶意插件**仍可以把那条命令写成任意东西。这道门挡的是
"插件偷偷起别的进程"，**不是"插件干了坏事"**——后者归安装那一步的信任判定管
（`docs/12`）。**别把这一层当沙箱。**

### 13.3 六个函数

| 函数 | 参数 | 干什么 | 会不会等 |
|---|---|---|---|
| `probe{}` | — | 拿一份**已经探过的结论**（不联网、不起服务器） | **不等**——没有结论就先回一句"正在检查" |
| `probe{root=}` | 目录 | 同上，并指定拿哪个目录当项目根 | 不等 |
| `probe{need=}` | 相对路径 | 同上，并多问一件事："这个路径在项目根**或它的任一层父目录**里有没有"（§13.3b） | 不等 |
| `probe{force=true}` | — | 这台机器**现在**能不能跑，**当场探** | 最多 20 秒 |
| `start{doc=}` | 文档 id | 起服务器，**返回时端口一定通了** | 最多 180 秒 |
| `status()` | — | 现在这场会话（没在跑就是 `nil`） | 立刻 |
| `open_in_browser()` | — | 把**这场会话**的地址交给系统浏览器 | 立刻 |
| `log()` | — | 进程输出的最后 30 行 | 立刻 |
| `stop()` | — | 收摊（杀整棵进程树 ＋ 删入口文件） | 立刻 |

⚠️⚠️ **`start` 会阻塞**（和它的前身故意相反：前身由 Tauri 同步命令调着，等就是冻
界面，所以等待被推给了前端轮询；现在这条路走插件命令，本来就在 `spawn_blocking`
上，等得起，那条 500ms 轮询及其竞态一起没了）。**别在 `on_load` 里 `start`**——
插件加载是同步走的，在那儿等 180 秒会把启动卡住。

### 13.3a `probe` 的两个档，与四档 `state`

⚠️ **`probe{}` 与 `probe{force=true}` 的区别是「谁在等」**，2026-09-26 才劈开的
（起因：面板的 `render` 里同步探一次会让那一页**画不出任何东西**，正常 1.3 秒、
最坏 20 秒，`docs/07` BUG-36）：

- **`probe{}` 不等。** 有结论就回；没有就**回一张 `state = "checking"`** 并在后台开
  一条，探完**宿主发事件**让前端重拉那一页。所以"探完了"这件事**只有宿主喊得动**——
  ⚠️ **Lua 沙箱里既没有 timer，插件也收不到宿主事件**（宿主插件只能 `nota.event`
  往**前端**发），想"探完自己再画一趟"是**做不到**的。
- **`probe{force=true}` 才等**（最多 20 秒）。用在"用户刚点了一下"的场合（`start`、
  面板上的「重新检测」）：那一刻给的结论必须是**此刻的**。

`state` 一共**四个**词，别当成三个：

| `state` | 意思 |
|---|---|
| `ready` | 探通了：命令拿得到，项目根也找得到 |
| `missing` | 探通了，但**跑不起来**：命令不存在／目录不是那个项目的 |
| `unknown` | **没结论**（20 秒没回话）——⚠️ 措辞**不许**暗示"没装" |
| `checking` | **不是结论**，是"后台正在探"。⚠️ 这一档只有 `probe{}` 给得出来 |

⚠️ **`checking` 那张表只带 `state` / `command` / `root`**，**故意不给**
`version` / `detail` / `marker_found` / `need_found`：还没看过的事不许提前摆在事实表里。
⚠️ **结论有缓存，但缓存不过期**——插件这边没有可靠的时间可用（沙箱里**没有 `os`**；
`nota.document.stats().clock_ms` 是 2026-09-26 才补上的，而这条缓存比它早，§5.1）。顶掉旧结论的
是**用户动作**：换项目根会重探（`root` 对不上就丢掉），`force = true` 也能顶。
详见 `docs/12` 那一节。

### 13.3b `need`：插件要问"这份文档还缺什么"

**"机器能跑"和"这份文档能跑"是两件事。** 前者是 `probe{}` 一直在回答的（命令在不在、
项目根对不对）；后者 2026-09-26 才补上，起因是用户实测的一场：

```text
[nota] $ npx @slidev/cli /home/lqy/.nota-slidev-1.md --port 32791 --no-open
The theme "@slidev/theme-default" was not found and cannot prompt for installation
```

面板说"能跑"（项目里确实有 `node_modules/@slidev/theme-`），进程两秒后自己退出。
病因：那份文档一个字没写主题 ⇒ Slidev 要 `@slidev/theme-default`，而装的是
`theme-seriph`——**"有一个 `@slidev/theme-*`"和"有文档要的那一个"不是同一件事**。

```lua
-- 插件把自己要问的东西**拼成一条相对路径**交上去（Slidev 那份就是这么写的）
nota.devserver.probe({ need = "node_modules/@slidev/theme-default" })
```

回报多一格 `need_found`，**三档，别当两档看**：

| `need_found` | 意思 |
|---|---|
| `nil` | **没问**（这次没传 `need`，或者传进来的不是一条合法的相对路径） |
| `true` | 问了，**有** |
| `false` | 问了，**没有** |

⚠️ **`nil` 与 `false` 必须分开**：给 `nil` 的场合硬填 `false`，就等于宿主替插件下了
结论"它缺东西"。插件那边的 `describe_probe` 也正是靠这一格分辨"这份文档要的主题包
没装"和"只问过'是不是个项目'"（两句话不一样，事实表里那一格也不一样）。

⚠️ **相对路径，而且是从项目根往下数的**：宿主会拿它**连各层父目录一起**找
（Node 解析 `node_modules` 就是从当前目录一层层往上的）。宿主**只回答"在不在"**，
不解释那是什么东西——"这是主题"归插件知道。
⚠️ 绝对路径、`..`、反斜杠、空段一律**不回答**（算"没问"）：那条路的正当用途一个都没有，
判据在 `devserver/probe.rs::合法的相对路径`。
⚠️ **为什么不让插件自己找**：`nota.fs` 是**工作区根**底下的、且**不收绝对路径**，
插件沿不了文档的父目录往上走；文档的绝对路径只在宿主手里。

⚠️ 缓存是**按（项目根 ＋ 要问的东西）**算的：同一台机器上换一份文档（要的包变了）
会重探一次——所以同一次面板 `render` 里两次 `probe{}` 给的是**各自那一份的结论**。

⚠️ **一个插件最多一场会话**（键就是插件 id）。⚠️ 入口文件写在**文档自己的目录**里
（服务器拿它的父目录当项目根，`![](./img.png)` 才解析得对），点号开头（不该在用户的
文件树里显眼）。

### 13.4 `kind = "frame"`：把画面嵌进面板

面板里写一块 `{ kind = "frame", height = 320 }` 就够——⚠️ **`url` 不用写、写了也没用**：
宿主会把它抹掉，再按"你这个插件自己那场会话"填（§8.5 那张表里 `frame` 那行有完整
理由）。没有会话就没有地址，所以"嵌别人的页面"这条路由**不存在**。

⚠️ 「在浏览器里打开」走 `open_in_browser()`（本插件自己那场会话的地址，属于
`process.devserver`），**不是** `nota.ui.open_url`——后者只放行 `https`，
**故意**不放行 `http://localhost`（§8 末尾那条注释）。

| **冻结** | ⚠️⚠️ `paused` 时大数字**直接用冻住的那个值**（`frozen_rate`），**不能再调一次 `average_rate`**。理由：暂停期间样本一个都没删，而"最近 Δt 秒"那个窗口是按 `now` 算的，秒针一走就有样本滑出去——不冻的话它会**在用户眼皮底下自己往下掉**（实测 69 → 53 还在降；不是掉成破折号，是一路滑）。⚠️ 这个 bug 是 `tools/stats-state-test.lua` 抓出来的，开窗那一帧看不出来。⚠️ 第六轮之后多了一条**同一个家族的**（(23) 那一组）：刚「继续」时 `live` 是 `nil`，而 `shown = live or frozen_rate` 会把**暂停前那个旧值**端出来（Lua 里 `0` 是真、`nil` 才是假）——所以「继续」和「开始」一样要清那个值 |

| 加权怎么算 | ⚠️ 存的是 `{t, dt, add}` 而**不是**算好的速度：平均速度要按**时间加权**（`(add1+add2)/(dt1+dt2)`），把速度存下来再平均是错的——采样间隔不等长（心跳一秒一次，但用户切过来那一下会额外拉一次），先算速度再平均会偏向间隔短的那几段。⚠️ 整轮平均走 `total_add / elapsed_ms`、**不是**对 `samples` 求和：`samples` 只留三分钟，而且**故意不含断档那几段** |
| 太短不给数 | 样本跨度不够就返回 `nil`，面板画破折号。⚠️ **两处都用它**（最近 Δt 秒与整轮）：两秒打了三个字乘出来是 90 字/分钟，那不是任何人的写作速度，是一个除法。⚠️ **门槛是 `min(Δt, MIN_SPAN_MS)`，不是写死的 10 秒**：写死的话 Δt 拖到 1 秒那一档就永远出不来数（要 10 秒的样本才给 1 秒的窗口算平均，等于这根滑杆的下半截是坏的）。反过来 Δt 拖到 60 秒时门槛仍是 10 秒——**不是**"窗口多大就要等多大的跨度"：那会让用户拖到 60 之后盯着破折号坐一分钟（测试 (24c) 两头都钉着） |
| 按钮 | `开始记录`／`暂停`／`继续`／`再来一轮`／`终止`／`制作本轮分享图`／`制作今日分享图`／`返回`——⚠️ 前四颗是**同一颗开关的四副面孔**，`TOGGLE` 那张表按 `phase` 挑一副。⚠️ 这一截 2026-10-04 搬进了 `share.lua`（`share.buttons_for(ctx, phase)` ／ `share.share_buttons(ctx)`）：它和分享图那块卡片是同一件事的两半（**这一屏上摆什么**），跟着 `main.lua` 一起过 1000 行是拆它的直接理由；搬的时候遵守与 `ticks.lua`／`cards.lua` 同一条规矩——**只读**，`ctx` 是宿主现搭的一张值表，模块不回写。⚠️ 面板里**只画当前能按的那几颗**，灰着的按钮不如不画。⚠️ 分享那两颗还有一层**插件自己的**判据（`needs`：`can_share`）——**没有东西可分享时那颗按钮根本不出现**（`total_add == 0` 的一轮、今天还没写过字），理由写在 `SHARE_BUTTONS` 上面那句：一颗"点了只得到一句空话"的按钮比灰按钮更坏。⚠️ `needs` **不发给前端**，是插件自己在 `buttons_for` 里筛掉的。⚠️ 每个命令都先改状态、再调 `nota.ui.refresh(PANEL_ID)` 让这一页**立刻**重画（不然要等下一拍心跳，按下去像没反应） |

## 16. `nota.time` 与 `nota.data`（2026-09-27 加）

两节一起写，因为它们是**同一件事的两半**：写作统计要做「今日」那本账
（`docs/07` 第 65 项第二轮），于是发现插件手上缺两样东西——**"今天是哪一天"**
和**"把我这串账存哪儿"**。两样都不该拿现成的凑。

⚠️ 两节的能力要求**故意不一样**：`nota.time` 永远可用，`nota.data` 要申请
`data.own`。判据见各自的开头。

### 16.1 `nota.time.now()` —— 墙钟（**不需要任何能力**）

```lua
local t = nota.time.now()
-- t = {
--   now_ms = 1780000473000,   -- Unix 毫秒（墙钟）
--   day_start_ms = 1779984000000, -- **本地**今天 0 点的 Unix 毫秒
--   ymd = "2026-09-27",       -- 按天分桶的**键**
--   y = 2026, mo = 9, d = 27, -- 本地年月日
--   hh = 22, mi = 14, ss = 33, -- 本地时分秒
--   wday = 6,                 -- 星期几，**0 = 周一**……6 = 周日
--   tz_offset_min = 480,      -- 本地相对 UTC 的分钟数（东八区 = 480）
-- }
```

| 字段 | 类型 | 干什么用 |
|---|---|---|
| `now_ms` | 整数 | 给记录盖时间戳、算"距今多久" |
| `day_start_ms` | 整数 | 判断某条记录算不算"今天"（`now_ms >= day_start_ms`；跨零点那一刻它自己会跳） |
| `ymd` | 字符串 `"YYYY-MM-DD"` | 按天分桶的**键**。⚠️ 已经是字符串了，比较大小直接 `==` 或 `<`，**不用再解析** |
| `y` `mo` `d` `hh` `mi` `ss` | 整数 | 拼给人看的日期。⚠️ `mo` / `d` / `hh` 这些**不补前导零**，要 `22:14` 这种就得自己 `string.format("%02d", t.hh)` |
| `wday` | 整数 0~6 | **0 = 周一**、6 = 周日。⚠️ 这个起点是**钉死的**（`time.rs` 里用它查表），换个起点会让"周三"整体挪一天，而那种错只在特定日期看得出来 |
| `tz_offset_min` | 整数 | 排查"日期怎么不对"时一眼看得出机器的时区。⚠️ 它是**副产品**，不是一条独立的身份信息 |

#### ⚠️ 为什么一次调用给一整套，而不是 `now_ms()` / `today()` 分开

因为**跨零点**。分成好几个函数的话，插件可能从第一个拿到"昨天"、从第二个拿到
"今天"，两套值自相矛盾，而错在哪一半完全看不出来。所以入口只有一个，
表里那几格**保证来自同一个瞬间**（`time.rs` 文件头那段）。

#### ⚠️ 为什么是**本地**日期，不是 UTC

`plugin/package.rs::今天()` 用的是 UTC，那里只在信任表上记一笔 `added_at`（**验签不读、
界面不显示**），差一天无所谓。这里**完全不同**：这个日期会被画进**分享图**，
用户会把它发出去——"今天是 9 月 26 日"错一天，是**分享给别人之后**才被指出来的
那种错。所以这一处值当引 chrono。

#### ⚠️ 它不需要能力，但它也不是"没有代价"

它不读文档、不读磁盘、不读用户的任何数据——只是把系统时钟报一遍，判据与
`nota.diff` / `nota.i18n` 那两张表一样（见 `api/mod.rs` 顶上的清单）。

⚠️ 反过来说**它给不了插件"用户在哪"**：时区偏移是"这台机器此刻的本地时间"的
副产品。真要问 `Asia/Shanghai` 那种名字，这里没有，将来也得另开一条能力。

#### 沙箱里为什么不能自己算

`os` / `date` / `require` 全在**摘掉**的白名单里（`lua/mod.rs::硬化的_lua()`）。
插件手上唯一的另一个时间是 `nota.document.stats()` 给的 `clock_ms`——
那是**单调钟**（从应用启动算起的毫秒）：做差是对的，但**回答不了"现在是哪一天"**，
它从 0 开始、没有时区、没有纪元，跨零点时照样一格一格往上走。

### 16.2 `nota.data` —— 插件**自己那份数据**（需 `data.own`）

```lua
nota.data.dir                     -- 字符串：那座目录本身的路径
nota.data.read(name)              -- → 文本 / nil（**文件不在就是 nil，不报错**）
nota.data.write(name, text)       -- → true
nota.data.remove(name)            -- → true（**本来就没有也是 true**）
```

落点固定在：

```text
$XDG_DATA_HOME/nota/plugin-data/<插件 id>/
# 本机就是 ~/.local/share/nota/plugin-data/nota.stats/
```

⚠️ `<插件 id>` 要过 `paths::安全文件名`（非 ASCII 一律换成 `_`），所以 id 里就算
混进 `/` 也带不出路径。

#### 为什么另开一张表，不用现成的那两张

| 现成的 | 为什么不行 |
|---|---|
| `nota.fs` | 它**围在工作区里**（`resolve_in`：canonicalize 之后必须在当前工作区根下，没有工作区就直接拒）。插件的账不该写进用户的文档目录；而且**没开工作区时它整个不能用** |
| `nota.settings` | 那是**设置**：能存的类型故意很小（文本、数字、布尔，**没有表、没有数组**）。而一条写作记录天然是**一串**记录，拿设置文件当数据库用就把它变成了一个没有 schema 的 blob |

所以这是**第三样东西**：一个目录 ＋ 一串文本文件。插件自己定格式（想存 JSON 就
自己拼），宿主只保证"**这是你的、别人碰不到、跨重启还在**"。

#### 为什么是"一串文本文件"而不是"一个键值库"

因为需要它的第一个用户（写作统计）要的是**按天追加的一段账**，而文本文件的
优点是**能被人当场看懂、能直接删**。一个二进制库会把"插件数据"变成一个用户
没法排查的黑盒。⚠️ 与之配套的是 `paths::plugin_data_dir` 那条口径：**删掉这个
目录，后果只是那个插件的记忆没了**（今天的记录从头开始），文档正文一个字节都不
受影响——插件的数据**不许**成为"删了就丢文档"的东西。

#### 三条硬边界

1. **名字只认 ASCII 字母数字与 `.` `-` `_`**，长度 ≤ 64，不含分隔符，不许是
   `.` / `..`。⚠️ 与 `settings.rs::键合法吗` **故意不一样**：这里多放了 `.`
   ——数据文件是**文件**，`day-2026-09-27.txt` 这种名字里有个后缀很正常；设置键
   不许带点是因为 TOML 拿它当嵌套表的语法。⚠️ **不支持子目录**——要分门别类请
   自己用文件名前缀（`day-2026-09-27.txt`），一旦允许多级路径，"目录穿越"那个
   话题就得在这里重新回答一遍，而它没有任何真实需求。
2. **写是原子的**：先写 `<名字>.tmp`（fsync）再 rename。插件崩在写盘中间时，
   用户看到的应该是"上一次那份账"，不是一份被截断的账。⚠️ 后缀是**宿主加的**，
   所以插件不可能拿它去覆盖别人。⚠️ 落盘顺序是 **fsync 再 rename**，反过来的话
   掉电时可能出现"名字已经指向新文件、而内容还在页缓存里"的空文件。
   ⚠️ 权限 0600、目录 0700，与 `plugin-settings` 同一套。
3. **一次读写 1 MiB 封顶**。这是**防呆**不是防恶意——插件本来就能每秒调一次，
   没有上限的话一个写错的循环能把用户的磁盘写满。⚠️ 超限时**报错而且一个字节
   都不落**（检查写在 `ensure_dir` 之前，所以连目录都不建）。真要存更大的东西
   （比如一张图）得先想清楚存哪，那是另一个决定。

#### ⚠️ 三个"看起来该报错、其实不报"的地方

| 情况 | 结果 | 为什么 |
|---|---|---|
| `read` 的文件不存在 | `nil` | "还没记过、从零开始"是**正常状态**，不是错误。⚠️ 但**读不出来**（权限、不是 UTF-8、超上限）**要报错**：那两种情况的含义正相反（"这份账坏了、该让用户知道" vs "还没记过"），静默合并成一种就会**把坏账当成新的一天** |
| `remove` 的文件不存在 | `true` | 与 `settings.set(k, nil)` 同一条口径：`remove` 的语义是"**保证它不在了**"，不是"删掉一个存在的文件" |
| 目录还不存在 | 建 | `write` 会先 `ensure_dir`。⚠️ 只有 `write` 会建——`read` / `remove` 不建（读一个还没有的目录就该得到 `nil`） |

#### ⚠️ 它和 `fs.*` 不是一回事，两条能力是**两扇门**

`data.own` **只放行上面那一个目录**。装了它**仍然碰不到**用户的文档——
`fs` 那一对围的是工作区，这一条围的是插件自己的角落。两条**都要**才是
"什么都能写"；只有这一条的话，插件连文档目录的门都摸不到。

⚠️ 这一条也是 `docs/10` §11.2「**插件读写任意路径**」那一行的判据来源：
插件能碰磁盘的地方一共**三块，互相独立**（工作区 / 自己的设置文件 / 自己的数据
目录），没有第四块，也没有哪一块能换到另一块。

#### ⚠️ 第一层的判据（`lua/api/mod.rs`）

```rust
if manifest.has(Capability::DataOwn) {
    set(nota.set("data", data::build(lua, &manifest.meta.id)?), lua)?;
}
```

⭐ 这条**没有第二层**（对比 `nota.ui` 的四条能力各判一次）：这张表里就四个函数，
**四个一起出现一起消失**——因为它们围的是同一个目录，不像 `ui.*` 那样四条能力
各管一件事。没申请 `data.own` 时 `nota.data` 是 `nil`，不是一张"调用才报错"的空表。

## 17. `nota.json`（永远可用，2026-10-04 加）

```lua
local v, why = nota.json.decode('{"a":[1,2,"三"]}')
if v == nil then
  nota.log.warn("读不出来：" .. why)
end
-- v.a[1] == 1、v.a[2] == 2、v.a[3] == "三"（⚠️ 数组下标从 1 起）
```

| 参数 | 返回 |
|---|---|
| 一段**文本** | 成功：**一个值**（表 / 字符串 / 数字 / 布尔）；失败：**`nil, "原因"`**（一句中文人话，带出错位置） |

⭐ **不需要任何能力。** 它不认识文档、不碰磁盘、不联网——判据与 `nota.diff` /
`nota.time` / `nota.i18n` 一样：这一条只是"把一份文本看成一张表"，没有新的门要开。

#### ⚠️ 失败**不抛**，给 `nil, 原因`——这是刻意的

§0.2 那两条通道：**环境失败返回、作者写错才抛**。"这段文本不是合法 JSON"是**环境**
（回包是网关的 HTML 错误页、模型多打了一个逗号），插件该有能力**接住它、说人话**，
而不是让一个栈飘到用户面前。所以：

| 传进去的东西 | 结果 |
|---|---|
| `"{"` （半截） | `nil, "…第 2 个字符处就断了…"` |
| `"不是 JSON"` | `nil, "…"` |
| `{a = 1}` （**一张表**） | **抛** —— 作者把参数写错了 |
| `true` | **抛** —— 同上 |
| `"123"` | `123`（数字）—— ⚠️ 合法 JSON 的顶层可以是个数字 |
| `"null"` | 一个 `nil`，**没有第二个返回值**——⚠️ 见下 |

⚠️ **顶层是 `null` 时给的是"一个 `nil`、没有原因"**，和失败长得**很像**：
`local v, why = nota.json.decode(s)` 这种情况下 `v == nil` 而 `why == nil`。
判据是 **`why == nil` 就是"真的解出来了，答案就是 `null`"**。
（把它和失败合并成一种是不行的：`null` 是一个**正常的** JSON 值，
"回包是 `null`"和"回包不是 JSON"是两件事，插件对它们的反应也完全不同。）

#### ⚠️ 为什么要加它（而不是让插件自己写一个解码器）

宿主**本来就在做这件事**（`lua/api/http.rs::json_to_lua`——`r.json` 就是它给的），
插件再手写一份是同一件事写两遍。而**手写的那一份坏了不会有人发现**：
它只在某一种转义、某一种嵌套上错，测试里那几条恰好都不碰它，
表现是"偶尔有一条回答显示成乱码"。

⚠️ **只解不编。** 要往外**发** JSON，走 §9 那条"`body` 写一张表、宿主当 JSON 发"
（`content-type` 也由宿主补）。这条是有意的：把 Lua 表编成 JSON 有几处**必须做决定**
的地方（空表是 `[]` 还是 `{}`？`nil` 怎么办？），而那个决定**没有正确答案**——
不如不做，让作者用"表体当 JSON"那条已经定好口径的路。

⚠️ 它是**纯函数**：同一条文本解两遍得到两个互不相干的表，改了其中一个
不会影响另一个（没有共享状态）。
