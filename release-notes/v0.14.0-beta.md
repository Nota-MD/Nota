# Nota 0.14.0-beta

Nota 0.14 focuses on Typedown/Textus-style editing, direct Typora theme
compatibility, safer document recovery and native platform integration.

## Editing

- Reworked inline Markdown editing around complete source-character offsets.
  Bold, italic, highlight, strike, code, underline, superscript and subscript
  now share one caret model.
- Adopted Textus-style in-place link source editing. A linked run becomes
  ordinary, editable `[label](destination)` text and is parsed back when the
  caret leaves.
- Fixed caret boundaries at both ends of links, continuous Left navigation,
  editing immediately before `)`, document-wide Ctrl+A, and invalid-source
  fallback.
- Completed Typedown-style delimiter pairing and closing rules, including
  `**1*|*`, nested `***local***`, nearest-strong closing, literal backslashes,
  smart quotes and IME-safe composition boundaries.
- Unified code block, Mermaid, math fence and `$$…$$` block exits. Only the
  absolute first/last source offsets leave a block with an arrow key.
- Improved inline math focus, IME commits, preview placement, dollar spacing,
  and mark inheritance when leaving a formula.

## Documents and recovery

- Added durable draft recovery under the application data directory. Drafts
  remain separate from source files and are removed after save, reload, delete
  or explicit discard.
- Existing untouched files save without serialization or rewrite, preserving
  LF/CRLF, UTF-8 BOM, table separators and trailing whitespace byte-for-byte.
- Added automatic GBK, Big5, Shift_JIS and UTF-16 detection while preserving the
  detected encoding on save.
- Added configurable line endings for new documents and safer draft recovery
  when the original source path is missing.

## Themes and rendering

- Added direct Typora theme-directory, single-CSS and ZIP import without a
  conversion step. Original CSS, fonts, images, `@import` rules and relative
  assets are retained.
- Added runtime bridges for Typora variables, headings, tables, figures,
  task/Alert/HTML/math aliases, code tokens and LaTeX light/dark themes.
- Added self-contained official and third-party theme package handling,
  including interface and document outputs from the same ZIP.
- Improved Mermaid SVG labels and theme colours, HTML image fallback, GitHub
  Alert appearance, block HTML source editing and HTML/PDF export parity.

## Platform integration

- Linux `Ctrl+P` renders the document to PDF and opens the XDG Desktop Portal
  print flow, using the GNOME GTK4 picker and following Plasma on KDE.
- Windows uses WebView2/Chromium native printing. The old self-drawn print
  dialog is no longer the default path.
- Windows runtime child processes consistently use `CREATE_NO_WINDOW`, removing
  transient command-prompt windows from Git, system diagnostics, Pandoc,
  update helpers and development servers.
- Native file pickers prefer XDG Desktop Portal on Linux with an in-app fallback.

## Developer and extension tooling

- Developer mode adds an element inspector and an opt-in selectable-interface
  text mode.
- Added opt-in Lua extension auto-refresh for `.lua` and `plugin.toml`, with
  transactional reload and rollback to the previous instance on failure.
- Added editor selection memory across panes, modes and document switches.
- Kept the global Extensions switch authoritative: disabling it hides all
  extension UI and stops extensions without deleting packages or changing their
  individual enabled state.

## Validation

- Frontend: 132 suites and at least 2087 assertions passed.
- Browser E2E: 73/73 scenarios passed.
- TypeScript, production build, WOFF2 asset verification and documentation
  synchronization passed.
- Linux and Windows x86_64/ARM64 packages are built by the release workflow
  with `BUILD-INFO.json`, `SHA256SUMS.txt` and `latest.json`.

Windows real-device coverage remains more limited than Linux. Issue reports and
feedback are welcome.
