# Nota 0.14.1-beta

Nota 0.14.1 is a maintenance release focused on editor handfeel, IME
reliability and developer tooling.

## Editor and IME

- During IME composition, the native caret owns the preedit. Nota restores its
  stable custom caret only after the committed text settles.
- Code-block carets are bound to real characters or empty line boxes instead of
  an ambiguous end-of-line widget. Line start, line end and empty blocks no
  longer move the caret to a following visual line.
- Unordered circles and ordered numbers keep one layout before, during and after
  editing, removing marker jitter and flicker.
- Inline formatting now applies to text blocks rather than empty paragraph
  boundaries. WebKitGTK also ignores ProseMirror's generated separator and
  trailing break after closing delimiter atoms, so `Ctrl+B` no longer pushes
  following paragraphs down by two blank lines.
- Code-block language selection is one centered input. Typing filters the
  candidate list directly; the list uses the exact same width and horizontal
  alignment as the input.

## Appearance and windows

- The colour picker text field now keeps keyboard focus and accepts direct
  colour input.
- Adwaita and Yaru picker dimensions, accents, radio controls, sidebars and
  window surfaces have been aligned with their system design references.
- Settings and About support full-page, embedded and independent-window modes.
  Independent utility windows are reused, and full-screen/maximized layouts no
  longer show a white strip.
- Source mode consistently uses the configured monospace font.

## Developer tooling

- The authenticated developer bridge can list extensions and remotely install,
  uninstall, enable, disable, check and apply updates.
- Remote extension installs accept an upload or a host-side path. Extension
  updates use the manifest declared by the package.

## Validation

- TypeScript and production frontend build passed.
- Focused layout, IME, formatting, language-picker, list and code-block browser
  E2E scenarios passed.
- The `Ctrl+B` regression was reproduced and verified in a real WebKitGTK
  window with a following paragraph.
- Linux and Windows x86_64/ARM64 packages are produced by the release workflow
  with build provenance, checksums and update metadata.

Windows real-device coverage remains more limited than Linux. Reports and
feedback are welcome through GitHub Issues.
