# Nota 0.14.4-beta

Nota 0.14.4 fixes Windows automatic updates failing to launch and replace the
installed application.

## Windows updater

- The installed build now launches its NSIS updater with `ShellExecuteW`,
  matching the path used by Textus. The installer runs with `/P /UPDATE /R`:
  it shows passive progress, overwrites the current installation, and restarts
  Nota when finished.
- The updater no longer waits on Nota's old PID from a hidden PowerShell
  process. This removes the stale-process deadlock that prevented the installer
  from launching.
- After update preparation, the frontend now quits the complete Tauri
  application. Hidden Preferences and About WebViews can no longer keep Nota
  alive or lock installed files during replacement.

The Windows-specific Rust path compiles cleanly for
`x86_64-pc-windows-gnu`. The release workflow then builds the actual MSVC NSIS
installer; a real Windows in-app upgrade is the remaining manual acceptance
step for this release.

## Inline line height

- Inline code could make its paragraph one or two pixels taller than adjacent
  prose when the monospace font's metrics participated in baseline alignment.
- Inline code now leaves vertical line-box ownership to the surrounding text.
  The code glyph box, background, padding, and horizontal appearance are
  unchanged; fenced code blocks are excluded.
- A browser regression compares inline code, inline math, emphasis, links,
  highlights, keyboard keys, superscripts, and subscripts against a plain
  paragraph at the same document line height.
