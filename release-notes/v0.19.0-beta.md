# Nota 0.19.0-beta

Nota 0.19.0-beta focuses on settings-package portability and long-document
performance. Files remain ordinary GFM Markdown.

## Settings packages

- Extension settings, extension data and installable `.nota-plugin` packages can
  be selected independently during export.
- Imported extension packages pass through the normal manifest, API, signature
  and capability validation path.
- Extension installation participates in the settings-import transaction.
  Existing installed versions and enabled state are restored if a later import
  step fails.
- Import opens the file picker immediately and inspects the selected package
  before enabling the apply action.

## Long-document performance

- On the shared 1,242,340-character, 20,800-block Textus fixture, Nota's
  open-only result is 5.02 seconds versus Textus at 4.97 seconds.
- Full-path startup is 4.85 seconds. Typing dispatch p95 is 102.6 ms versus
  88.0 ms, while input-to-frame p95 is 208.4 ms versus 224.3 ms.
- Point-to-point scroll median frame time is 23.3 ms versus Textus at 33.3 ms.
- A 1,000,000-character rich fixture opens in 1.54 seconds and a
  2,000,000-character fixture opens in 4.43 seconds.
- Heading ids are applied while Markdown is parsed. Later updates are limited to
  edits that touch a heading and run after a short idle delay.
- Code syntax highlighting is viewport-driven in long documents and is batched
  after scrolling settles.
- Math, Mermaid, images, HTML blocks and full code editors are created only when
  they approach the viewport or receive focus.
- Formulas and diagrams render once near the viewport instead of repeatedly
  releasing and rebuilding their DOM.
- Viewport work uses an 80 ms scroll-settle delay and an 8 ms per-frame budget.

## Editing and interface

- Typewriter mode reserves half a viewport above and below both source and
  WYSIWYG content and centers after native scrolling has settled.
- Focus mode now decorates only the caret path, with non-path blocks dimmed by
  CSS.
- The custom body caret pauses while scrolling and restores after scrolling
  settles.

## Release support

- The release workflow publishes unsigned macOS Intel and Apple Silicon DMG
  previews alongside Linux and Windows packages.
- `npm run bench:large-doc` runs the production editor against generated rich
  or mixed documents and external Markdown fixtures without creating an
  installer.

## Validation

- Frontend unit tests: 168 suites and at least 2,374 assertions passed.
- TypeScript, production build, WOFF2 assets, localization, source-language and
  pinyin audits passed.
- Documentation synchronization completed with 0 failures.
- Browser E2E and Rust release gates are run before publication.
